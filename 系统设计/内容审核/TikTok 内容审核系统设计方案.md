# TikTok 内容审核系统 · 完整设计方案

> 场景：合规风控 + 舆情监测 ｜ 落地某地区｜ 日处理百万级 ｜ 分钟级时效
> 混合数据源 ｜ 开源模型优先 ｜ 私有化部署 ｜ 人工复审 ｜ 全流程可追溯（月级存储）

---
## 1. 总体架构

```mermaid
flowchart TD
    subgraph IN[数据接入层]
        A1[官方 Research/商业 API]
        A2[授权数据商]
        A3[合规公开采集]
        A4[客户回流数据]
    end
    A1 & A2 & A3 & A4 --> GW{合规网关<br/>授权校验 + PDPA 脱敏}

    GW --> UC[用户分级引擎]
    GW --> VC[视频分级引擎]

    UC --> SCH[调度与流程引擎]
    VC --> SCH

    SCH --> PRE[预处理 & 特征抽取<br/>抽帧/ASR/OCR/语种]
    PRE --> L0[L0 静态规则层<br/>五大特征库]
    L0 --> L1[L1 小模型粗筛]
    L1 --> RT{审核分级路由}

    RT -->|低风险/高置信| ARCH[自动入库归档]
    RT -->|中高风险/低置信/敏感| L2[L2 大模型 · 审核智能体]

    L2 --> DEC{判定}
    DEC -->|高置信| ACT[自动处置]
    DEC -->|边界/敏感| HUM[L3 人工审核工作台]

    HUM --> ACT
    ACT --> OUT[处置输出层<br/>打标/告警/下架/报告/对接]

    HUM -.回流标注.-> FB[回馈线路]
    L2 -.误判反馈.-> FB
    FB -.迭代优化.-> L0
    FB -.迭代优化.-> L1
    FB -.迭代优化.-> L2

    OUT --> AUDIT[(全流程审计追溯)]
    OUT --> OPI[舆情监测子系统]
```


**数据接入层 是整个系统的最上游入口，承担"原料供给"的职责。其中**官方 Research / 商业 API** 是优先级最高的主数据源，通过 TikTok 官方授权接口按话题、账号、地域、时间范围拉取视频元数据与媒体文件，合规等级最高；**授权数据商**作为补量与历史回溯通道，向有授权的第三方供应商批量获取官方接口覆盖不到的存量与增量数据；**合规公开采集**是在法务审核范围内对公开页面做的边缘补充，配合代理 IP 池、账号池与速率自适应，仅作为前两者的补充而非主力；**客户回流数据**则是甲方/业务方定向送入的待监测内容，用于精准监控特定账号或话题。四路数据汇聚后统一向下游输出标准化的待审内容。
**合规网关** 是所有数据进入系统的强制闸口，体现"合规先行"的设计铁律。它对每一条数据做服务条款与 robots 校验、PDPA 隐私脱敏（去除非必要个人信息）、并打上来源与授权标记。任何缺少合法授权标记的数据都会被拦截，不得进入后续处置流程。它的输出是带有合规标签、可追溯来源的干净数据，确保整个链路从源头就满足马来西亚监管与数据保护要求。
**用户分级引擎** 接收合规网关输出的数据，结合作者的历史违规率、账号画像（粉丝量、影响力、认证状态）、行为特征等，为发布者打分并划分等级（如 L5 高危到 L1 白名单）。它的输出是用户等级标签，直接影响该用户内容的**爬取强度与审核深度**——高危用户重点爬取、全量审核，可信用户低频抽样、轻量审核。该等级会随后续审核结果动态升降级，形成闭环。
**视频分级引擎** 与用户分级并行运行，依据内容本身的流量热度（播放、点赞、转发、增速）、传播风险（敏感标签、负面情感、举报数）以及发布者等级，为每条内容评定等级（如 V1 极高到 V4 低）。它的输出是视频等级标签，决定该内容的**处理优先级与处理深度**：爆款或敏感内容实时优先、走全链路，长尾低流量内容则降频、批处理。
**调度与流程引擎** 是系统的中枢决策节点，本身不做审核判断，而是综合"用户等级 + 视频等级 + 内容维度"三类输入，决定每条内容的**处理顺序、资源分配与流转路径**。它通过优先级队列让高危、高流量、敏感内容插队，通过负载均衡把任务分给空闲的算力与审核员，通过可配置的工作流编排决定内容要走几审几核。它是把前面的"分级策略"真正落地为"实际处理动作"的关键，确保百万级流量下既控成本又保时效。
**预处理与特征抽取层** 在正式审核前对内容做标准化加工。它用 FFmpeg 转码抽帧、用 pHash/视频指纹去重（命中历史结论可直接复用以省算力）、用 faster-whisper 做多语种语音转写、用 PaddleOCR 提取画面与字幕文字、用 fastText 做语种识别。它的输出是统一结构化的特征（帧、转写文本、OCR 文本、语种标签），把图音视频都转化为后续模型可处理的形式，也为多语种（马来语、英语、中文、淡米尔语）路由打好基础。
**L0 静态规则层（五大特征库）** 是 AI 之前的第一道高速闸门，由关键词库、规则引擎、黑白名单、语义模型、图像特征五大特征库组成。它用 Aho-Corasick 多模式匹配、正则、布隆过滤器等确定性手段，以极低成本拦截/放行明确的黑白样本。命中高确定性场景（如违规指纹、CSAM 哈希）可直接终判，其余仅作为"加权信号"继续下传，避免误杀。它的输出是命中规则的标签、分值与证据，既提速降本又提供可解释依据。
**L1 小模型粗筛** 承担高吞吐、低成本的初筛职责，用 NSFW、暴力、暴恐检测、YOLO 目标检测、XLM-R 文本分类、多语言 CLIP 等开源小模型，对每条内容在各审核维度上输出"风险分数 + 置信度"。它的目标是拦截绝大多数（85%以上）流量，单条延迟仅数十毫秒。它的输出喂给审核分级路由，决定内容是直接归档还是需要上送更重的处理层。
**审核分级路由** 是承上启下的分流节点，综合 L1 输出的风险分、用户等级、视频等级与维度敏感系数做判断：低风险且可信的内容直接归档；一般风险走大模型自动判定；高风险、高危用户或高流量内容升级处理；P0 敏感维度（3R、未成年人、暴恐）无视分数强制进入人工。它确保资源精准投放到真正需要深度判断的灰区与高危内容上。
**自动入库归档** 是低风险内容的终点节点。对被判定为明确无风险的内容，系统不再消耗大模型与人工资源，直接打标签结构化入库保存，同时保留必要元数据以备审计与抽检。它是漏斗收窄、控制成本的重要出口。
**L2 大模型 / 审核智能体** 是对疑难、敏感、高风险样本做深度理解的核心节点。它以私有化部署的多模态大模型（Qwen-VL、InternVL 等）为基座，不是单次分类，而是以智能体形式多步推理——调用规则库查命中详情、向量检索相似历史判例、调专项模型复核、读取用户画像，最终输出包含判定、维度、理由、证据帧/时间戳、置信度与相似判例的结构化结论。它兼顾语义理解与可解释性，是对齐监管留存要求的关键一环。
**判定（决策节点）** 对 L2 智能体的输出做分流：高置信度结论直接进入自动处置；边界、低置信或敏感内容则转人工审核。它是机器与人工的分界点，体现"AI 处理确定性违规、人工专注边界案例"的人机协同原则。
**L3 人工审核工作台** 是处理灰区与高代价内容的人工节点。审核员在统一界面上同时看到原视频、证据帧、转写字幕与 AI 给出的理由，配合倍速浏览、关键帧跳转、命中高亮、快捷键等工具一屏决策。它内部还包含交叉审核、二审与复审机制（两次结果不一致升级到更高一级负责人裁定），保证审核质量。其结论既流向最终处置，也回流作为标注数据驱动模型迭代。
**自动处置** 是判定与人工结论汇聚后的执行节点，负责把"结论"转化为"动作"，根据违规类型与等级触发打标、告警、下架建议等相应处置。
**处置输出层（打标、告警、下架、报告、对接）** 是面向业务与外部的统一出口。它把审核结果结构化入库、分级告警（即时/汇总，邮件/IM/Webhook）、生成含理由与证据的下架建议、自动产出监管合规报告与舆情报告，并通过开放 API、回调或消息队列对接客户系统。它是系统价值最终交付的环节。
**回馈线路** 是贯穿全局的闭环优化节点。它收集人工审核结论、误判与申诉反馈，汇入标注数据池，用于小模型再训练、大模型/智能体微调、规则词库更新以及用户/视频分级权重调优，所有更新经灰度上线与效果回测后生效。它让系统具备持续自我进化的能力。
**全流程审计追溯** 是合规支撑节点，以追加式日志加校验和的方式，完整记录每条内容从数据来源、各模型版本、规则命中、人工动作到最终处置的全链路（谁、依据什么、何时、做了什么），不可篡改，按月留存，满足 Act 866 监管复核与报告导出要求。
**舆情监测子系统** 是与审核并行的分析节点，复用同一套数据与特征，叠加事件聚类、多语言情感分析、传播链路与协同行为识别，并在增速、负面占比或敏感命中量超阈值时分级预警，最终以趋势看板与舆情报告形式输出，服务于舆情监测目标。

**核心思想：四级漏斗（L0 规则 → L1 小模型 → L2 大模型/智能体 → L3 人工）**，
用低成本层拦截绝大多数明确样本，仅把灰区/高风险/敏感样本逐级上送，
在百万级吞吐下兼顾成本、精度与合规可解释性。

## 2. 数据接入层 & 合规网关

### 2.1 混合数据源
| 来源 | 用途 | 优先级 | 合规等级 |
|------|------|--------|----------|
| 官方 Research / 商业 API | 主数据源 | P0 | 高 |
| 授权第三方数据商 | 补量 / 历史回溯 | P1 | 高 |
| 合规公开页面采集 | 边缘补充 | P2 | 需法务审核 |
| 客户回流数据 | 定向监测 | P0 | 依授权 |

### 2.2 采集工程
- 代理 IP 池 + 账号池 + 指纹隔离 + 速率自适应。
- 调度：分布式任务队列（Temporal / Celery），按地域、话题、账号、**用户等级**分片。
- **合规网关（强制）**：robots/ToS 校验、PDPA 脱敏、来源与授权标记；无授权标记数据不得进入处置流程。

### 2.3 规模规划（百万/天）
- 均值约 12 条/秒，峰值按 3–5x 冗余弹性扩缩容。
- 视频不全量落盘：命中样本 + 抽样 + 证据帧存原片，其余存元数据 + 缩略 + 特征向量，控成本。

## 3. 用户分级

### 3.1 分级维度
- **历史违规率、违规严重度、账号画像**（粉丝量、影响力、注册时长、实名/认证）。
- **行为特征**：发布频率、突发爆量、协同/水军特征、敏感话题参与度。
- **舆情权重**：高影响力账号、敏感领域 KOL。

### 3.2 用户等级与策略
| 等级 | 定义 | 爬取策略 | 审核策略 |
|------|------|----------|----------|
| L5 高危 | 屡犯/诈骗/敏感煽动 | 高频重点爬取 | 全量审核 + 强制人工 |
| L4 重点 | 高影响力/敏感领域 KOL | 高频爬取 | 全量过 L2 |
| L3 普通 | 正常活跃账号 | 常规爬取 | 漏斗常规处理 |
| L2 可信 | 长期合规/认证号 | 低频抽样 | 降低抽检比例 |
| L1 白名单 | 官方/权威机构 | 最低频 | 仅规则轻审 |

```mermaid
flowchart LR
    U[用户行为/画像数据] --> S[用户评分模型]
    S --> G{分级}
    G -->|L5/L4| HI[重点爬取 + 重点审核]
    G -->|L3| MID[常规]
    G -->|L2/L1| LO[低频抽样 + 轻审]
    F[审核结果回流] -.动态调整权重.-> S
```
> 用户等级随审核结果**动态升降级**，形成闭环。

## 4. 视频分级（按流量等因素）

### 4.1 分级因子
- **流量热度**：播放量、点赞、评论、转发、增速（爆款优先）。
- **传播风险**：敏感话题标签、负面情感、被举报数。
- **发布者等级**：继承用户分级权重。

### 4.2 等级与处理深度
| 等级 | 触发条件 | 处理策略 |
|------|----------|----------|
| V1 极高 | 爆量/高增速/敏感话题 | 实时优先，全链路 L0→L2，命中即人工 |
| V2 高 | 较高流量或高危用户发布 | 优先队列，全量过 L2 |
| V3 中 | 一般流量 | 漏斗常规 |
| V4 低 | 长尾低流量 | 规则 + 小模型，抽样过 L2 |

> 资源有限时按等级配额：高等级保 SLA，低等级降频/批处理。

## 5. 审核分级路由（用户 × 流量 × 违规类别）

综合三要素决定**走多深、谁来审、几审几核**。

```mermaid
flowchart TD
    IN[内容 + 用户等级 + 视频等级 + 维度] --> R[路由决策器]
    R -->|低风险 可信用户 低流量| A1[自动归档]
    R -->|一般风险| A2[L1 到 L2 自动判定]
    R -->|高风险 高危用户 高流量| A3[L2 + 人工一审]
    R -->|P0敏感 3R 未成年 暴恐| A4[强制人工 + 双审 复审]
```

**路由权重示例**：`风险路由分 = w1·内容风险 + w2·用户等级 + w3·视频等级 + w4·维度敏感系数`
- 超阈值 → 升级处理深度；P0 维度无视分数，直接强制人工。

## 6. 预处理 & 多模态特征抽取层

**定位**：一次抽取，两级复用。

|模块|开源选型|说明|
|---|---|---|
|转码/抽帧|FFmpeg|关键帧 + 间隔抽帧（默认 1fps），输出统一 224×224|
|去重|pHash / 视频指纹|命中则复用历史 L1+L2 结论，直接跳过推理|
|ASR|faster-whisper|多语种语音转文字（ms/en/zh/ta + 方言兜底）|
|OCR|PaddleOCR|提取字幕、画面文字、导流号、二维码内容|
|语种识别|fastText lid.176|对 ASR / OCR / 标题文本做语种路由|
|视觉特征|ViT / CLIP ViT-L|抽取帧级视觉 embedding，供 L1 分类 & L2 检测复用|
|音频特征|wav2vec2 / VGGish|抽取音频 embedding，供 L1 分类 & L2 检测复用|
|文本特征|XLM-R / ERNIE|对 ASR + OCR + 标题拼接后编码为文本 embedding|

>**多语种是某地区关键难点**：马来语+英语+中文+淡米尔语+方言混杂，需分语种路由 + 大模型兜底。

## 7.L0 静态规则层 · 五大特征库策略引擎

与 L1 并行执行，仅对确定性 100% 的违规做终判拦截，其余输出加权信号供下游综合。

| 特征库          | 实现                                        | 作用                     |
| --------------- | ------------------------------------------- | ------------------------ |
| CSAM / 违规指纹 | MD5/pHash + NCMEC 哈希库 + Redis 布隆过滤器 | 命中即终判拦截，无需模型 |
| 已知违规视频    | 视频指纹 + 向量库（Milvus）                 | 搬运/二剪秒级召回        |
| 关键词库        | Aho-Corasick 多模式 + 多语种变体词典        | 敏感词/谐音/变形匹配     |
| 黑白名单        | Redis + 布隆过滤器                          | 哈希/URL/账号指纹        |
| 导流规则        | 正则 + 规则 DSL（OPA）                      | 电话/微信号/外链/二维码  |

**策略组合**：各库输出「命中信号 + 分数」，由策略编排器加权聚合。后台可视化配置、热加载、灰度发布、命中统计。

**规则原则**：仅在高确定性场景终判（CSAM 哈希、确认违规指纹）；其余只做"加权信号"，避免误杀。

## 8. L1 小模型粗筛层

目标：拦截 85%+ 流量，单条数十毫秒，GPU 批处理。

两级架构：S1 对视频做多标签分类，输出 Top-N 候选标签；命中敏感标签则触发 S2 对应领域小模型做二分类精判。

|层级|目标|任务|开源基座|
|---|---|---|---|
|S1 多标签分类|粗筛，Top-N 输出|多标签分类（Sigmoid）|InternVL2 / Qwen2.5-VL + LoRA|
|S2 暴力血腥|领域精判|帧分类 + 时序|ConvNeXt / ViT + LSTM|
|S2 色情低俗|领域精判|帧分类|NSFW / EfficientNet 微调|
|S2 暴恐/武器/旗帜|领域精判|目标检测|YOLOv8 / RT-DETR|
|S2 政治敏感|领域精判|多模态二分类|XLM-R + CLIP|
|S2 仇恨辱骂|领域精判|文本分类|XLM-R + 语种分类头|
|S2 导流/诈骗|领域精判|检测 + OCR + 正则|YOLO + PaddleOCR|
|S2 未成年风险|领域精判|多模态二分类|CLIP + 年龄检测|
|S2 违禁品|领域精判|检测 + 分类|YOLOv8 + 分类头|

**S1 敏感标签阈值**：普通 > 0.5，敏感（暴力/色情/政治/违禁/未成年/仇恨）> 0.3 即触发 S2。

**S2 评级与处置**：

|评级|分数|处置|
|---|---|---|
|安全|< 0.3|放行|
|有争议|0.3~0.7|人工复审（政治/暴恐优先级 HIGH）|
|违规|≥ 0.7|自动拦截 + 告警|

> S2 复用 §6 特征，不重复抽取。大部分视频无敏感标签直接放行，少部分触发 S2。

输出 `{维度: 分数, 置信度}` → 进入审核分级路由（§5）。

### 9.2 智能体工作机制
不是单次分类，而是 **LLM + 工具调用 + 多步推理** 的 Agent：

```mermaid
flowchart TD
```

**能力**：AI 预审、智能推荐（建议动作+理由+相似判例）、辅助决策；

## 11. 人工审核机制

### 11.1 入口来源
- **系统转发**：AI 判定为疑似、检测为高危用户、P0 敏感维度命中。
- **随机抽样**：对自动通过内容按比例抽检，监控漏判。

### 11.2 任务分配机制（按语种/类型）
- **按内容类型分发**：图片、文字、音频、视频分流给对应组；某些专项（如涉黄）由专人负责。
- **按语种分发**：ms/en/zh/ta 路由到对应语种审核员。
- **按时间/在线状态**：审核员非 24h 在线，离线时段内容次日优先处理；高危发布者内容优先。
- **优先级队列**：P0 敏感 + 高危用户 + 高流量内容插队置顶。

```mermaid
flowchart TD
    SRC1[系统转发: 疑似/高危] --> Q[人工任务池]
    SRC2[随机抽样] --> Q
    Q --> D{分配器}
    D -->|语种 ms| TM[马来语组]
    D -->|语种 zh| TZ[中文组]
    D -->|类型 涉黄| TP[涉黄专项组]
    D -->|高优先级| TT[置顶插队]
```

## 12. 人工审核系统

### 12.1 账号管理
- 超级管理员开通/删除账号、分配角色与权限（审核员/二审/质检/管理员）。

### 12.2 监管平台（质量监控）
- **抽样观察 + 操作日志留痕**。
- **交叉审核 / 二审**：内容被一审后，部分进入交叉审核或专门二审部门（KPI 不同，重质量）。
- **复审机制**：两次结果不一致 → 自动升级复审，由更高级负责人裁定。
- **投毒质检**：任务流中混入已知答案金标样本，实时评估审核员准确率与状态。

```mermaid
flowchart TD
    A[一审] --> X{抽取交叉/二审?}
    X -->|是| B[二审/交叉审核]
    X -->|否| OK1[出结论]
    B --> C{一审 = 二审?}
    C -->|一致| OK2[出结论]
    C -->|不一致| RV[复审: 高级负责人]
    RV --> OK3[最终结论]
```

### 12.3 人工审核平台
- 图/文/音/视频分别定制前端样式与交互。
- 配套：倍速浏览、自动播放、关键帧跳转、命中片段高亮、AI 理由与证据并排、键盘快捷键、一键改判。

## 19. 部署与算力（私有化）

- **编排**：Kubernetes，推理 GPU 节点与流处理 CPU 节点分离。
- **GPU 分配**：L1 小模型少量 GPU 即可支撑百万级；L2 大模型为主要算力点，按 L2 流量与 SLA 配置 + 量化 + 批处理降本。
- **分钟级时效**：Kafka 流式 + 自动扩缩容 + 优先级队列（V1/P0 插队）。
- **高可用**：多副本、限流降级（高峰大模型降级为小模型 + 提高人工抽检）。

## 20. 人力规划（百万/天参考）

- L0+L1 拦截后约 10–15% 进 L2，其中约 1–3% 转人工 ≈ 1–3 万条/天。
- 按人均 800–1200 条/天，需 **约 15–30 人**（分语种、含二审/质检、三班倒），按实际命中率调整。
