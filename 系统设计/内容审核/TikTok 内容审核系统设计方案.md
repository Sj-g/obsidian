# TikTok 内容审核系统设计方案（某地区 / 私有化部署）

> 场景：合规风控 + 舆情监测｜日处理百万级｜分钟级时效｜混合数据源｜开源模型优先｜私有化部署｜人工复审｜审计追溯（月级存储）

## 1. 总体架构（文字说明）

系统采用 **三级漏斗** 结构，从上到下分为六层：

1. **数据接入层**：官方 Research/商业 API、授权数据商、合规公开采集、客户回流四路汇入，统一经过「合规网关」做授权校验与 PDPA 脱敏后入库。
2. **预处理 & 特征抽取层**：去重、转码抽帧、ASR 语音转写、OCR、文本清洗与语种识别。
3. **L1 小模型粗筛层**：高吞吐、低成本，对每条内容打出「维度分数 + 置信度」，并据此路由。低风险直接归档，中/高风险或低置信样本上送 L2。
4. **L2 大模型精审层**：私有化部署的多模态/文本大模型，对疑难样本做深度理解，输出「判定 + 理由 + 证据帧/时间戳 + 置信度」。高置信自动处置，边界/敏感样本转人工。
5. **L3 人工审核工作台**：复审、标注、申诉处理，结果回流用于模型迭代。
6. **处置 & 输出层**：打标入库、告警、下架建议、报告生成、客户系统对接、审计日志。

**核心思想**：用低成本小模型拦截绝大多数低风险流量（目标 85%+），仅将高风险/低置信/敏感样本送入昂贵的大模型与人工，从而在百万级吞吐下兼顾成本与精度。

---

## 2. 数据接入层 & 合规网关

### 2.1 混合数据源
| 来源                   | 用途        | 优先级 | 合规等级 |
| -------------------- | --------- | --- | ---- |
| 官方 Research / 商业 API | 主数据源      | P0  | 高    |
| 授权第三方数据商             | 补量 / 历史回溯 | P1  | 高    |
| 合规公开页面采集             | 边缘补充      | P2  |      |
| 客户回流数据               | 定向监测      | P0  | 依授权  |

### 2.2 采集工程（针对公开补充采集）
- 代理 IP 池 + 账号池 + 浏览器指纹隔离 + 速率自适应。
- 调度：分布式任务队列（Temporal / Celery），按地域、话题、账号分片。
- **强制合规网关**：robots/ToS 校验、PDPA 脱敏（去除非必要 PII）、来源与授权标记；无授权标记数据不得进入处置流程。

### 2.3 规模规划（百万/天）
- 均值约 12 条/秒，峰值按 3–5x 冗余设计弹性扩缩容。
- 视频不全量落盘：命中样本 + 抽样 + 证据帧保留原片，其余仅存元数据 + 缩略图 + 特征向量，控成本。

## 3. 预处理 & 特征抽取层

| 模块 | 开源选型 | 说明 |
|------|----------|------|
| 转码 / 抽帧 | FFmpeg | 关键帧 + 固定间隔（如 1fps），动态调整 |
| 去重 | pHash / 视频指纹 | 重复内容复用历史结论，省算力 |
| ASR 语音转写 | faster-whisper | 覆盖马来语、英语、华语、淡米尔语 |
| OCR | PaddleOCR | 字幕、画面文字、水印导流号 |
| 语种识别 | fastText langid | 区分 ms / en / zh / ta |
| 音频特征 | wav2vec2 | 辅助音频违规判别 |

> **某地区多语种是关键难点**：马来语 + 英语 + 中文 + 淡米尔语 + 方言混杂，各模型需多语言能力或分语种路由。

---

## 4. L1 小模型粗筛层（高吞吐 / 低成本）

目标：拦截 85%+ 流量，单条延迟数十毫秒，GPU 批处理。

### 4.1 模型矩阵
| 维度                | 任务            | 开源基座                      |
| ----------------- | ------------- | ------------------------- |
| 色情低俗 (NSFW)       | 帧分类           | NSFW 模型 / 微调 EfficientNet |
| 暴力血腥              | 图像分类          | 微调 ConvNeXt / ViT         |
| 暴恐 / 武器 / 旗帜      | 目标检测          | YOLOv8/v10                |
| 广告导流 / 二维码 / 联系方式 | 检测 + OCR + 正则 | YOLO + PaddleOCR + 规则     |
| 多语言文本违规           | 文本分类          | XLM-R / 多语言 BERT 微调       |
| 仇恨 / 辱骂           | 文本分类          | 同上，分语种头                   |
| 图文相关性             | 图文匹配          | 多语言 CLIP                  |

### 4.2 路由决策（核心逻辑）
对每条内容输出 `{维度: 分数, 置信度}`，按规则路由：

- `最大风险分 < 低阈值` → **AUTO_PASS**，直接归档。
- `置信度 < 阈值` 或 命中敏感维度 → **送 L2 大模型**。
- `风险分 > 高阈值` → 仍送 L2，由大模型补「理由 + 证据」。
- **政治 / 宗教 / 王室 / 种族敏感** → 强制走 L2，且大概率转人工。

> 阈值按维度独立配置，并随人工反馈动态调优（见 §9）。

---

## 5. L2 大模型精审层（私有化 VLM / LLM）

目标：对「不确定 / 高风险 / 敏感」样本做多模态深度理解 + 可解释判定。

### 5.1 开源选型
| 类型 | 候选 | 用途 |
|------|------|------|
| 多模态大模型 (VLM) | Qwen2.5-VL / InternVL2.5 / LLaVA-OneVision | 看帧 + 读字幕 + 听转写综合判定 |
| 文本大模型 (LLM) | Qwen2.5 / Llama-3.x / DeepSeek | 长文本、评论、上下文推理 |
| 推理框架 | vLLM / SGLang / TensorRT-LLM | 高并发，量化 (AWQ/GPTQ) 降本 |

### 5.2 输出结构（可解释，对齐监管留存）
```json
{
  "content_id": "xxx",
  "decision": "VIOLATION | SUSPECT | PASS",
  "dimensions": [
    {"type": "政治敏感", "level": "高", "confidence": 0.92,
     "reason": "画面+字幕涉及…（具体说明）",
     "evidence": {"frames": ["t=12.4s"], "text_span": "..."}}
  ],
  "suggested_action": "下架建议 | 告警 | 入库归档",
  "model_version": "qwen2.5-vl-xxx",
  "reviewed_at": "2026-06-15T10:00:00+08:00"
}
```
### 5.3 提示工程要点

- 注入**马来西亚本地化审核规则手册**（分维度、分语种的判定标准与红线）。
- 强制结构化输出（JSON Schema 约束），保证可入库、可审计。
- 引入 few-shot 本地敏感案例，降低误判。

## 6. 审核维度与优先级

| 优先级 | 维度                         | 说明                       |
| --- | -------------------------- | ------------------------ |
| P0  | 政治 / 王室 / 种族 / 宗教敏感（3R 议题） | 当地高压线，零容忍，强制人工           |
| P0  | 未成年人保护                     | Act 866 法定义务，年龄相关、儿童不当内容 |
| P0  | 色情低俗                       | 含宗教文化敏感尺度                |
| P0  | 暴恐 / 极端主义                  | 旗帜、武器、煽动                 |
| P1  | 暴力血腥                       |                          |
| P1  | 仇恨言论 / 网络霸凌                | 多语种                      |
| P1  | 虚假信息 / 谣言                  | 舆情联动                     |
| P2  | 广告导流 / 诈骗引流                | 二维码、联系方式                 |
| P2  | 版权                         | 指纹比对                     |

> 优先级映射到「路由强度」与「人工抽检比例」：P0 维度全部经 L2，命中即转人工。

## 7. 舆情监测子系统

与审核共用数据与特征，叠加分析层：

- **事件聚类**：按话题 / 标签 / 关键词聚合，识别热点与异常增长。
- **情感分析**：多语言情感模型，监测负面舆情走势。
- **传播分析**：账号网络、转发链路、疑似水军/协同行为识别。
- **预警**：设定阈值（增速、负面占比、敏感维度命中量），触发分级告警。
- **看板**：趋势图、热词、Top 内容、地域分布，支持导出舆情报告。

## 8. 处置 & 输出层

| 动作     | 说明                             |
| ------ | ------------------------------ |
| 打标入库   | 全量结果结构化入库（维度、分数、理由、证据、版本）      |
| 告警     | 分级（即时/汇总）；渠道：邮件 / IM / Webhook |
| 下架建议   | 含理由与证据，供人工/客户决策                |
| 报告生成   | 自动生成监管合规报告、舆情报告（定期+按需）         |
| 客户系统对接 | 开放 API / 回调 / 消息队列推送           |
| 审计日志   | 全链路操作留痕，满足监管复核                 |

## 9. 人工审核工作台（L3）

- **任务队列**：按优先级与置信度排序，敏感样本置顶。
- **审核界面**：原视频 + 证据帧 + 字幕/转写 + 大模型理由，一屏决策。
- **操作**：确认 / 推翻 / 改判 + 标注违规维度 + 备注。
- **申诉处理**：客户/用户申诉流转复审。
- **质检**：双盲抽检、审核员一致性（Kappa）监控。
- **数据回流**：人工结论作为标注样本，回灌小模型与大模型微调集，形成闭环优化。
- **产能规划（百万/天参考）**：L1 拦截后约 10–15% 进 L2，其中约 1–3% 转人工 ≈ 1–3 万条/天；按人均 800–1200 条/天，需 **约 15–30 人审核团队**（分语种、三班倒），按实际命中率调整。

---

## 10. 数据存储与审计追溯

- **元数据库**：PostgreSQL（审核结论、标签、状态、版本）。
- **对象存储**：MinIO（私有化），存命中原片、证据帧、缩略图。
- **向量库**：Milvus（特征检索、去重、相似内容召回）。
- **搜索/日志**：OpenSearch（全文检索、审计日志）。
- **消息队列**：Kafka（分钟级流式处理主干）。
- **存储周期**：以月为单位（如命中样本 6–12 月、普通元数据 3 月），到期自动归档/清理，策略可配置。
- **审计追溯**：每条内容保留「数据来源→各模型版本→判定→人工动作→处置」完整链路，不可篡改（追加式日志 + 校验和）。

---

## 11. 部署与算力规划（私有化）

- **集群**：Kubernetes 编排；推理服务（GPU 节点）与流处理（CPU 节点）分离。
- **GPU 分配**：
    - L1 小模型：少量 GPU 即可支撑百万级（高吞吐、低算力）。
    - L2 大模型：主要算力消耗点，按 L2 流量比例与 SLA 配置 GPU 数量，量化 + 批处理 + 动态扩缩降本。
- **分钟级时效保障**：Kafka 流式 + 自动扩缩容 + 优先级队列（P0 内容插队）。
- **高可用**：多副本、限流降级（高峰时大模型降级为小模型 + 提高人工抽检）。

---

## 12. 闭环迭代机制

1. 人工标注回流 → 定期微调小模型、更新大模型提示与 few-shot。
2. 阈值与路由策略基于「漏判率/误判率/成本」周期性调优。
3. 维护本地化规则手册**，随法规（Act 866 后续细则）与舆情热点更新。
4. 监控指标：召回率、精确率、各级吞吐、L2 占比、人工占比、单条成本、端到端延迟。

---

## 13. 关键风险与建议

| 风险            | 缓解                      |
| ------------- | ----------------------- |
| 爬取合规/法律风险     | 优先官方/授权数据，合规网关强制，法务定期评估 |
| 多语种漏判（方言/混合语） | 分语种模型 + 大模型兜底 + 本地审核员   |
| 大模型成本失控       | 漏斗分级、量化、动态阈值、降级策略       |
| 政治/3R 误判代价高   | 强制人工 + 保守阈值 + 双人复核      |
| PDPA / 数据出境   | 全私有化、PII 脱敏、用途最小化       |
