## 核心摘要
本资料是 [[Karpathy]] 提出的 **[[LLM Wiki]]** 方法论原文（GitHub Gist），也是本知识库运作模式的奠基性文档。其核心主张是：**不要像 [[RAG]] 那样在每次查询时从头检索原始文档，而应让 LLM 增量构建并维护一个持久的、相互链接的 Markdown wiki**——知识"编译一次、持续更新"，而非每次重新推导。wiki 是一个"持续复利"的产物：交叉引用已建好、矛盾已标注、综合已反映所有阅读过的内容。人类负责筛选素材与提问，LLM 负责所有繁琐的维护（总结、交叉引用、归档），使维护成本趋近于零。

## 关键信息
**三层架构：**
- **Raw sources（原始资料）**：不可变的源文件集合，唯一真相来源，LLM 只读不改 → 对应本库 `raw/`。
- **The wiki（维基）**：LLM 生成并完全拥有的 Markdown 目录（摘要/实体/概念/对比/综合），随新源更新 → 对应本库 `wiki/`。
- **The schema（模式文件）**：告诉 LLM wiki 结构、规范与工作流的配置文件（如 CLAUDE.md / AGENTS.md）→ 对应本库根目录的 CLAUDE.md。

**三大操作：**
- **Ingest（摄入）**：丢入新源 → LLM 读、提炼、写摘要、更新 index 与相关实体/概念页、追加 log。单个源可能触及 10-15 个页面。
- **Query（查询）**：LLM 检索相关页 → 阅读 → 综合带引用的答案；**好答案应回填为 wiki 新页**，让探索也复利。
- **Lint（巡检）**：定期健康检查——矛盾、过时声明、孤儿页、缺失的概念页与交叉引用、可补的数据空白。

**两个特殊文件：**
- `index.md`：**内容导向**的目录，按类别组织，每次 ingest 更新，query 时先读它定位。中等规模（~100 源、数百页）下效果出色，无需 embedding RAG 基础设施。
- `log.md`：**时间导向**的 append-only 日志，统一前缀（`## [YYYY-MM-DD] op | desc`）便于 unix 工具解析（`grep "^## \[" log.md | tail -5`）。

**为什么有效：** 维护知识库的繁琐不在阅读思考，而在 bookkeeping（更新交叉引用、保持摘要新鲜、标注矛盾、跨页一致）。人类因维护成本超过价值而放弃；LLM 不厌其烦、不忘更新、一次可改 15 个文件。

**历史传承：** 理念与 [[Memex]]（Vannevar Bush, 1945）一脉相承——私人、主动策划、文档间关联与文档本身同等重要。Bush 未解决的"谁来做维护"，由 LLM 解决。
