产品将以438c方式进行编写，为了方便后续将以markdown的方式进行编写

可以核心实现的

| 阶段       | 文档            | 作用                   |
| -------- | ------------- | -------------------- |
| **计划阶段** | 软件开发计划        | 说明怎么开发、谁负责、里程碑、交付物   |
| **需求阶段** | 软件需求规格说明      | 说明软件必须实现什么功能和性能      |
| **设计阶段** | 软件概要设计说明      | 说明软件整体架构、模块划分、数据流    |
| **设计阶段** | 软件详细设计说明      | 说明每个模块内部逻辑、接口、数据结构   |
| **测试阶段** | 软件测试计划 / 测试说明 | 说明如何测试、测什么、测试环境      |
| **测试阶段** | 软件测试报告        | 说明测试结果、缺陷、是否通过       |
| **交付阶段** | 软件用户手册        | 说明用户如何使用软件           |
| **交付阶段** | 软件安装部署说明      | 说明如何安装、配置、运行         |
| **管理阶段** | 软件配置管理记录      | 管理版本、代码、文档、基线        |
| **管理阶段** | 需求跟踪矩阵        | 建立需求、设计、代码、测试之间的追踪关系 |

|   5 | 软件详细设计说明      | Detailed Design Description                     | 设计阶段  | 必写   |
|   6 | 接口设计说明        | Interface Design Description                    | 设计阶段  | 视情况  |
|   7 | 数据库设计说明       | Database Design Description                     | 设计阶段  | 视情况  |
|   8 | 软件测试计划 / 测试说明 | Software Test Plan / Software Test Description  | 测试阶段  | 必写   |
|   9 | 软件测试用例        | Test Cases / Test Procedures                    | 测试阶段  | 必写   |
|  10 | 软件测试报告        | Software Test Report                            | 测试阶段  | 必写   |

你可以把一个 438C 项目文档包组织成这样：
```
XX软件项目_438C文档包/
├── 01_计划类文档/
│   ├── 01_软件开发计划.docx
│   ├── 02_软件配置管理记录.docx
│   └── 03_软件质量保证记录.docx
│
├── 02_需求类文档/
│   ├── 01_软件需求规格说明.docx
│   ├── 02_接口需求规格说明.docx
│   └── 03_需求跟踪矩阵.xlsx
│
├── 03_设计类文档/
│   ├── 01_软件概要设计说明.docx
│   ├── 02_软件详细设计说明.docx
│   ├── 03_接口设计说明.docx

│
├── 04_测试类文档/

│   ├── 02_软件测试说明.docx
│   ├── 03_软件测试用例.docx

│   └── 05_软件问题报告.docx
│
├── 05_交付类文档/
│   ├── 01_软件用户手册.docx
```
