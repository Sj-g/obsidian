## 1 引言

### 1.1 标识

本文件为「认知行动平台」**MVP（最小可行产品）版本规划**。它不是 GJB 438C 正式软件工程文档（SRS/HLD/SDD）的替代，而是面向"可演示的最小产品"这一交付目标的**范围裁剪与实施规划**：在已完成的 SRS V3.8（40 项需求）/ HLD V2.7 / 7 子系统 SDD 基础上，裁剪出一条可演示的端到端链路，明确做什么、降级做什么、不做什么。

### 1.2 文档概述

本规划配合功能清单交付物 [`MVP功能清单.xlsx`](./MVP功能清单.xlsx)（11 张工作表：说明 / MVP范围总览 / **7 个子系统分表** / 阶段排期 / 风险登记）使用。**功能逐条明细（模块→功能层级，含优先级、状态、降级路径）以 xlsx 各子系统分表为唯一权威源**，本文档仅做概要引用与说明。

### 1.3 决策方法

本规划的所有取舍结论来自一次结构化的设计评审（grilling），沿决策树逐项确认。下文每节先给出"决策"，再给出"依据"。

## 2 MVP 定位

### 2.1 目标

**可演示的最小产品**——面向特定客户/任务的现场演示，重 UI 与可见效果，轻深层架构完备性。不是架构可行性验证，也不是真实小规模上线的内部工具。

> 依据：演示场景下，"看得见的执行"比"看不见的架构"更能打动观众；IRS/SWM/OCC 的深层分析能力可降级为预设数据或人工，不影响演示主线。

### 2.2 演示主线

**智能体蜂群养号/发帖**：客户坐下看 10 分钟，最打动人的故事是"一片真机同时在动 + 智能体看屏幕自主决策"。

> 依据：视觉冲击最强（设备画面同时在动 + 智能体自主决策），最能撑起"多设备矩阵 + 智能体"这个产品定位。全闭环演示里 IRS/SWM/OCC 分析部分很容易做成空壳。

### 2.3 子系统优先级

| 优先级 | 子系统 | MVP 角色 |
| --- | --- | --- |
| 主场 | **MC** | 演示核心：执行网关 + 远控 + 双执行模式 |
| 主场 | **SWM** | 提示词供给：产出提示词包驱动智能体 |
| 主场 | **IRS** | 演示灵魂：多模态视觉模型驱动智能体决策 |
| 配角 | **OCC** | 蜂群驱动源：行动编排下发蜂群执行 |
| 配角 | **DC** | 闭环起点：少量真采集供数据原料 |
| 底座 | **COM** | 能登录：统一鉴权底座 |
| 底座 | **OM** | 能看日志：最小可观测看板 |

### 2.4 约束

- **时间/人力**：3 个月 · 2-4 人（满负荷偏紧，见 §6 风险）。
- **交付物**：可现场演示的完整系统 + 一份说明文档。不做完整单元/集成/性能测试、不做正式部署包与运维手册。

## 3 三个架构原则（MVP 必须保住）

下列三项是平台架构底线，MVP 范围再裁剪也不可违背：

1. **动作收口（CON-07）**：所有真机动作（ADB/无障碍）均经 MC 统一执行网关落地，保证可观测、可审计、可熔断。
2. **推理与执行分离（CON-10）**：agent-runtime 调 IRS 多模态视觉推理**不经执行网关**（低延迟旁路），推理产出的动作指令**再经执行网关落地**。
3. **双执行模式（CON-08）**：脚本模式（GraalVM JS 沙箱，确定性流程保底）与智能体模式（agent-runtime + VLM，演示亮点）并存。智能体推理失败时降级为脚本模式。

> 这三项原则在 SRS/MC SDD 中已有设计支撑（MC SDD §5.2.2 `AgentRuntime.execute()` 含 `degrade_to_script_or_human(job)` 降级钩子），MVP 直接复用。

## 4 范围裁剪（按子系统）

> 逐条明细见 [`MVP功能清单.xlsx`](./MVP功能清单.xlsx) 各**子系统分表**（按「②模块→③功能」层级，共 133 功能点：74 项纳入 MVP + 59 项砍）。本节仅给出各子系统裁剪要点。

### 4.1 MC 多设备矩阵自动化群控（主场）

**纳入**：真机 ADB/无障碍接入（3-8 台）；自建 mc-sfu（mediasoup）单控 WebRTC + 多终端宫格预览；统一执行网关（收口鉴权/记录/基础熔断）；双执行模式（脚本 GraalVM JS 沙箱 + 智能体 agent-runtime）；账号主数据最小集（注册/凭据 AES-256-GCM 加密/平台/状态）；任务管理（入队/分发/简化状态机）；agent-runtime 调 IRS；代理 IP 绑定（简化版固定代理）。

**降级**：mc-sfu 故障降级截图轮询；智能体推理失败降级脚本；宫格可先只做多台截图刷新。

**砍**：指纹浏览器/云手机/虚拟化真机/ARM 板卡接入；完整账号生命周期/风险评估/分类；模板任务库；编排器（交 OCC）；脚本 IDE（MC-16）；熔断全套；录屏回看。

### 4.2 SWM 蜂群智能体（主场·提示词供给）

**纳入**：swm-gw/swm-memory（Java）；人设标签管理（Web 录入）；提示词包构建（agent_id + 人设 + 提示词 + 作业策略）经 II-14 同步 MC 持存；蜂群记忆读写（被 MC agent-runtime 远程读取）；coze-loop Playground（魔改接入，Web 试跑提示词看 IRS 输出）。

**降级**：coze-loop 魔改不成 → 砍 Playground，退 swm-gw 自研最简试运行；记忆服务不可用 → MC 无记忆降级运行。

**砍**：评测集/评估器/实验（M-SWM-06）；自动生成提示词（M-SWM-07，依赖 II-18 OCC 画像）；swm-distill 提炼编排；版本输出对比；完整评测迭代闭环。

### 4.3 IRS 私有化大模型部署（主场·演示灵魂）

**纳入**：部署 1 个多模态视觉模型（如 Qwen2-VL/InternVL）；提供 EI-05 统一推理接口（私有化，CON-06 不依赖公有云）；被 MC agent-runtime 调用做"截图 → 理解页面 → 输出动作"；被 SWM Playground 调用试跑提示词。

**降级**：VLM 效果差/延迟高 → 智能体降级 UI 树（a11y dump）+ 纯文本 LLM 推理（不看图但仍是智能体）；GPU 不足 → 更小参数模型。

**砍**：多模型管理/切换；完整推理监控；多租户配额；模型版本回退（用固定版本）。

### 4.4 OCC 舆情行动业务（配角·蜂群驱动源）

**纳入**：行动编排轻量版（R-OCC-006）——Web 选一群智能体节点 + 任务节点 → 经 II-10 下发 MC 执行 → 效果数据回传；预设数据看板（目标/效果用预设样本数据展示）。

**降级**：编排引擎不做 Flowable/BPMN，用最简任务下发；看板用静态预设数据。

**砍**：目标自动识别/分析研判自动化（M-OCC-02）；效果评估模型（M-OCC-06）；策略库（M-OCC-07）；内容管理（M-OCC-08）；关系图谱（NebulaGraph）。

> 关键架构事实：OCC 的行动编排（II-10）是"蜂群"唯一正宗的驱动源——不做 OCC，"一群智能体同时执行"就只能由 MC 自带批量下发（偏离架构）。故 OCC 即便配角也必须做编排最小版。

### 4.5 DC 数据爬取（配角·闭环起点）

**纳入**：少量真采集——1-2 个海外平台（如 X/TikTok）某话题的帖子/用户数据进库，为 OCC 看板提供数据原料。

**降级**：采集不稳/被反爬 → 完全用预设样本数据替代（省一整个 Python 子系统栈）。

**砍**：代理池/调度限流/策略自优化；PySpark ETL；ClickHouse 明细；NebulaGraph 关系；情报回注闭环（M-DC-04）。

> **排期吃紧首个砍项**：DC 真采集是第一个该砍的（退预设数据即可，省 Python 栈），绝不砍 MC 执行链路 + IRS 多模态。

### 4.6 COM 公共功能（底座·能登录）

**纳入**：登录 + JWT 签发；com-auth-lib 共享验签库（下沉到每个 Java 服务本地验签）；1-2 个角色（管理员/操作员）；组织隔离（org_id）。

**降级**：com-auth-lib 可先简化为共享密钥本地校验。

**砍**：完整 6 角色×21 权限 RBAC；组织管理 CRUD；5 次锁定策略；令牌黑名单/登出吊销。

> 不做 COM 则各 Java 服务裸奔（无统一鉴权），且 com-auth-lib 要下沉到每个 Java 服务才能验签，故 COM 最小登录不可省。

### 4.7 OM 运维监控（底座·能看日志）

**纳入**：最小日志/任务看板——各子系统上报的关键日志、设备在线状态、任务执行状态能在 Web 看到。

**降级**：只做关键日志聚合，不做指标检索/告警。

**砍**：KubeSphere 可观测底座；Prometheus/Grafana 指标；Alertmanager 告警；OpenSearch 日志检索；指标仪表盘。

### 4.8 前端

**纳入**：Web 控制台核心页——登录页/控制台门户/MC 终端台账/远程控制页（单控 + 宫格）/OCC 编排页/SWM 提示词页/OM 看板（约 10 核心页）。

> 设计参考线框稿 [`认知行动平台-线框图`](./认知行动平台-线框图)（.pen，已有 63 页设计），MVP 实现其中约 10 核心页。技术栈 Vue3/React + TypeScript。

## 5 阶段排期

> 明细见 [`MVP功能清单.xlsx`](./MVP功能清单.xlsx)「阶段排期」表。阶段按演示主线倒推：先打通演示灵魂（MC 执行 + IRS 多模态），再补驱动源（SWM 提示词），最后闭环（OCC 编排 + DC 采集）+ 联调演示。

| 阶段 | 时间窗 | 里程碑 | 交付物 |
| --- | --- | --- | --- |
| 第 0 阶段·地基 | 第 1-2 周 | M0：能登录 | 可登录的控制台骨架 + 1 台真机 ADB 可见 |
| 第 1 阶段·演示灵魂 | 第 3-6 周 | **M1：智能体能动★** | 单台真机：智能体看屏幕自主决策 + WebRTC 远控画面 |
| 第 2 阶段·提示词供给 | 第 7-9 周 | M2：提示词能驱动 | 一群智能体按各自人设+提示词包在多台真机上作业 |
| 第 3 阶段·闭环驱动 | 第 10-11 周 | M3：蜂群能编排 | OCC 编排驱动蜂群执行 + 效果看板 |
| 第 4 阶段·联调演示 | 第 12-13 周 | M4：可演示 | 可现场演示的完整系统 + 说明文档 |

**M1 是整个 MVP 的关键里程碑**，含一个★早期验证点：第 4-6 周必须验证"截图 → IRS 推理 → 动作"能跑通一次。跑不通即触发 §6 R1 降级（VLM → UI 树 + 文本 LLM）。

## 6 风险登记

> 明细见 [`MVP功能清单.xlsx`](./MVP功能清单.xlsx)「风险登记」表。

| 编号 | 风险 | 等级 | 应对/降级 | 触发判断点 |
| --- | --- | --- | --- | --- |
| **R1** | 多模态视觉模型驱动手机 GUI 效果差/延迟高（演示灵魂，不探针直接赌） | **高** | 降级 UI 树 + 纯文本 LLM；GPU 不足用更小模型；演示选 VLM 表现好的场景 | 第 4-6 周：截图→推理→动作能否跑通一次 |
| R2 | coze-loop 魔改不成 | 中 | 硬止损：时间盒 3 周，不成→砍 Playground，退 swm-gw 自研最简试运行 | 第 7-9 周末 |
| R3 | mc-sfu 自建 mediasoup WebRTC 联调复杂 | 中 | mc-sfu 故障降级截图轮询；宫格先做截图刷新 | 第 3-6 周 |
| R4 | 范围 vs 时间偏紧 | 中 | 按优先级砍：DC 真采集 → coze-loop Playground → OM/COM 非核心；绝不砍 MC+IRS | 每个里程碑评审 |
| R5 | 真机账号被平台风控/封禁 | 中 | 备用账号池；演示用养好的账号；脚本模式拟人化节奏 | 演示前账号健康检查 |

**R1 是 MVP 最高风险项**：决策上接受了"不探针直接赌 VLM"的赌注。这把风险集中到第 4-6 周的早期验证点——若到中后期才发现模型不行就来不及换，整个"智能体亮点"演示主线可能崩塌。M1 的早期验证点是这道风险的保险。

## 7 与正式文档的关系

本 MVP 规划**不修改** SRS V3.8 / HLD V2.7 / SDD 的任何需求、模块、接口、数据、约束编号。40 项功能需求（R-XX-NNN）与 14 项约束（CON-NN）全程不变，追溯仍以 [`软件需求跟踪矩阵.xlsx`](./软件需求跟踪矩阵.xlsx) 为唯一权威源。

MVP 是"在完整设计上裁剪出可演示子集"，是**实施层**的范围决策，不是**需求层**的变更。砍掉的能力（如 OCC 自动分析、SWM 评测、指纹浏览器接入）仍是正式需求的有效组成部分，只是本版不实现，留待 V1.1+。

[`MVP功能清单.xlsx`](./MVP功能清单.xlsx) 中的需求/模块/功能点编号均与正式文档对齐，便于后续将 MVP 实现回溯到正式需求追溯链。

## 8 附录：决策树复盘

本次 MVP 规划的取舍结论来自一次结构化设计评审（grilling），沿 11 个决策点逐项确认。决策树要点：

1. 目标 → 可演示的最小产品（非架构验证、非真实上线）
2. 演示主线 → 智能体蜂群养号/发帖（MC+SWM+IRS 主场）
3. 终端规模 → 单类型 3-8 台（最小证明）
4. 终端类型 → 真机 ADB + 自建 SFU（业务可信度优先）
5. 双执行模式 → 两者都做，脚本保底 + 智能体亮点
6. IRS → 多模态视觉模型（真智能体决策，高风险高回报）
7. SWM → 窄链路 + coze-loop Playground（魔改不成则砍）
8. OCC/DC → OCC 编排 + DC 真采集（全链路闭环）
9. 远控 → 单控 WebRTC + 宫格预览
10. OM/COM → 最小登录验签 + 最小日志看板
11. 时间/交付 → 3 个月·2-4 人，交付可演示系统 + 说明文档

每一项决策的"依据"与"降级路径"已固化在 [`MVP功能清单.xlsx`](./MVP功能清单.xlsx) 各表中，作为后续实施与范围调整的依据。
