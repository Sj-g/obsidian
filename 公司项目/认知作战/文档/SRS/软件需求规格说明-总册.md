## 1 引言

> **本册为《软件需求规格说明》总册**。V3.8 起，原单文件《软件需求规格说明.md》按子系统拆分为本总册 + 7 个子系统分册（位于本目录 `SRS/`）。总册承载引言、引用文件、需求框架与分册索引、接口需求、数据需求、非功能需求、合格性规定与附录等**系统级共性内容**；各子系统的功能需求（`R-XX-NNN`）见对应分册。需求编号 `R-XX-NNN` 全程不变，追溯以编号为准。

### 1.1 标识

本软件命名为"认知行动平台"（以下简称"系统"或"平台"）。系统由私有化大模型部署（IRS）作为底层推理基础设施，五个业务子系统与一组公共功能构成：数据爬取子系统（DC）、多设备矩阵自动化群控子系统（MC）、运维监控子系统（OM）、蜂群智能体子系统（SWM）、舆情行动业务子系统（OCC），以及公共功能（COM）。

### 1.2 软件概述

平台面向社交媒体，构建"**数据采集 → 分析研判 → 智能体编队 → 编队执行 → 效果评估 → 运维保障**"的完整需求能力闭环。

系统按职责分为三层。底层为基础设施层，包括私有化大模型部署、数据爬取子系统与运维监控子系统。私有化大模型部署（IRS）提供本地大模型的私有化部署与推理调用，使全系统的 AI 推理不依赖外部公有云；数据爬取子系统负责爬取工程底座与社交媒体数据的采集与 ETL 处理；运维监控子系统汇聚全系统日志与指标，完成常态化运维。

中层为执行层，包括多设备矩阵自动化群控子系统与蜂群智能体子系统。
群控子系统（MC）定位为"统一自动化执行引擎与多终端执行网关"，统一管理四类执行终端——移动端（真机、云手机、ARM 板卡、虚拟化真机）与桌面端（指纹浏览器 Profile）——提供终端接入、远程控制、指纹与代理隔离，承担账号资源（注册、凭据、验证、风险评估、生命周期、账号分类）的统一维护，并作为智能体的执行宿主。无论动作来自自动化脚本（移动端 ADB/无障碍、桌面端 CDP 等通道）还是智能体，所有落到任何执行终端的动作均经群控子系统的统一执行网关落地，从而保证每一个动作可观测、可审计、可熔断。
账号按终端类型遵循差异化的绑定规则：真机、云手机、虚拟化真机出于风控要求执行"一设备一账号一 IP"（一个终端仅绑定一个账号与一个固定代理 IP），指纹浏览器 Profile 执行"一 Profile 一账号一 IP"（浏览器实例可多开，每个 Profile 绑定一个账号身份与一个固定代理 IP）；智能体定义（agent_id）与账号（account_id）为 1:N 绑定（一个智能体可绑定多个账号，复用同一套行为风格与作业策略），但记忆与动态提示词实例按 account_id 1:1 归属（每个账号拥有独立的行为记忆与动态提示词实例）；叠加账号-终端绑定与终端-代理 IP 绑定，移动端形成 agent_id:account_id:终端:代理 IP = 1:N:1:1 的行动关系（其中 account_id:终端:代理 IP 为 1:1:1，agent_id:account_id 为 1:N），桌面端每个 Profile 内部同样形成 1:N:1:1；
蜂群智能体子系统（SWM）定位为"提示词生成与记忆中心"，根据画像、账号属性生成驱动智能体作业的提示词并管理记忆（人设属性直接写进提示词文本，不再作为独立数据实体），并将生成的提示词包（以 agent_id 为标识，含提示词、作业策略）同步下发至群控子系统持存；群控子系统在任务执行时由其 agent-runtime 子模块运行这些提示词包（场景适配、动态调用、调用 IRS 推理），并在执行前校验行为风格一致性。蜂群智能体子系统不直接操作设备，所有动作收口于群控子系统的执行网关。
执行层支持两种执行模式：脚本模式由固定流程驱动（含 ADB 脚本、CDP 等自动化通道），智能体模式由大模型实时决策驱动，两者均收口于群控子系统的统一执行网关。

上层为业务层，舆情行动业务子系统构建"目标识别 → 行动编排 → 效果评估"的行动闭环，并承担内容资源的统一管理。公共功能（COM）为各层提供统一的认证、权限与组织管理。

各子系统之间存在密切的协作关系。账号与内容是平台级的两类核心资源：账号资源由群控子系统（MC）统一管理（MC 既是账号权威源也是账号执行方），内容资源由舆情行动业务子系统（OCC）担任权威源；遵循"权威源唯一、使用方引用、变更经事件通知"的原则。

账号资源由群控子系统（MC）担任权威源，负责注册、验证、养护策略与生命周期等主数据的维护，并经事件总线向各子系统共享分发账号标识（account_id）。账号按用途分为两类：爬虫账号以桌面端指纹浏览器 Profile 为执行终端，承担数据采集兜底；认知行动账号以移动端设备为执行终端，承担认知行动养号。两类账号的注册、验证、生命周期主数据均由 MC 维护，养护（养号）动作均经 MC 的统一执行网关落地（爬虫账号经 CDP 通道、认知行动账号经 ADB/无障碍通道）、拟人化节奏由群控子系统的账号操作编排与养号能力（R-MC-009）内置。数据爬取（DC）、蜂群智能体（SWM）、舆情行动（OCC）作为账号使用方，仅引用账号标识并维护各自的扩展属性（如采集关联、提示词包、目标标注）。账号状态变更经事件总线广播 account.status.changed 事件，使用方订阅响应，确保被封禁等状态全网即时生效。

内容资源由舆情行动业务子系统（OCC）担任权威源，负责素材入库、分类、审核与发布排期，并向使用方主动分发内容标识（content_id）；蜂群智能体（养号文案）、群控（内容投放）与未来 AI 素材制作为使用方，通过引用内容标识获取内容，并在其上维护各自的平台适配版本与使用记录。

舆情行动子系统是全链路的指挥大脑：它基于数据爬取子系统的分析结果与本地大模型的推理能力，产出行动方案，并以"行动编排"的方式直接编排群控子系统中的智能体节点与自动化脚本节点形成执行流程（蜂群智能体子系统作为智能体节点的供给方之一参与编排），最终由群控子系统的设备矩阵执行落地，并将执行效果回传至舆情行动子系统进行评估闭环。

本地大模型部署为数据爬取的文本分析、蜂群智能体的行为决策、舆情行动的判别与策略生成提供统一的推理能力支撑。各子系统均向运维监控子系统上报日志与指标。

### 1.3 文档概述


功能需求编号采用 `R-XX-NNN`，其中 XX 为子系统代号（DC/MC/OM/COM/SWM/IRS/OCC）；非功能需求编号采用 `NR-类-N`。编号用于需求追踪与测试覆盖。

## 3 需求框架与分册索引

本节给出系统的功能需求组织方式与分册索引。功能需求按子系统组织，依次为数据爬取子系统（DC）、多设备矩阵自动化群控子系统（MC）、运维监控子系统（OM）、跨子系统的公共功能（COM）、蜂群智能体子系统（SWM）、私有化大模型部署（IRS）、舆情行动业务子系统（OCC）。每个用户需求先经"目标澄清、梳理场景、理清流程、理清流程-异常、列出规则"五步分析，并按"足够小、端到端、独立性、可测性"四原则重新划分为若干编号需求，每个编号需求按"需求目的、使用角色、前置条件、输入、输出、业务规则、异常场景、验收标准、关联接口"描述，并给出需求编号以便追踪。

**各子系统的功能需求（`R-XX-NNN`）位于对应分册**，接口/数据/非功能/约束等系统级共性需求见本总册第 4~6 章。

## 4 接口需求

### 4.1 外部接口需求

系统应提供与外部系统交互的接口。所有外部接口均应使用鉴权与传输加密。各接口如下：

**社交平台交互接口 EI-01**

对接对象：TikTok、Instagram、Facebook、YouTube、X 等社交平台。

输入：采集请求（平台、目标、范围、采集方式）、投放内容、账号操作指令。

输出：采集到的原始社交数据、投放/操作执行结果。

**代理 IP 服务接口 EI-02**

对接对象：VPS 代理链路与代理 IP 供应商。

输入：代理分配请求（平台、地区、数量）。

输出：可用代理 IP 列表、代理可用性状态、轮换日志。

**接码与虚拟号服务接口 EI-03**

对接对象：手机号接码与虚拟号服务。

输入：注册请求（平台、手机号或虚拟号标识）、验证码获取请求。

输出：接收的验证码、注册结果、虚拟号凭据。


**对象存储接口 EI-04**

对接对象：MinIO 或阿里云 OSS 等对象存储。

输入：上传文件（素材、截图、录屏）、下载请求、签名 URL 请求。

输出：文件存储路径、下载链接（限时签名）、存储结果。

**本地大模型推理接口 EI-05**

对接对象：底层私有化大模型部署（IRS）。

输入：推理请求（文本/截图、任务类型、上下文、行为风格参数）。

输出：推理结果（分类标签、立场、情感、观点、规划动作）。

**指纹浏览器服务接口 EI-06**

对接对象：商用指纹浏览器产品（提供 Profile 管理、指纹与代理配置、启动与调试端口返回、画面预览等能力的 HTTP API）。

输入：Profile 创建请求（指纹模板、代理、分组、标签）、Profile 启动/关闭请求、指纹与代理更新请求、画面预览请求、Profile 状态查询请求。

输出：Profile 标识、指纹配置结果、启动后返回的调试端口（CDP）、Profile 运行状态、页面预览画面流。MC 经该接口管理桌面端 Profile（创建/指纹固化/代理/启停），并经返回的调试端口用 CDP 控制页面动作（点击/输入等）。

### 4.2 内部接口需求

子系统间及子系统内部应通过明确的接口交互。各接口如下：

**账号服务接口 II-01**

提供方 → 调用方：群控子系统（MC） → 数据爬取（DC）、蜂群智能体（SWM）、舆情行动（OCC）。

输入：账号查询请求（account_id）、账号变更请求（状态、风险评估）。

输出：账号主数据（凭据、平台、状态、生命周期、风险等级、账号分类）。

**账号状态变更事件 II-01a**

提供方 → 事件总线 → 订阅方：群控子系统（MC） → 事件总线 → DC/SWM/OCC。

输入：account.status.changed 事件（account_id、旧状态、新状态、变更原因）。

输出：使用方订阅后执行响应（停止任务、停止养号、休眠智能体、移除目标），保证被封账号全网即时失效。

**Agent 指令与日志接口 II-02**

提供方 ↔ 调用方：群控子系统（MC）服务端 ↔ 设备端 Agent。

输入：下发指令（动作类型、参数、目标设备）、回传日志（执行结果、截图）。

输出：指令下发确认、日志与截图回传结果。

**远控画面传输接口 II-03**

提供方 → 调用方：MC 设备 → WebRTC SFU → 操作端。

输入：设备画面流、操作端输入事件（鼠标、键盘）。

输出：实时画面流（低延迟）、输入事件执行确认。

**日志与指标上报接口 II-04**

提供方 → 调用方：各子系统 → 运维监控子系统（OM）。

输入：子系统日志、运行指标（设备在线率、任务成功率、爬虫吞吐量、队列积压）。

输出：上报确认、入库结果。

**Kafka 数据总线接口 II-05**

提供方 → 调用方：数据爬取子系统（DC）内部采集 → 处理与存储环节。

输入：原始采集数据、共享资源状态变更事件。

输出：Kafka 消息流（分区分组、可回溯消费）。

**管理 REST 接口 II-06**

提供方 → 调用方：各子系统 → 前端与外部。

输入：设备/任务/内容/账号/审计的管理请求（CRUD 操作）。

输出：管理操作结果（数据列表、操作状态）。

**执行网关动作接口 II-07**

提供方 ← 调用方：群控子系统（MC）统一执行网关 ← 脚本引擎/智能体引擎。

输入：动作指令（动作类型、坐标/元素、参数、目标执行终端、账号标识、终端类型）。

输出：动作执行结果、动作日志记录、熔断记录。本接口统一收口移动端终端（真机/云手机/ARM 板卡/虚拟化真机，经 ADB/无障碍通道）与桌面端浏览器 Profile（经 CDP 通道）的所有动作。

**本地大模型推理调用接口 II-08**

提供方 → 调用方：群控子系统（MC）的 agent-runtime 子模块 → 私有化大模型部署（IRS）。

输入：推理请求（截图、任务类型、行为风格上下文）。

输出：推理结果（视觉理解、下一步动作规划）。此接口不经执行网关，以保证低延迟。

**行动编排下发与执行回传接口 II-10**

提供方 ↔ 调用方：舆情行动子系统（OCC） ↔ 群控子系统（MC）。

输入：下发——行动编排流程（目标、策略、内容、账号、时间、节点编排关系：智能体节点引用的智能体定义、自动化脚本节点及其前后序/并行/分支）；回传——作业执行效果数据（触达、互动、完成情况、节点执行结果）。

输出：编排下发确认、效果数据回传结果，形成行动执行闭环。OCC 直接编排 MC 中的智能体节点与自动化脚本节点落地，蜂群智能体子系统（SWM）作为智能体定义的供给方经 II-14 同步至 MC，作业执行效果经 MC 可观测性（R-MC-010）采集后回传 OCC 评估。

**执行网关日志上报接口 II-11**

提供方 → 调用方：群控子系统（MC）统一执行网关 → 运维监控子系统（OM）。

输入：全量动作日志、熔断记录（含移动端终端与桌面端浏览器 Profile 的动作）。

输出：上报确认、入库结果。

**内容服务接口 II-12**

提供方 → 调用方：舆情行动业务子系统（OCC） → 蜂群智能体（SWM）、群控（MC）。

输入：内容查询请求（content_id）、素材获取请求。

输出：内容主数据（素材、分类、审核状态）、素材文件或下载链接。

**内容变更事件 II-12a**

提供方 → 事件总线 → 订阅方：舆情行动业务子系统（OCC） → 事件总线 → SWM/MC。

输入：content.changed 事件（content_id、变更类型、新状态）。

输出：使用方订阅后执行响应（刷新缓存、更新平台适配）。

**分析数据与情报接口 II-13**

提供方 → 调用方：数据爬取子系统（DC） → 舆情行动子系统（OCC）。

输入：分析数据请求（舆情事件、目标、时间范围）。

输出：DC 采集与 ETL 加工后的原始舆情数据、传播数据、关系数据（供 OCC 内部 R-OCC-002~005 分析能力消费；文本分析结果、关系图谱等分析产物现由 OCC 内部产出，不再作为本接口输出）。

**提示词包同步接口 II-14**

提供方 → 调用方：蜂群智能体子系统（SWM） → 群控子系统（MC）。

输入：提示词包（以 agent_id + account_id 组合作为同步主键、当前生效版本号、提示词模板（agent_id 共性）、账号级动态提示词实例（account_id 个性）、作业策略；人设属性直接写进提示词文本，不再单列）。一个 agent_id 可绑定 N 个 account_id，每个 (agent_id, account_id) 组合同步一份独立的动态提示词包。记忆不在提示词包内，由 MC 的 agent-runtime 子模块运行时向 SWM 记忆服务按 account_id 读取（见 R-SWM-002）。

输出：同步确认、持存版本号。MC 以 agent_id + account_id 组合为主键持存提示词包，记录 agent_id↔account_id 1:N 绑定关系（一个 agent 可绑多个账号），作为 agent-runtime 在任务执行时运行与校验的依据（见 R-MC-014），并作为 OCC 行动编排中智能体节点的定义来源（以 agent_id 引用）。

**情报回注采集接口 II-15**

提供方 → 调用方：舆情行动子系统 OCC 分析（R-OCC-002 ~ R-OCC-005） → 数据爬取子系统 DC 情报回注（R-DC-007）与任务池调度（R-DC-003）。

输入：分析产出的高价值目标个体、关联实体与传播节点（来自 OCC 分析 R-OCC-002 ~ R-OCC-005），以及回注规则（自动回注或人工确认、优先级、来源情报标识）；扩散场景下另含扩散起点目标与扩散参数（关系类型、扩散层数、去重范围）。

输出：回注生成的采集任务（写入 task_pool，携带 source_type=intel_feedback 与来源情报标识）、回注与扩散的审计记录。该接口与 II-13（DC 原始数据→OCC）方向相反，构成"OCC 分析→DC 采集"跨子系统反向驱动闭环。

资源遵循统一约束：使用方只引用资源标识（account_id、content_id），不复制主数据；账号主数据由群控子系统（MC）担任权威源（R-MC-011），内容主数据由舆情行动业务子系统（OCC）担任权威源；状态变更一律经事件总线通知。

## 5 数据需求

系统应维护以下数据。账号与内容作为平台级资源按权威源模式分层存储：账号主数据（凭据、平台、状态、生命周期、风险评估、账号分类，凭据须加密存储）由群控子系统（MC）担任权威源统一维护（DR-02M）；账号扩展数据由使用方各自维护并引用账号标识，包括数据爬取侧的采集关联、群控侧的账号-终端绑定与登录状态（由 R-MC-009 维护）、智能体账号分层分组与作业生命周期（亦归 MC）、蜂群侧挂 agent_id 的提示词包（人设属性写进提示词文本，DR-02E2，见 DR-09）；账号标识（account_id）作为全局唯一引用贯穿各子系统。内容主数据（原始素材、分类、审核状态、来源）由舆情行动业务子系统（OCC）担任权威源统一维护（DR-03M）；内容扩展数据由使用方维护并引用内容标识，包括平台适配版本与使用记录（DR-03E）；内容标识（content_id）作为全局唯一引用。

其它数据包括：执行终端数据，包括移动端终端（真机/云手机/ARM 板卡/虚拟化真机）、桌面端浏览器 Profile、终端分组与终端指标（DR-01）；任务数据，包括任务、任务实例与任务日志（DR-04）；脚本与工作流数据，包括脚本、脚本版本与工作流定义（DR-05）；采集与 ETL 加工数据，其中 ETL 明细结果存于 ClickHouse，关系数据存于 NebulaGraph 图库（DR-06，限 DC 采集与清洗存储；分析能力 V3.3 起移至 OCC，其数据归 DR-11）；审计与风险数据，包括审计日志与风险事件（DR-07）；代理与指纹数据，包括代理 IP 池、移动端设备指纹配置与桌面端浏览器 Profile 指纹配置（DR-08，移动端与桌面端 Profile 指纹均归 MC）。

蜂群智能体数据，包括以 agent_id（稳定逻辑标识）为索引的提示词模板（提示词、作业策略及当前生效版本号；人设属性直接写进提示词文本，不再单列）及 agent_id↔account_id 的 1:N 绑定关系（一个 agent 可绑多个账号）、按 account_id 1:1 归属的账号级动态提示词实例与智能体作业记忆（记忆服务承载，以 account_id 为主键索引）与提示词模板版本（DR-09）；提示词包（模板+动态实例）由 SWM 生成并以 agent_id+account_id 组合同步至 MC 持存（见 R-MC-014），记忆由 SWM 记忆服务（Java）承载、运行时由 MC 的 agent-runtime 按 account_id 读取。智能体账号的分层分组关系与作业生命周期状态归 MC 维护（见 DR-02E2、R-MC-012）。本地大模型数据，包括本地大模型配置与推理调用日志（DR-10）。舆情行动数据，包括目标识别结果、传播链路、多维画像、抓手挖掘结果、行动编排流程（节点编排关系）、策略库版本与效果评估记录（DR-11）。

平台级资源数据的统一约束：主数据只存于权威源且唯一一份；使用方只存"资源标识 + 自有扩展属性"，不复制主数据；资源标识在全系统唯一；主数据状态变更经事件总线广播。

## 6 非功能需求

本节给出系统的非功能需求，包括性能、安全性、保密性、可靠性、可维护性、易用性、运行环境、故障处理与约束条件。

### 6.1 性能需求

系统应满足以下性能要求。
单设备远程控制端到端延迟应不大于 300 毫秒，多设备宫格预览可适当放宽（NR-P-01）。
单租户应支持不少于 200 台设备的并发接入与控制（NR-P-02）。
数据爬取子系统的爬虫集群应满足业务采集量的日处理能力，并支持水平扩展（NR-P-03）。
任务从入队到分发应不超过 2 秒，并支持任务优先级与最大并发控制（NR-P-04）。
WebRTC SFU 应支持单节点并发多路远控流，并在弱网下自动降帧（NR-P-05）。
运维监控的日志检索响应应不超过 3 秒，覆盖近 7 日数据（NR-P-06）。

### 6.2 安全性需求

系统应满足以下安全性要求。
系统应提供用户认证，并对全部 API 进行鉴权（NR-S-01）。
系统传输应全程使用 HTTPS 或 TLS，远程控制通道应加密（NR-S-02）。
账号凭据、代理凭据等敏感字段应加密存储，不得明文落库（NR-S-03）。
Agent 应进行签名校验以防止伪造设备接入，指令应签名（NR-S-04）。
脚本应运行于沙箱并配置权限白名单，禁止越权访问与读取敏感路径（NR-S-05）。
所有账号、设备、任务操作应留存审计日志，可追溯（NR-S-06）。
文件访问应使用签名 URL，限时有效（NR-S-07）。

### 6.3 保密性需求

系统应满足以下保密性要求。
多组织或多租户的数据应严格隔离，禁止跨组织访问（NR-C-01）。
数据访问应遵循最小权限原则，按角色与数据范围控制（NR-C-02）。
手机号、凭据等敏感数据应脱敏展示（NR-C-03）。数据库应定期备份，
数据导出操作应审计留痕（NR-C-04）。

### 6.4 可靠性需求

系统应满足以下可靠性要求。
核心服务可用性应不低于 99.5%（NR-R-01，**V2 目标**：当前版本各微服务单副本部署，可用性目标在 V2 多副本 HA 演进后强制达标）。
任务应支持幂等与失败重试，异常任务应自动熔断（NR-R-02）。
Agent 掉线应自动重连，设备重启后 Agent 应自启动（NR-R-03）。
关键服务应高可用部署，无单点故障（NR-R-04，**V2 目标**：当前版本各微服务单副本部署，存在单点；V2 演进多副本 HA 后达标）。
数据采集应具备补偿与断点续采能力（NR-R-05）。

### 6.5 可维护性需求

系统应满足以下可维护性要求。
系统应采用模块化、服务化设计，子系统可独立部署升级（NR-M-01）。
采集、调度、频率控制、代理等关键策略应可配置，无需修改代码（NR-M-02）。
系统应提供全链路日志与追踪，故障可定位（NR-M-03）。
系统应提供运维仪表盘与告警，支持常态化运维（NR-M-04）。

### 6.6 易用性需求

系统应满足以下易用性要求。
Web 管理后台界面应清晰，设备、任务、账号、内容分区明确（NR-U-01）。
批量操作应支持选择设备组并一键下发（NR-U-02）。
远程控制画面与任务日志应同屏可见（NR-U-03）。
关键操作应有确认与风险提示（NR-U-04）。

### 6.7 运行环境需求

服务端应运行于 Linux 操作系统，采用 Docker 与 Kubernetes 进行容器编排、并以 KubeSphere 作为统一容器管理平台（PaaS），后端采用 Python（FastAPI）。
数据存储应包括 PostgreSQL 或 MySQL、Redis、Kafka、ClickHouse、NebulaGraph 与 MinIO 或 OSS。
数据爬取子系统应基于 Kubernetes 容器化部署爬虫集群，支持横向扩缩容与节点故障自愈；原始采集数据经 Kafka 分区分组流转并支持回溯消费，任务去重与调度队列基于 Redis 实现。上述爬虫集群、Kafka 数据流转与 Redis 调度构成数据采集的资源底座。
前端应基于现代浏览器，采用 Vue3 或 React 与 TypeScript。
移动端应提供 Android Agent，兼容主流 Android 版本，设备类型包括真机、云手机、ARM 板卡与虚拟化真机，由群控子系统（MC）统一接入管理。桌面端指纹浏览器应对接商用指纹浏览器产品（经其 HTTP API 管理 Profile、配置指纹与代理，不自建浏览器内核）；商用产品在 Profile 启动后返回调试端口，MC 经 CDP 接入控制页面动作；Profile 数据由商用产品独立隔离存储，亦由群控子系统（MC）统一接入管理。移动端（含虚拟化真机）远程控制采用 WebRTC 通道，桌面端浏览器 Profile 远程控制采用商用指纹浏览器 API 画面预览。监控应采用 Prometheus、Grafana 与 ELK 或 Loki。

私有化推理服务应部署于配备 GPU 算力的私有化服务器或算力集群，用于本地大模型的加载与推理；部署不依赖外部公有云模型服务。

### 6.8 故障处理需求

系统应满足以下故障处理要求。
任务异常应自动熔断，停止后续执行并告警（NR-F-01）。
设备或 Agent 异常应自动隔离，不再派发任务，待恢复后重新接入（NR-F-02）。
账号发生封禁或受限等异常时，应自动停止该账号相关任务并告警（NR-F-03）。
消息中间件或数据库故障应具备重试与死信处理（NR-F-04）。
服务异常应具备降级能力，优先保障远程控制与日志通道（NR-F-05）。

### 6.9 约束条件

群控子系统最小可行产品优先接入云手机与真机、实现远程控制与基础任务（CON-01）。
第一阶段不自研云手机内核，优先接入第三方云手机 API（CON-02）。
爬虫与 ETL 应复用现有大数据与基础设施组件，包括 Kubernetes（由 KubeSphere 管理，爬虫集群容器编排）、Kafka、Redis、PySpark 与 ClickHouse（CON-03）。
蜂群智能体（SWM）、私有化大模型部署（IRS）、舆情行动（OCC）应优先实现核心闭环链路：本地大模型可用、蜂群可调度执行、舆情行动可形成识别到评估的闭环（CON-04）。
目标平台为海外社交平台，需考虑网络代理与合规边界（CON-05）。
大模型推理应采用私有化部署，不依赖外部公有云模型服务；多模型接入亦严格限于本地/私有化模型，系统应拒绝接入外部公有云模型（CON-06）。

所有执行终端动作均应经执行网关落地，禁止任何子系统或 Agent 绕过执行网关直接操作终端，以保证动作可观测、可审计、可熔断：移动端终端（真机/云手机/ARM 板卡/虚拟化真机）动作经 ADB/无障碍通道收口，桌面端指纹浏览器 Profile 动作经 CDP 通道收口，两类终端动作均经群控子系统（MC）的统一执行网关收口（CON-07）。
系统应同时支持脚本模式与智能体模式两种执行引擎，养号等风控敏感场景可优先采用脚本模式，内容投放与自适应场景可采用智能体模式（CON-08）。
执行终端应按指纹真实度进行风控分级，认知行动账号养号等高敏感场景应优先选用真机与 ARM 板卡，云手机与指纹浏览器 Profile 用于爬虫账号养护与规模化采集，模拟器仅用于测试（CON-09）。
智能体模式下由群控子系统（MC）的 agent-runtime 子模块调用 IRS 本地大模型完成视觉推理，不经 MC 执行网关；推理产出的动作指令再经执行网关落地（CON-10）。agent-runtime 与执行网关逻辑隔离，以保持"推理与执行分离"语义。
执行层职责应按"统一执行网关 + 内容权威源"两类归属：指纹浏览器 Profile 的管理（创建、指纹固化、接入、监控）与桌面端 CDP 执行网关、移动端终端管理与 ADB/无障碍执行网关、账号主数据（注册、凭据、验证、风险评估、生命周期、账号分类）的唯一维护与共享分发、智能体执行宿主（含运行时 agent-runtime 子模块），均归群控子系统（MC）；内容资源（素材入库、分类、审核、排期、分发）唯一权威源归舆情行动业务子系统（OCC）。蜂群智能体子系统（SWM）作为提示词生成与记忆中心，将生成的提示词包（提示词、作业策略）同步至 MC 持存，运行时（场景适配、动态调用、调用 IRS 推理）归 MC 的 agent-runtime 子模块；舆情行动子系统（OCC）以行动编排方式直接编排 MC 中的智能体节点与自动化脚本节点，使执行终端管理、账号主数据与动作执行统一收口（CON-11）。
指纹浏览器应对接商用指纹浏览器产品（经其 HTTP API），不自建浏览器内核；MC 经商用产品 API 创建/管理 Profile、配置指纹与代理，商用产品在 Profile 启动后返回调试端口，MC 经 CDP（Chrome DevTools Protocol）控制页面动作；浏览器 Profile 创建时由商用产品生成并固化指纹，一个 Profile 对应一套固定指纹与一个账号身份（CON-12）。
账号应按用途分类管理：爬虫账号以桌面端指纹浏览器 Profile 为执行终端、其养护（养号）动作执行经 MC 统一执行网关的 CDP 通道，认知行动账号以移动端设备为执行终端、经 MC 统一执行网关的 ADB/无障碍通道执行养号动作；两类账号的注册、验证与生命周期等主数据均由群控子系统（MC）统一维护并向各子系统分发 account_id。账号-终端-代理绑定遵循差异化规则：真机、云手机、虚拟化真机执行"一设备一账号一 IP"，指纹浏览器 Profile 执行"一 Profile 一账号一 IP"（实例可多开），每个终端/Profile 绑定一个固定代理 IP（CON-13）。
蜂群智能体子系统（SWM）的提示词工程（模板库、版本管理、Playground 试运行、版本输出对比）与智能体评测（评测集、评估器、实验）能力，以**魔改 coze-loop 作为 SWM 主体内核**（在开源 coze-loop 基础上定制开发，UI 层自研并与全平台统一控制台体验对齐，不再是旁挂外部黑盒）；其余智能体域组件（网关、编排提炼、记忆服务）采用 Java（Spring Boot），与管控/业务微服务统一 Java 栈一致（CON-14，智能体域特例，仿 DC 采集域特例思路）。

## 7 合格性规定

### 7.1 验证方法

系统应采用评审、演示、测试与分析相结合的方法进行合格性验证。评审用于对需求与设计文档进行相关方确认。演示用于对设备接入、远程控制、群控、采集与可视化等能力进行现场展示。测试用于对功能、接口、性能与安全进行验证。分析用于对日志、指标与审计记录进行分析确认。

### 7.2 验证条件

合格性验证应在部署完整的各子系统及其依赖组件的测试环境中进行。环境应接入不少于规定数量的测试设备，包括云手机与真机，以及测试账号。应准备目标平台的测试数据与代理 IP 资源。私有化推理服务应部署配备 GPU 算力的环境并加载本地大模型。蜂群智能体与舆情行动子系统应接入测试智能体账号与行动场景数据。

### 7.3 验证准则

验证应以本文件的需求为准则。功能需求应逐项验证通过。非功能需求应达标，其中性能指标应经实测满足，安全项应无高危问题。各子系统接口应联通，日志与指标应正常上报至运维监控子系统。验证应无遗留的致命与严重缺陷。

## 8 附录

### 8.1 需求编号说明

R-DC-NNN 表示数据爬取子系统功能需求，R-MC-NNN 表示多设备矩阵自动化群控子系统功能需求，R-OM-NNN 表示运维监控子系统功能需求，R-COM-NNN 表示公共功能需求，R-SWM-NNN 表示蜂群智能体子系统功能需求，R-IRS-NNN 表示私有化大模型部署功能需求，R-OCC-NNN 表示舆情行动业务子系统功能需求。NR-P、NR-S、NR-C、NR-R、NR-M、NR-U、NR-F 分别表示性能、安全、保密、可靠性、可维护性、易用性与故障处理的非功能需求。EI、II、DR、CON 分别表示外部接口、内部接口、数据与约束。

子系统代号对照：
DC（Data Crawler，数据爬取）、MC（Multi-device Control，多设备群控，统一自动化执行引擎与多终端执行网关，含账号资源管理与智能体执行宿主及运行时 agent-runtime 子模块）、OM（Ops Monitor，运维监控）、COM（Common，公共功能）、SWM（Swarm，蜂群智能体，提示词生成与记忆中心）、IRS（Inference Service，私有化大模型部署，底层推理基础设施）、OCC（Opinion Combat Command，舆情行动业务，行动编排并承担内容资源权威源）。
