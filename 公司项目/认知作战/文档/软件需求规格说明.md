## 1 引言

### 1.1 标识

本软件命名为"认知作战平台"（以下简称"系统"或"平台"）。系统由六个子系统与一组跨子系统的公共功能组成：数据爬取子系统（DC）、多设备矩阵自动化群控子系统（MC）、运维监控子系统（OM）、蜂群智能体子系统（SWM）、私有化推理服务子系统（IRS）、舆情作战业务子系统（OCC），以及公共功能（COM）。

本文件为 V2.0 版，相比 V1.0（仅含 DC、MC、OM、COM）新增 SWM、IRS、OCC 三个子系统，纳入蜂群智能体、私有化大模型推理、舆情作战业务闭环等能力。本文件依据 GJB 438C 编制，给出系统的软件需求规格说明（SRS），作为概要设计、详细设计、开发实现与验收确认的依据。

> 说明：本文件为**对内**技术需求文件，如实描述系统各能力的真实用途与边界，供研发团队开发与验收使用。

### 1.2 软件概述

平台面向社交媒体，构建"数据采集 → 分析研判 → 智能体编队 → 编队执行 → 效果评估 → 运维保障"的完整能力闭环。

系统按职责分为三层。底层为基础设施层，包括数据爬取子系统与运维监控子系统。数据爬取子系统负责爬取工程底座、账号维护、社交媒体数据的采集与分析；运维监控子系统汇聚全系统日志与指标，完成常态化运维。

中层为执行层，包括多设备矩阵自动化群控子系统与蜂群智能体子系统。群控子系统基于安卓设备矩阵，实现远程控制、群控、养号、数据兜底与内容投放，并对每一个动作提供可观测性；蜂群智能体子系统在群控之上构建智能体蜂群，实现智能体账号管理、蜂群任务智能分发、行为仿真与防伪装、集群负载均衡与离线保活，以及提示词与记忆管理。

上层为智能层，包括私有化推理服务子系统与舆情作战业务子系统。私有化推理服务子系统提供一体化的大模型推理底座、统一网关、智能路由、并发会话管控、量化适配与容错容灾，支撑全场景 AI 推理；舆情作战业务子系统构建"目标识别 → 情报侦察 → 多维画像 → 抓手挖掘 → 行动实施 → 效果评估"的作战闭环。公共功能（COM）为各子系统提供统一的认证、权限与组织管理。

各子系统之间存在密切的协作关系。账号是数据爬取、群控与蜂群智能体子系统的共享资产：数据爬取侧负责账号注册、验证与风险评估，群控侧通过养号维持账号存活，蜂群侧在账号上绑定人设标签并驱动智能体作业。

舆情作战子系统是全链路的指挥大脑：它基于数据爬取子系统的分析结果与私有化推理服务的推理能力，产出作战方案，再经蜂群智能体子系统调度，最终由群控子系统的设备矩阵执行落地，并将执行效果回传至舆情作战子系统进行评估闭环。

私有化推理服务子系统为数据爬取的文本分析、蜂群智能体的行为决策、舆情作战的判别与策略生成提供统一的推理能力支撑。各子系统均向运维监控子系统上报日志与指标。

### 1.3 文档概述

本文件第 1 章给出标识、概述与术语；第 2 章列出引用文件；第 3 章给出需求，其中 3.1 给出功能需求（按子系统划分能力，每个能力以能力说明、输入、处理、输出的段落式描述并附带需求编号），3.2 给出非功能需求（性能、安全、保密、可靠性、可维护性、易用性、运行环境、故障处理与约束条件）；第 4 章规定合格性验证方法；第 5 章给出需求可追溯性；第 6 章为附录。

功能需求编号采用 `FR-XX-NNN`，其中 XX 为子系统代号（DC/MC/OM/COM/SWM/IRS/OCC）；非功能需求编号采用 `NFR-类-N`。编号用于需求追踪与测试覆盖。

### 1.4 术语和缩略语

本节给出文档中使用的术语与缩略语。

群控，指对多台移动设备进行集中、同步、批量控制。智能体控制，指在设备端部署 Agent，按服务端下发的策略自主执行任务。养号，指通过模拟真人行为（发帖、关注、浏览等）维持社交账号的活跃度与可信度。数据兜底，指在常规爬取不可达时，由移动端或网页端作为补充采集手段。逆向，指对目标 App 的网络协议或界面结构进行分析，以获取数据或实现自动化。风控，指社交平台对异常或自动化行为的检测与处置机制。设备指纹，指标识设备身份的硬件与软件特征集合。云手机，指云端虚拟化或容器化的安卓实例。ARM 板卡，指集成 ARM 芯片的安卓主板设备。Agent，指部署在终端设备上、与服务端通信并执行指令的代理程序。ADB，即 Android Debug Bridge，安卓调试桥。WebRTC，指支持实时音视频通信的协议，用于远程控制画面传输。ETL，即数据抽取-转换-加载。RBAC，即基于角色的访问控制。K8s，即 Kubernetes 容器编排平台。Kafka、Redis、HBase、Spark 分别为消息中间件、缓存与键值存储、列式数据库与分布式计算引擎。

蜂群，指大量智能体账号组成的协同作业集群。智能体账号，指绑定人设标签、具备行为记忆、由系统驱动自主作业的社交账号。人设标签，指赋予智能体账号的身份特征、立场倾向、语言风格等画像标签。MCP，指蜂群资源集中调度的管理控制协议与模块，实现任务池统一管控与资源动态分配。提示词管理，指对驱动智能体作业的提示词模板进行分类、版本管理、场景适配与动态调用。记忆管理，指对智能体作业记忆进行存储、沉淀、复用与个性化延续。碎片化仿真作业，指将任务拆分为细碎、离散的动作并以拟人化节奏执行，模拟真人行为轨迹。防批量特征伪装，指规避账号操作在时间、频率、内容上的批量同质化特征，降低被识别风险。抓手，指舆情事件中可用于舆论干预的切入点、薄弱点或博弈支点。舆情对冲，指以正向内容铺垫或稀释负面舆论的策略动作。

立场倾向判别，指识别文本在特定议题上的立场取向。情感极性分析，指识别文本的情感正负倾向与强度。核心观点抽取，指从文本中提取主要观点与论据。AWQ，即 Activation-aware Weight Quantization，激活感知权重量化方法。INT4，指 4 比特整数量化精度。MoE，即 Mixture of Experts，混合专家模型结构。KV 缓存，指大模型推理中缓存的历史键值对，用于加速自回归生成。SFU，即 Selective Forwarding Unit，WebRTC 媒体转发单元。

## 3 需求

### 3.1 功能需求

本节给出系统的功能需求，按子系统组织。3.1.1 给出数据爬取子系统（DC）的功能需求，3.1.2 给出多设备矩阵自动化群控子系统（MC）的功能需求，3.1.3 给出运维监控子系统（OM）的功能需求，3.1.4 给出跨子系统的公共功能（COM）需求，3.1.5 给出蜂群智能体子系统（SWM）的功能需求，3.1.6 给出私有化推理服务子系统（IRS）的功能需求，3.1.7 给出舆情作战业务子系统（OCC）的功能需求，3.1.8 至 3.1.10 给出接口与数据需求。每个能力以段落式描述其能力说明、输入、处理与输出，并给出需求编号以便追踪。

#### 3.1.1 数据爬取子系统（DC）

##### 3.1.1.1 爬取工程基础（FR-DC-001 ~ 004）

该能力为数据爬取子系统提供分布式运行的工程底座。能力说明：系统应提供可弹性伸缩的爬虫集群、可靠的数据流转通道、任务调度与去重机制，以及面向海外社交平台的代理网络出口，支撑后续采集、分析等能力的稳定运行。

输入包括爬虫任务定义（目标平台、采集范围、频率）、节点资源配置、代理 IP 与 VPS 代理链路配置，以及平台与地区的分配策略。

处理上：

- 爬虫基于 K8s 部署，以容器化方式运行并支持横向扩缩容与节点自愈；
- 采集到的原始数据经 Kafka 消息中间件流转，支持分区分组与回溯消费；
- 任务调度与去重使用 Redis 实现，包括 URL 与任务去重、调度队列与分布式锁；
- 代理 IP 池对接 VPS 代理链路，按平台与地区分配代理，定时轮换，并对代理进行可用性检测与失效剔除。

输出为运行中的爬虫实例、Kafka 中的原始数据流、调度指令与去重结果，以及可用的代理 IP 列表与轮换日志。

##### 3.1.1.2 账号维护（FR-DC-010 ~ 014）

该能力负责社交媒体账号的提交、验证、日常维护、注册与生命周期管理，是数据采集与群控执行的共享账号来源。

输入包括待提交的账号信息（平台、账号名、凭据、标签、归属）、平台注册方式（邮箱、手机接码、虚拟号）、维护任务（发帖、关注、浏览），以及账号状态变更事件。

处理上：

- 账号提交后凭据加密存储并记录归属与标签；
- 账号验证通过登录探测与状态识别检测账号是否可用，并识别封禁、限制、需要验证等风险点，输出风险等级；
- 账号日常维护按拟人化的节奏模拟发帖、关注、浏览等真人行为，维持账号活跃度与权重；
- 账号注册支持邮箱注册、手机号接码注册与虚拟号注册流程；
- 账号生命周期在待登录、正常、受限、需验证、封禁、归档等状态间流转。

输出为入库的账号记录、账号可用性与风险评估结果、维护执行记录、注册成功的账号，以及账号的最新状态。

##### 3.1.1.3 社交媒体数据采集（FR-DC-020）

该能力从目标社交平台采集原始数据。能力说明：系统应支持多种采集手段，覆盖 TikTok、Instagram、Facebook、YouTube、X 等海外社交平台，作为后续分析的数据来源。

输入为目标平台标识与采集任务（采集对象、范围、频率、使用的采集方式）。

处理上，系统综合运用多种采集手段：

- 对 Instagram 采用逆向方式采集推荐、人物、Reels 等界面数据；
- 对 TikTok、Facebook 采用模拟点击自动化采集；
- 对提供官方 API 的平台通过 API 授权采集；
- 对网页端采用页面解析采集；
- 采集过程中使用代理 IP 与维护账号，以应对平台访问限制。

输出为采集到的原始社交数据，包括用户信息、内容、互动数据、关系数据等。

##### 3.1.1.4 数据处理与存储（FR-DC-021 ~ 022）

该能力对原始数据进行清洗加工并持久化存储。能力说明：系统应提供标准的大数据 ETL 链路，完成数据的抽取、转换与加载。

输入为采集到的原始数据。

处理上：

- 系统基于 Spark 或 MapReduce 进行分布式批处理计算，完成数据清洗、字段提取、格式标准化、去重与关联；
- 处理结果写入 HBase 列式数据库，元数据与索引写入关系型数据库，关系数据写入图数据库。

输出为清洗加工后的结构化数据，持久化于 HBase 与关系库中，可供分析与检索使用。

##### 3.1.1.5 数据分析与情报（FR-DC-023 ~ 029）

该能力对加工后的数据进行分析，提供从群体到个体的筛选、关系图谱、情报检索与可视化，并支持文本智能分析。

输入为加工后的数据、群体特征条件、实体标识、检索条件，以及待分析的文本内容与关键词库。

处理上：

- 系统结合人工智能算法实现从群体到个体的逐层下钻筛选，从大范围群体中定位目标个体；
- 基于实体与关联数据绘制关系图谱并支持图查询；
- 提供基础信息检索，按账号、昵称、标识等检索实体信息；
- 对给定实体输出关联拓扑与情报标签，形成关联网络；
- 聚合多来源信息形成实体的全维度档案；
- 对文本内容结合文本模型与关键词库进行规则匹配与分类筛选，用于内容研判与目标识别。

输出为目标个体集合、关系图谱、实体信息列表、关联拓扑与情报信息、实体档案视图、文本分类与筛选结果，以及可视化展示界面。

#### 3.1.2 多设备矩阵自动化群控子系统（MC）

本子系统以开发方案 V1.1 为依据展开，并按对内真实用途补充执行目标（群控、养号、数据兜底、内容投放）。子系统的核心要求是集群控制具备可观测性，对每一个动作都能知晓与追溯。

##### 3.1.2.1 设备管理（FR-MC-001 ~ 007）

该能力管理多类型设备的接入、分组、状态监控与基础操作。能力说明：系统应统一管理云手机、ARM 板卡、真实安卓手机与安卓模拟器，并支持网页端接入，为后续的远控、群控与任务执行提供设备资源池。

输入包括设备标识与 Agent 信息、分组与标签规则、设备指标心跳，以及针对设备集合的批量操作指令。

处理上：

- Agent 启动后向服务端注册并建立长连接，系统记录设备类型（区分虚拟移动端与实体移动端）、版本、型号、分组与标签；
- 系统持续采集并监控设备的在线与离线状态、电量、CPU、内存、存储与网络状态；
- 系统支持网页端接入，用于数据兜底获取与养号；
- 系统支持对设备集合进行批量安装与卸载 App、批量重启、批量截图，以及通过对象存储临时链接进行文件上传与下载。

输出为设备台账、设备分组关系、设备实时状态视图，以及批量操作执行结果。

##### 3.1.2.2 远程控制（FR-MC-010 ~ 014）

该能力提供对单台及多台设备的实时远程控制。能力说明：系统应提供低延迟的设备画面预览与输入控制，并支持多设备同屏监控，用于人工介入与设备操作。

输入为远控请求、目标设备标识，以及操作人员的鼠标、键盘输入事件。

处理上：

- 屏幕画面基于 WebRTC 传输，远程控制通道与任务执行通道相互分离以保证稳定性；
- 操作人员的鼠标与键盘事件被映射为设备的触摸、点击、滑动、输入及返回键、Home 键、多任务键事件；
- 系统支持由 Agent 采集的截图与录屏，并支持保存与回看；
- 多设备宫格监控以低码率同屏预览多台设备；
- 剪贴板在操作端与设备间双向同步。

输出为设备的实时画面流、被翻译并执行的设备事件、截图与录屏文件，以及多设备宫格预览画面。

##### 3.1.2.3 群控与执行（FR-MC-020 ~ 024）

该能力是群控子系统的核心执行能力，实现两种控制模式及其四类执行目标。

输入包括控制指令或任务策略、目标设备组、内容素材，以及目标账号与设备。

处理上：

- 手机群控模式接收控制指令与设备组，对多台设备进行同步控制，统一投放内容；
- 手机智能体控制模式由设备端 Agent 按服务端下发的策略自主执行任务，适应更复杂的执行场景；
- 数据兜底获取由移动端与网页端作为常规爬取的补充手段执行采集任务；
- 养号通过移动端按拟人化节奏模拟发帖、关注、浏览等真人行为，维持账号的活跃度与权重；
- 内容投放下发并发布内容素材到目标社交平台的目标账号。

所有执行动作均纳入可观测性体系留痕。

输出为群控同步执行结果、智能体自主执行结果、兜底采集数据、养号执行记录，以及内容投放执行记录。

##### 3.1.2.4 账号管理（FR-MC-030 ~ 032）

该能力在群控侧管理账号与设备、登录状态及操作记录，复用数据爬取子系统维护的账号池。

输入为账号与设备的绑定关系、账号登录事件，以及账号操作（发帖、关注、浏览等）。

处理上：

- 系统将账号绑定到具体设备，记录绑定关系；
- 系统记录账号在设备上的登录状态及其变化；
- 系统记录账号的各项操作，供审计与风控分析使用。

输出为账号与设备的绑定关系、登录状态记录，以及账号操作记录。

##### 3.1.2.5 内容管理（FR-MC-040 ~ 042）

该能力管理投放所需的内容素材、发布排期与发布审核。

输入为图片、视频、文案等素材，素材的标签与平台分类信息，发布排期，以及待发布内容。

处理上：

- 系统对素材进行分类管理，支持标签、平台分类与账号适配；
- 系统支持按素材、账号与时间制定定时发布排期；
- 发布前对内容进行审核与敏感词检测。

##### 3.1.2.6 任务管理（FR-MC-050 ~ 054）

##### 3.1.6.5 大模型并发会话管控（FR-IRS-050 ~ 053）

该能力构建精细化的大模型并发会话管控体系，适配常态与峰值的稳定并发推理需求。

输入为并发推理会话请求、KV 缓存资源配置、过载保护策略。

处理上，系统适配常态 130 路、峰值 155 路的稳定并发推理需求；系统对 KV 缓存资源进行动态调度与按需分配，提升并发吞吐与显存利用率；系统配套过载保护机制，在并发超过承载能力时进行保护性降级。

输出为稳定并发运行的推理会话及 KV 缓存调度状态。

##### 3.1.6.6 AWQ INT4 量化模型适配（FR-IRS-060 ~ 063）

该能力完成 AWQ INT4 量化模型的适配与优化定制开发。

输入为原始模型权重、AWQ 量化配置、MoE 专家路由配置。

处理上，系统完整保留模型的原生网络拓扑与专家结构；系统实现量化权重的高效加载，降低显存占用与加载时间；系统对 MoE 模型的专家路由进行精准校准，保证量化后的路由正确性；系统配套推理精度补偿算法，弥补量化带来的精度损失。

输出为适配完成的 AWQ INT4 量化模型及校准后的推理结果。

##### 3.1.6.7 推理队列容错容灾（FR-IRS-070 ~ 075）

该能力搭建高可靠的推理队列与容错容灾机制，保障推理业务连续运行。

输入为推理请求队列、异常与超时事件、容灾策略。

处理上，系统对异常请求进行自动重试；系统对超时请求进行熔断拦截，避免雪崩；系统对失败任务进行回滚与重试；系统在突发流量时进行削峰填谷，平滑负载；系统通过上述机制保障大模型推理业务七乘二十四小时稳定运行。

输出为容错处理后的推理结果、熔断与重试记录，以及稳定的推理服务运行状态。

#### 3.1.7 舆情作战业务子系统（OCC）

舆情作战业务子系统是全链路的指挥大脑，构建"目标识别 → 情报侦察 → 多维画像 → 抓手挖掘 → 行动实施 → 效果评估"的作战闭环。本子系统基于数据爬取子系统的分析结果与私有化推理服务的推理能力，产出作战方案并调度蜂群智能体子系统执行落地，最终对作战效果进行评估与迭代。

##### 3.1.7.1 目标识别（FR-OCC-010）

该能力精准识别舆情事件的目标要素。

输入为舆情事件数据、传播数据、相关账号与内容。

处理上：

- 系统识别舆情事件的事件主体（涉及的人、机构、议题）；
- 系统识别传播源头（首发账号、首发渠道）；
- 系统识别核心争议点（事件的主要分歧与矛盾）；
- 系统识别干预的目标对象（需影响的关键账号与群体）。

输出为事件主体、传播源头、核心争议点与干预目标对象的识别结果。

##### 3.1.7.2 情报线索侦察（FR-OCC-020 ~ 022）

该能力自动抓取舆情传播线索并溯源传播链路。

输入为舆情事件、传播数据流、侦察规则。

处理上：

- 系统自动抓取舆情传播线索，发现新的传播节点与扩散动向；
- 系统对传播链路进行溯源，还原事件的传播路径与关键转发节点；
- 系统挖掘潜在风险情报与扩散趋势，预判事件走向。

输出为传播线索清单、传播链路溯源图，以及风险情报与扩散趋势预判。

##### 3.1.7.3 全维度画像分析（FR-OCC-030 ~ 033）

该能力对事件、群体、账号、传播进行多维度建模分析。

输入为目标事件、群体数据、账号数据、传播数据。

处理上：

- 系统完成事件画像，刻画事件的主题、规模、烈度、阶段；
- 系统完成群体画像，刻画参与群体的构成、立场、情绪；
- 系统完成账号画像，刻画关键账号的角色、影响力、行为模式；
- 系统完成传播画像，刻画传播的速度、广度、结构。

输出为事件画像、群体画像、账号画像与传播画像的多维建模结果。

##### 3.1.7.4 抓手挖掘（FR-OCC-040 ~ 042）

该能力基于舆情特征与用户画像自动挖掘舆论干预的切入点。

输入为舆情特征、用户画像、事件争议点、传播薄弱点。

处理上：

- 系统基于舆情特征与用户画像自动挖掘舆论干预的切入点；
- 系统识别传播链路的薄弱点（影响力低、易渗透的节点）；
- 系统发现观点博弈的抓手（可用于引导或对冲的论据与话题）。

输出为干预切入点、传播薄弱点与观点博弈抓手的挖掘结果。

##### 3.1.7.5 舆情风险定级与对冲策略匹配（FR-OCC-050 ~ 053）

该能力对舆情风险进行定级并智能匹配对冲策略，支持热点事件快速响应。

输入为舆情事件特征、风险等级标准、策略库、热点事件信号。

处理上：

- 系统按预设标准对舆情风险进行定级（如低、中、高、紧急）；
- 系统根据风险等级与事件特征智能匹配对冲策略；
- 系统对热点事件提供快速响应机制，缩短从发现到响应的时延。

输出为舆情风险等级、匹配的对冲策略，以及热点事件响应方案。

##### 3.1.7.6 仿真舆论发声与观点博弈（FR-OCC-060 ~ 062）

该能力实现仿真舆论发声、观点博弈与话题节奏干预。

输入为对冲策略、智能体蜂群资源、话题上下文、目标节奏。

处理上：

- 系统驱动智能体进行仿真舆论发声，按人设与立场产出内容；
- 系统组织观点博弈，针对对立观点进行回应与引导；
- 系统对话题节奏进行干预，控制话题的热度走向与发酵节奏。

输出为仿真发声内容、观点博弈执行记录，以及话题节奏干预结果。

##### 3.1.7.7 全媒体投送适配与舆论对冲（FR-OCC-070 ~ 072）

该能力实现全媒体素材投送适配、正向舆论铺垫与负面舆情稀释对冲。

输入为全媒体素材（图文、视频、音频）、目标平台、对冲目标、负面舆情数据。

处理上：

- 系统对不同平台进行全媒体素材投送适配，按平台规格转换素材；
- 系统进行正向舆论铺垫，提前布局正向内容；
- 系统对负面舆情进行稀释与对冲，以正向与中性内容降低负面浓度。

输出为适配后的投送素材、正向舆论铺垫记录，以及负面舆情稀释对冲结果。

##### 3.1.7.8 行动方案实施（FR-OCC-080 ~ 082）

该能力根据挖掘的抓手自动匹配干预策略、生成作业方案并调度蜂群执行落地。

输入为抓手挖掘结果、策略库、蜂群资源状态、执行约束。

处理上：

- 系统根据挖掘的抓手自动匹配干预策略；
- 系统生成具体的作业方案（含内容、账号、时间、节奏）；
- 系统将作业方案调度至蜂群智能体子系统执行落地，并由群控设备矩阵实施。

输出为匹配的干预策略、生成的作业方案，以及调度执行落地的结果。

##### 3.1.7.9 效果评估（FR-OCC-090 ~ 093）

该能力完成单轮干预成效统计、舆论走势修正、策略迭代反馈与作业复盘，并支持中短期与长期效果评估。

输入为干预执行后的舆情数据、效果指标、历史基线、长周期观察数据。

处理上：

- 系统完成单轮干预的成效统计（触达、互动、立场变化等）；
- 系统对舆论走势进行修正评估；
- 系统将评估结果反馈至策略库以迭代优化；
- 系统进行作业复盘总结经验；
- 系统提供中短期实网绩效评估与长期舆论塑造效果评估接口，实现效果联动。

输出为单轮成效统计、舆论走势修正评估、策略迭代反馈、作业复盘报告，以及中短期与长期效果评估结果。

##### 3.1.7.10 线下态势联动研判（FR-OCC-100 ~ 101）

该能力实现线下态势联动研判与阵地运营效果数据复盘。

输入为线下态势数据、阵地运营数据、线上舆情数据。

处理上：

- 系统将线下态势与线上舆情进行联动研判，综合判断整体态势；
- 系统对阵地运营效果进行数据复盘，评估阵地的运营成效与改进方向。

输出为线上线下联动研判结论，以及阵地运营效果复盘结果。

##### 3.1.7.11 舆论作业策略库（FR-OCC-110 ~ 113）

该能力搭建并迭代多语种、多场景、多风格的舆论作业策略库。

输入为策略定义（语种、场景、风格、适用条件）、历史作业效果、迭代反馈。

处理上：

- 系统按多语种、多场景、多风格组织舆论作业策略库；
- 系统对策略进行分类管理与版本控制；
- 系统根据作业效果反馈对策略进行迭代优化；
- 系统支持策略的场景适配与动态调用。

输出为多语种多场景多风格的舆论作业策略库、策略版本记录，以及迭代优化结果。

#### 3.1.8 外部接口需求

系统应提供与外部系统交互的接口。其一，系统应通过逆向、模拟点击与官方 API 等方式与 TikTok、Instagram、Facebook、YouTube、X 等社交平台交互（EI-01）。其二，系统应对接 VPS 代理链路与代理 IP 供应商，获取代理网络出口（EI-02）。其三，系统应对接手机号接码与虚拟号服务，用于账号注册（EI-03）。其四，系统应对接第三方云手机供应商 API，获取云手机实例（EI-04）。其五，系统应对接 MinIO 或阿里云 OSS 等对象存储，存储素材、截图与录屏（EI-05）。其六，系统应在大模型层面实现私有化部署，不依赖外部公有云模型服务，相关推理能力由私有化推理服务子系统（IRS）内部提供（EI-06）。所有外部接口均应使用鉴权与传输加密。

#### 3.1.9 内部接口需求

子系统间及子系统内部应通过明确的接口交互。数据爬取子系统与群控子系统之间应提供账号池接口，群控子系统据此复用账号并绑定设备（II-01）。群控子系统的 Agent 与服务端之间应通过 WebSocket 或 MQTT 长连接下发指令并回传日志（II-02）。群控子系统与设备之间应通过 WebRTC SFU 传输远控画面与输入（II-03）。各子系统应通过日志采集 Agent 与指标采集器向运维监控子系统上报日志与指标（II-04）。数据爬取子系统内部应以 Kafka 作为数据总线，将采集数据流转至处理与存储环节（II-05）。系统应提供设备、任务、内容、账号、审计等管理的 REST 接口，供前端与外部调用（II-06）。

蜂群智能体子系统与群控子系统之间应提供资源与执行接口，蜂群子系统复用群控的设备资源池，并将作业指令下达到设备执行（II-07）。舆情作战子系统与蜂群智能体子系统之间应提供作战方案下发与效果回传接口，形成作战执行闭环（II-08）。私有化推理服务子系统应提供统一推理网关接口，向数据爬取、蜂群智能体、舆情作战等子系统提供标准化推理调用（II-09）。蜂群智能体子系统与数据爬取子系统之间应共享账号池，蜂群账号的人设标签与生命周期管理复用数据爬取侧的账号资产（II-10）。舆情作战子系统与数据爬取子系统之间应提供分析数据与情报接口，作战研判基于爬取侧的分析结果展开（II-11）。

#### 3.1.10 数据需求

系统应维护以下数据：设备数据，包括设备、设备分组与设备指标（DR-01）；账号数据，包括社交账号、登录记录与操作记录，凭据须加密存储（DR-02）；内容数据，包括素材、发布排期与发布记录（DR-03）；任务数据，包括任务、任务实例与任务日志（DR-04）；脚本与工作流数据，包括脚本、脚本版本与工作流定义（DR-05）；采集与分析数据，其中 ETL 结果存于 HBase，关系数据存于图数据库（DR-06）；审计与风险数据，包括审计日志与风险事件（DR-07）；代理与指纹数据，包括代理 IP 池与设备指纹配置（DR-08）。

蜂群智能体数据，包括智能体账号的人设标签、分层分组关系、生命周期状态、作业记忆与提示词模板版本（DR-09）。推理服务数据，包括推理请求日志、并发会话状态、KV 缓存调度记录与量化模型配置（DR-10）。舆情作战数据，包括目标识别结果、传播链路、多维画像、抓手挖掘结果、作战方案、策略库版本与效果评估记录（DR-11）。

### 3.2 非功能需求

本节给出系统的非功能需求，包括性能、安全性、保密性、可靠性、可维护性、易用性、运行环境、故障处理与约束条件。

#### 3.2.1 性能需求

系统应满足以下性能要求。单设备远程控制端到端延迟应不大于 300 毫秒，多设备宫格预览可适当放宽（NFR-P-01）。单租户应支持不少于 200 台设备的并发接入与控制（NFR-P-02）。数据爬取子系统的爬虫集群应满足业务采集量的日处理能力，并支持水平扩展（NFR-P-03）。任务从入队到分发应不超过 2 秒，并支持任务优先级与最大并发控制（NFR-P-04）。WebRTC SFU 应支持单节点并发多路远控流，并在弱网下自动降帧（NFR-P-05）。运维监控的日志检索响应应不超过 3 秒，覆盖近 7 日数据（NFR-P-06）。

私有化推理服务应支持常态 130 路、峰值 155 路的稳定并发推理会话（NFR-P-07）。推理统一网关应对推理请求进行集中接入与限流，单请求经校验、过滤到转发的处理应满足实时推理时延要求（NFR-P-08）。推理队列在突发流量下应通过削峰填谷保障稳定，异常请求重试与超时熔断不应影响其他会话（NFR-P-09）。AWQ INT4 量化模型相对原模型的精度损失应控制在可接受范围，由精度补偿算法予以弥补（NFR-P-10）。

#### 3.2.2 安全性需求

系统应满足以下安全性要求。系统应提供用户认证与双因素，并对全部 API 进行鉴权（NFR-S-01）。系统传输应全程使用 HTTPS 或 TLS，远程控制通道应加密（NFR-S-02）。账号凭据、代理凭据等敏感字段应加密存储，不得明文落库（NFR-S-03）。Agent 应进行签名校验以防止伪造设备接入，指令应签名（NFR-S-04）。脚本应运行于沙箱并配置权限白名单，禁止越权访问与读取敏感路径（NFR-S-05）。所有账号、设备、任务操作应留存审计日志，可追溯（NFR-S-06）。文件访问应使用签名 URL，限时有效（NFR-S-07）。

#### 3.2.3 保密性需求

系统应满足以下保密性要求。多组织或多租户的数据应严格隔离，禁止跨组织访问（NFR-C-01）。数据访问应遵循最小权限原则，按角色与数据范围控制（NFR-C-02）。手机号、凭据等敏感数据应脱敏展示（NFR-C-03）。数据库应定期备份，数据导出操作应审计留痕（NFR-C-04）。

#### 3.2.4 可靠性需求

系统应满足以下可靠性要求。核心服务可用性应不低于 99.5%（NFR-R-01）。任务应支持幂等与失败重试，异常任务应自动熔断（NFR-R-02）。Agent 掉线应自动重连，设备重启后 Agent 应自启动（NFR-R-03）。关键服务应高可用部署，无单点故障（NFR-R-04）。数据采集应具备补偿与断点续采能力（NFR-R-05）。

#### 3.2.5 可维护性需求

系统应满足以下可维护性要求。系统应采用模块化、服务化设计，子系统可独立部署升级（NFR-M-01）。采集、调度、频率控制、代理等关键策略应可配置，无需修改代码（NFR-M-02）。系统应提供全链路日志与追踪，故障可定位（NFR-M-03）。系统应提供运维仪表盘与告警，支持常态化运维（NFR-M-04）。

#### 3.2.6 易用性需求

系统应满足以下易用性要求。Web 管理后台界面应清晰，设备、任务、账号、内容分区明确（NFR-U-01）。批量操作应支持选择设备组并一键下发（NFR-U-02）。远程控制画面与任务日志应同屏可见（NFR-U-03）。关键操作应有确认与风险提示（NFR-U-04）。

#### 3.2.7 运行环境需求

服务端应运行于 Linux 操作系统，采用 Docker 与 Kubernetes 进行容器编排，后端采用 Java Spring Boot 或 Go。数据存储应包括 PostgreSQL 或 MySQL、Redis、Kafka、HBase、图数据库与 MinIO 或 OSS。前端应基于现代浏览器，采用 Vue3 或 React 与 TypeScript。移动端应提供 Android Agent，兼容主流 Android 版本，设备类型包括云手机、ARM 板卡、真机与模拟器。监控应采用 Prometheus、Grafana 与 ELK 或 Loki。

私有化推理服务应部署于配备 GPU 算力的私有化服务器或算力集群，满足常态 130 路至峰值 155 路并发推理的显存与算力需求；推理框架应支持 AWQ INT4 量化权重的高效加载与 MoE 专家路由；推理网关与会话管控服务应以高可用方式部署。

#### 3.2.8 故障处理需求

系统应满足以下故障处理要求。任务异常应自动熔断，停止后续执行并告警（NFR-F-01）。设备或 Agent 异常应自动隔离，不再派发任务，待恢复后重新接入（NFR-F-02）。账号发生封禁或受限等异常时，应自动停止该账号相关任务并告警（NFR-F-03）。消息中间件或数据库故障应具备重试与死信处理（NFR-F-04）。服务异常应具备降级能力，优先保障远程控制与日志通道（NFR-F-05）。

#### 3.2.9 约束条件

群控子系统应按开发方案 V1.1 分阶段落地，最小可行产品优先接入云手机与真机、实现远程控制与基础任务（CON-01）。第一阶段不自研云手机内核，优先接入第三方云手机 API（CON-02）。爬虫与 ETL 应复用现有大数据组件，包括 Kafka、Spark 与 HBase（CON-03）。蜂群智能体（SWM）、私有化推理（IRS）、舆情作战（OCC）三个子系统为本期 V2.0 新增能力，应优先实现核心闭环链路：推理底座可用、蜂群可调度执行、舆情作战可形成识别到评估的闭环（CON-04）。目标平台为海外社交平台，需考虑网络代理与合规边界（CON-05）。大模型推理应采用私有化部署，不依赖外部公有云模型服务，并采用 AWQ INT4 量化以适配自有算力（CON-06）。

## 4 合格性规定

### 4.1 验证方法

系统应采用评审、演示、测试与分析相结合的方法进行合格性验证。评审用于对需求与设计文档进行相关方确认。演示用于对设备接入、远程控制、群控、采集与可视化等能力进行现场展示。测试用于对功能、接口、性能与安全进行验证。分析用于对日志、指标与审计记录进行分析确认。

### 4.2 验证条件

合格性验证应在部署完整的各子系统及其依赖组件的测试环境中进行。环境应接入不少于规定数量的测试设备，包括云手机与真机，以及测试账号。应准备目标平台的测试数据与代理 IP 资源。私有化推理服务应部署满足并发会话规模（常态 130 路、峰值 155 路）的 GPU 算力环境，并加载 AWQ INT4 量化模型。蜂群智能体与舆情作战子系统应接入测试智能体账号与作战场景数据。

### 4.3 验证准则

验证应以本文件的需求为准则。功能需求应逐项验证通过。非功能需求应达标，其中性能指标应经实测满足，安全项应无高危问题。各子系统接口应联通，日志与指标应正常上报至运维监控子系统。验证应无遗留的致命与严重缺陷。

## 6 附录

### 6.1 需求编号说明

FR-DC-NNN 表示数据爬取子系统功能需求，FR-MC-NNN 表示多设备矩阵自动化群控子系统功能需求，FR-OM-NNN 表示运维监控子系统功能需求，FR-COM-NNN 表示公共功能需求，FR-SWM-NNN 表示蜂群智能体子系统功能需求，FR-IRS-NNN 表示私有化推理服务子系统功能需求，FR-OCC-NNN 表示舆情作战业务子系统功能需求。NFR-P、NFR-S、NFR-C、NFR-R、NFR-M、NFR-U、NFR-F 分别表示性能、安全、保密、可靠性、可维护性、易用性与故障处理的非功能需求。EI、II、DR、CON 分别表示外部接口、内部接口、数据与约束。

子系统代号对照：DC（Data Crawler，数据爬取）、MC（Multi-device Control，多设备群控）、OM（Ops Monitor，运维监控）、COM（Common，公共功能）、SWM（Swarm，蜂群智能体）、IRS（Inference Service，私有化推理服务）、OCC（Opinion Combat Command，舆情作战业务）。
