## 引言

### 标识

本软件命名为"认知作战平台"（以下简称"系统"或"平台"）。系统由私有化大模型部署（IRS）作为底层推理基础设施，五个业务子系统与一组公共功能构成：数据爬取子系统（DC）、多设备矩阵自动化群控子系统（MC）、运维监控子系统（OM）、蜂群智能体子系统（SWM）、舆情作战业务子系统（OCC），以及公共功能（COM）。

> V3.0 架构调整说明：V2.0 中的"指纹浏览器管理子系统（FB）"与"共享资源管理子系统（SR）"已整体并入"多设备矩阵自动化群控子系统（MC）"——FB 的桌面端浏览器 Profile 管理与桌面端执行网关、SR 的账号资源管理现均由 MC 统一承担，原 FR-FB-001/002 融入 FR-MC-001/003、FR-SR-001 融入新增的 FR-MC-010。详见 MC 子系统章节与可追溯性章节。

### 软件概述

平台面向社交媒体，构建"**数据采集 → 分析研判 → 智能体编队 → 编队执行 → 效果评估 → 运维保障**"的完整需求能力闭环。

系统按职责分为三层。底层为基础设施层，包括私有化大模型部署、数据爬取子系统与运维监控子系统。私有化大模型部署（IRS）提供本地大模型的私有化部署与推理调用，使全系统的 AI 推理不依赖外部公有云；数据爬取子系统负责爬取工程底座与社交媒体数据的采集与分析；运维监控子系统汇聚全系统日志与指标，完成常态化运维。

中层为执行层，包括多设备矩阵自动化群控子系统与蜂群智能体子系统。
群控子系统（MC）定位为"统一自动化执行引擎与多终端执行网关"，统一管理四类执行终端——移动端（真机、云手机、ARM 板卡、虚拟化真机）与桌面端（反指纹浏览器 Profile）——提供终端接入、远程控制、指纹与代理隔离，承担账号资源（注册、凭据、验证、风险评估、生命周期、账号分类）的统一维护，并作为智能体的执行宿主。无论动作来自自动化脚本（ADB/RDP/CDP 等通道）还是智能体，所有落到任何执行终端的动作均经群控子系统的统一执行网关落地，从而保证每一个动作可观测、可审计、可熔断。账号按终端类型遵循差异化的绑定规则：真机、云手机、虚拟化真机出于风控要求执行"一设备一账号"（一个终端仅绑定一个账号），反指纹浏览器 Profile 执行"一 Profile 一账号"（浏览器实例可多开，每个 Profile 绑定一个账号身份）；
蜂群智能体子系统（SWM）定位为"智能体定义与记忆中心"，根据人设（画像、账号属性）编写驱动智能体作业的提示词与记忆，并将智能体定义（人设标签、提示词、记忆、作业策略）同步下发至群控子系统持存；群控子系统在任务执行时调用这些智能体定义驱动设备作业。蜂群智能体子系统不直接操作设备，所有动作收口于群控子系统的执行网关。
执行层支持两种执行模式：脚本模式由固定流程驱动（含 ADB 脚本、RDP、CDP 等自动化通道），智能体模式由大模型实时决策驱动，两者均收口于群控子系统的统一执行网关。

上层为业务层，舆情作战业务子系统构建"目标识别 → 作战编排 → 效果评估"的作战闭环，并承担内容资源的统一管理。公共功能（COM）为各层提供统一的认证、权限与组织管理。

各子系统之间存在密切的协作关系。账号与内容是平台级的两类核心资源：账号资源由群控子系统（MC）统一管理（MC 既是账号权威源也是账号执行方），内容资源由舆情作战业务子系统（OCC）担任权威源；遵循"权威源唯一、使用方引用、变更经事件通知"的原则。

账号资源由群控子系统（MC）担任权威源，负责注册、验证、养护策略与生命周期等主数据的维护，并经事件总线向各子系统共享分发账号标识（account_id）。账号按用途分为两类：爬虫账号以桌面端反指纹浏览器 Profile 为执行终端，承担数据采集兜底；认知作战账号以移动端设备为执行终端，承担认知作战养号。两类账号的注册、验证、生命周期主数据均由 MC 维护，养护（养号）动作均经 MC 的统一执行网关落地（爬虫账号经 CDP 通道、认知作战账号经 ADB/无障碍通道）、拟人化策略由蜂群智能体子系统提供。数据爬取（DC）、蜂群智能体（SWM）、舆情作战（OCC）作为账号使用方，仅引用账号标识并维护各自的扩展属性（如采集关联、人设标签、目标标注）。账号状态变更经事件总线广播 account.status.changed 事件，使用方订阅响应，确保被封禁等状态全网即时生效。

内容资源由舆情作战业务子系统（OCC）担任权威源，负责素材入库、分类、审核与发布排期，并向使用方主动分发内容标识（content_id）；蜂群智能体（养号文案）、群控（内容投放）与未来 AI 素材制作为使用方，通过引用内容标识获取内容，并在其上维护各自的平台适配版本与使用记录。

舆情作战子系统是全链路的指挥大脑：它基于数据爬取子系统的分析结果与本地大模型的推理能力，产出作战方案，并以"作战编排"的方式直接编排群控子系统中的智能体节点与自动化脚本节点形成执行流程（蜂群智能体子系统作为智能体节点的供给方之一参与编排），最终由群控子系统的设备矩阵执行落地，并将执行效果回传至舆情作战子系统进行评估闭环。

本地大模型部署为数据爬取的文本分析、蜂群智能体的行为决策、舆情作战的判别与策略生成提供统一的推理能力支撑。各子系统均向运维监控子系统上报日志与指标。

### 文档概述


功能需求编号采用 `FR-XX-NNN`，其中 XX 为子系统代号（DC/MC/OM/COM/SWM/IRS/OCC）；非功能需求编号采用 `NFR-类-N`。编号用于需求追踪与测试覆盖。

## 需求

### 功能需求

本节给出系统的功能需求，按子系统组织。依次给出数据爬取子系统（DC）、多设备矩阵自动化群控子系统（MC）、运维监控子系统（OM）、跨子系统的公共功能（COM）、蜂群智能体子系统（SWM）、私有化大模型部署（IRS）、舆情作战业务子系统（OCC）的功能需求，随后给出接口与数据需求。每个功能按"功能目的、使用角色、前置条件、输入、输出、业务规则、异常场景、验收标准"描述，并给出需求编号以便追踪。

#### 数据爬取子系统（DC）

##### 社交媒体数据采集（FR-DC-002）

**功能目的**：从目标社交平台采集原始数据，覆盖 TikTok、Instagram、Facebook、YouTube、X 等海外社交平台，作为后续分析的数据来源。本功能同时承担采集的执行调度：管理采集任务池、URL 与任务去重、调度队列与配额限流，以及面向海外社交平台的代理网络出口（代理 IP 池按平台与地区分配、定时轮换、可用性检测与失效剔除），保证采集动作稳定、不重复、不失控。爬虫集群的容器化部署与 Kafka、Redis 等基础组件的运行见"运行环境需求"。

**使用角色**：数据采集调度（按任务自动采集与调度）、采集策略配置人员（配置采集方式与范围）、系统运维人员（配置代理资源）。

**前置条件**：目标平台采集手段（逆向、模拟点击、官方 API、网页解析）已就绪；代理 IP 与维护账号可用；爬虫集群与 Kafka、Redis 等基础组件已按运行环境需求部署可用。

**输入**：目标平台标识与采集任务（采集对象、范围、频率、使用的采集方式）、代理 IP 与 VPS 代理链路配置、平台与地区代理分配策略、采集配额参数。

**输出**：采集到的原始社交数据（用户信息、内容、互动数据、关系数据等）、调度指令与去重结果、可用代理 IP 列表与轮换日志。

**业务规则**：

- 对 Instagram 采用逆向方式采集推荐、人物、Reels 等界面数据；
- 对 TikTok、Facebook 采用逆向方式采集；
- 对 x 采用逆向方式采集；
- 采集过程中使用代理 IP 与维护账号，以应对平台访问限制；
- 代理 IP 池对接 VPS 代理链路，按平台与地区分配代理并定时轮换，对代理进行可用性检测与失效剔除；
- 任务调度与去重：维护采集任务池，基于 Redis 实现 URL 与任务去重、调度队列与分布式锁，并对采集范围、频率、并发设配额上限，超限自动限流，支撑 FR-DC-005 情报回注入池去重与配额约束、II-16 情报回注采集接口；
- 采集策略自优化：基于历史采集指标（封禁率、采集成功率、反爬升级信号、各采集手段的有效率）对采集策略进行主动调整，包括采集手段优先级排序、请求频率与并发调节、代理与账号选择策略优化，使采集策略随平台反爬强度变化自适应演进，而非仅被动应对单次异常。

**异常场景**：逆向接口失效或改版时告警并切换备用采集方式；API 限流时按限额退避重试；账号被封时自动切换备用账号；代理全部失效时告警并暂停受影响的采集任务；代理检测超时时剔除该代理并补充新代理；策略自优化指标不足或波动过大时维持上一稳定策略并告警，避免策略频繁抖动。

**验收标准**：各平台可通过对应采集手段获取数据；采集过程可使用代理与账号应对访问限制；代理按策略分配、定时轮换并自动剔除失效节点；任务调度与去重功能生效且配额限流可对采集范围、频率、并发设上限；采集异常可告警并切换备选手段；采集策略可基于历史采集指标进行主动调整，策略调整可在指标不足或波动过大时维持稳定并告警。

##### 数据处理与存储（FR-DC-003）

**功能目的**：对采集到的原始数据进行清洗加工并持久化存储，提供标准的大数据 ETL 链路，完成数据的抽取、转换与加载。

**使用角色**：系统（自动执行 ETL 流程）、数据分析人员（消费加工后的数据）。

**前置条件**：Spark 或 MapReduce 计算集群可用；HBase、关系型数据库与图数据库可写入。

**输入**：采集到的原始数据。

**输出**：清洗加工后的结构化数据，持久化于 HBase 与关系库中，可供分析与检索使用。

**业务规则**：

- 基于 Spark 或 MapReduce 进行分布式批处理计算，完成数据清洗、字段提取、格式标准化、去重与关联；
- 处理结果写入 HBase 列式数据库，元数据与索引写入关系型数据库，关系数据写入图数据库。

**异常场景**：计算节点失败时任务自动重试或转移；写入 HBase 或关系库失败时数据进入重试队列；数据格式异常时隔离坏数据并记录。

**验收标准**：原始数据可经分布式计算完成清洗与标准化；结果可正确写入 HBase、关系库与图数据库；处理过程对节点失败具备重试能力。

##### 数据分析与情报（FR-DC-004）

**功能目的**：对加工后的数据进行分析，提供从群体到个体的筛选、关系图谱、情报检索、可视化与文本智能分析能力，支撑目标识别与内容研判。

**使用角色**：情报分析人员（检索、筛选与研判）、系统（自动执行分析与建模）。

**前置条件**：加工后的数据已就绪；AI 算法、文本模型与关键词库已配置；图数据库可用。

**输入**：加工后的数据、群体特征条件、实体标识、检索条件、待分析的文本内容与关键词库。

**输出**：目标个体集合、关系图谱、实体信息列表、关联拓扑与情报信息、实体档案视图、文本分类与筛选结果、可视化展示界面。

**业务规则**：

- 结合人工智能算法实现从群体到个体的逐层下钻筛选，从大范围群体中定位目标个体；
- 基于实体与关联数据绘制关系图谱并支持图查询；
- 提供基础信息检索，按账号、昵称、标识等检索实体信息；
- 对给定实体输出关联拓扑与情报标签，形成关联网络；
- 聚合多来源信息形成实体的全维度档案；
- 对文本内容结合文本模型与关键词库进行规则匹配与分类筛选，用于内容研判与目标识别。

**异常场景**：算法推理超时或失败时降级返回部分结果并告警；图谱查询数据量过大时分页或限流；文本模型不可用时回退到关键词规则匹配。

##### 情报驱动采集与目标扩散（FR-DC-005）

**功能目的**：打通"分析→采集"反向驱动链路，使数据分析与情报（FR-DC-004）产出的目标个体、关联实体与传播节点能够自动或经人工确认后回注采集任务池，并支持以已采集目标为起点按关系（关注/粉丝/互动/转发链/评论链）逐层扩散采集，形成"发现线索→定向扩散采集→锁定目标"的情报驱动闭环。本能力区分两类扩散：DC 侧的"目标扩散采集"（图扩展式爬取，本期实现）与 OCC 侧的"扩散趋势预判"（传播预测分析，见附录"本期暂不实现的 OCC 能力"，本期不做）。

**使用角色**：情报分析人员（确认回注与扩散策略）、系统（自动回注与扩散调度）。

**前置条件**：FR-DC-002 任务池与调度可用；FR-DC-004 分析结果可读；FR-DC-003 关系数据已入图数据库。

**输入**：分析产出的目标个体集合与关联实体（来自 FR-DC-004）、回注规则（自动/人工确认、优先级、扩散层数与关系类型）、扩散起点目标与扩散参数（关系类型、层数、去重范围）。

**输出**：回注生成的采集任务（写入 task_pool，携带 source_type=intel_feedback）、扩散采集的新目标与关系数据（回流至 FR-DC-003 存储）、回注与扩散的审计记录。

**业务规则**：

- 情报回注：FR-DC-004 分析产出的高价值目标个体、关联实体、传播节点，可按回注规则自动生成定向采集任务（account/keyword/url_list 类型）回注任务池，回注任务携带 source_type=intel_feedback 与来源情报标识，满足情报可审计性；
- 回注去重：回注任务须经过 FR-DC-002 的入池目标级去重，避免对已采集目标重复下发；命中已采集目标时可触发复查类任务（recheck）而非新增采集；
- 人工确认闸门：对高扩散层数、大规模批量或敏感目标的回注与扩散，须经情报分析人员确认后方可入池，防止采集范围失控与资源浪费；
- 目标扩散采集：以已采集目标为起点，按指定关系类型（关注/粉丝/互动/转发链/评论链）与扩散层数进行图扩展式采集，每层发现的新节点经去重后生成新采集任务，形成广度优先的目标网络扩展；
- 扩散闭环：扩散采集的新目标经 FR-DC-003 加工与 FR-DC-004 分析后，可再次触发回注与进一步扩散，直至达到扩散层数上限、去重命中率阈值或人工停止，形成可控的迭代扩散；
- 范围与配额控制：扩散任务受 FR-DC-002 配额限流约束，扩散层数、单层节点数、总目标数设上限，超出上限自动停止并告警；
- 本能力与 OCC"扩散趋势预判"区分：本能力是 DC 侧的图扩展采集（把目标网络的边采全），OCC 扩散趋势预判是传播预测分析（预判传播会怎么扩散），后者本期不做（见附录）。

**异常场景**：扩散层数超限或目标数超阈值时自动停止并告警；回注任务入池去重后无新增目标时记录并跳过；扩散关系数据缺失或不完整时降级为已采集层的部分结果；人工确认超时未响应时按默认策略（不入池）处理并记录。

**验收标准**：FR-DC-004 分析产出的目标可回注生成采集任务并写入任务池；回注任务经目标级去重后不重复采集已采集目标；高扩散/批量/敏感回注经人工确认闸门；以目标为起点可按关系类型与层数扩散采集新目标；扩散采集受配额与层数上限约束；扩散新目标可回流存储并再次触发回注，形成迭代扩散闭环。

#### 多设备矩阵自动化群控子系统（MC）

本子系统定位为"统一自动化执行引擎与多终端执行网关"，是所有执行终端动作的唯一收口，并承担账号资源管理与智能体执行宿主两项职责。子系统核心职责为：统一管理四类执行终端——移动端（真机、云手机、ARM 板卡、虚拟化真机）与桌面端（反指纹浏览器 Profile）的接入、远程控制、指纹与代理隔离；承担账号资源（注册、凭据、验证、风险评估、生命周期、账号分类）的统一维护与共享分发；作为智能体的执行宿主，持存蜂群智能体子系统同步来的智能体定义并在任务执行时调用；提供脚本模式与智能体模式两种执行引擎；以统一执行网关的形式收口所有落到任何执行终端的动作，保证每一个动作可观测、可审计、可熔断。

本子系统是账号资源的平台级权威源（V2.0 由共享资源管理子系统 SR 承担，已并入），负责注册、验证、养护策略与生命周期等主数据的维护，并经事件总线向数据爬取（DC）、蜂群智能体（SWM）、舆情作战（OCC）等使用方共享分发账号标识（account_id）。账号按终端类型遵循差异化的绑定规则：真机、云手机、虚拟化真机出于风控要求执行"一设备一账号"，反指纹浏览器 Profile 执行"一 Profile 一账号"（浏览器实例可多开）。内容资源由舆情作战业务子系统（OCC）统一管理（见 FR-OCC-005），本子系统仅作为内容使用方引用内容标识（content_id）进行内容投放。

子系统遵循两条基本原则。其一，动作收口原则：无论动作来自脚本引擎还是智能体引擎，所有执行终端动作（点击、输入、滑动、安装、发布、养号动作等）均经执行网关落地，执行网关负责鉴权、记录、熔断与转发，动作日志全量上报运维监控子系统。其二，推理与执行分离原则：智能体模式下的视觉推理由智能体调用底层私有化大模型部署（IRS）的本地大模型完成，不经执行网关；推理产出的动作指令再经执行网关落地，从而兼顾推理的低延迟与执行的可观测。

##### 执行终端管理（FR-MC-001）

**功能目的**：统一管理四类执行终端（移动端：真机、云手机、ARM 板卡、虚拟化真机；桌面端：反指纹浏览器 Profile）的接入、创建、分组、状态监控、风控分级与基础操作，为远控、群控与任务执行提供终端资源池。按终端硬件/环境指纹真实度为养号等高敏感场景提供终端选型依据。本功能融合 V2.0 的 FR-MC-001（移动端设备管理）与 FR-FB-001（桌面端 Profile 管理）。

**使用角色**：设备运维人员（注册与维护执行终端）、任务调度（按分级选终端）、运营人员（批量操作）。

**前置条件**：移动端可安装 Agent 或可被接入；反指纹浏览器内核（基于开源 BotBrowser 定制）已部署且支持 CDP 接入与 Profile 级指纹配置；对象存储可用；风控分级规则已配置。

**输入**：移动端执行终端标识与 Agent 信息、浏览器 Profile 创建请求（指纹模板、代理、分组、标签）、指纹配置、Profile 标识与 CDP 信息、分组与标签规则、终端指标心跳、终端风控分级规则、针对终端集合的批量操作指令。

**输出**：执行终端台账（含移动端与桌面端 Profile）、终端分组关系、终端实时状态视图、终端风控分级标签、批量操作执行结果。

**业务规则**：

- 移动端 Agent 启动后向服务端注册并建立长连接，系统记录设备类型（真机/云手机/ARM 板卡/虚拟化真机，区分虚拟与实体）、版本、型号、分组与标签；
- 浏览器 Profile 创建时生成一套渲染层指纹（Canvas、WebGL、字体、时区、Audio、UA 等 20+ 维度）并固定不变，使该 Profile 长期呈现一致的设备身份，更像真人，降低被风控识别为异常的概率（指纹固化）；一个 Profile 对应一套固化指纹与一个账号身份；Profile 创建后经 CDP 向服务端注册，系统记录 Profile 标识、指纹配置、Chromium 内核版本、分组与标签；
- 系统持续采集并监控移动端设备的在线与离线状态、电量、CPU、内存、存储与网络状态，以及浏览器 Profile 的运行状态与资源占用；
- 系统按指纹真实度对执行终端风控分级：真机与 ARM 板卡为高真实度等级，虚拟化真机为中高等级，云手机为中等级，浏览器 Profile 为中等级；养号等风控敏感场景优先选用高真实度等级终端；
- 系统支持对执行终端集合批量操作：移动端支持批量安装与卸载 App、批量重启、批量截图；浏览器 Profile 支持批量创建、启动、关闭、批量截图；均可通过对象存储临时链接进行文件上传与下载；
- Profile 间的 Cookie、LocalStorage、缓存相互独立隔离，避免账号关联。

**异常场景**：移动端 Agent 掉线或浏览器 Profile 掉线时标记离线并告警；Profile 启动失败时记录错误码并重试；指纹校验失败时拒绝启动并提示重新生成；终端指标异常（过热、存储满、内存超限）时隔离并停止派发任务；批量操作部分失败时记录失败项并支持重试。

**验收标准**：移动端设备与浏览器 Profile 均可注册接入（含指纹固化与 CDP 注册）；执行终端状态与指标可实时监控；风控分级可按规则打标且养号优先选用高真实度终端；移动端与桌面端的批量操作均可执行并返回结果；Profile 间 Cookie/缓存可相互隔离。

##### 远程控制（FR-MC-002）

**功能目的**：对单台及多台执行终端提供低延迟的实时画面预览与输入控制，并支持多终端同屏监控，用于人工介入与终端操作。移动端（真机/云手机/ARM 板卡/虚拟化真机）采用 WebRTC 通道，桌面端浏览器 Profile 与虚拟化真机的桌面形态采用 RDP 通道。

**使用角色**：运营人员（远程操作终端）、监控人员（宫格监控）。

**前置条件**：目标终端在线且 Agent 正常（移动端）或 Profile 已启动（桌面端）；WebRTC SFU 与 RDP 网关可用；远控权限已授权。

**输入**：远控请求、目标终端标识、操作人员的鼠标与键盘输入事件。

**输出**：终端实时画面流、被翻译并执行的终端事件、截图与录屏文件、多终端宫格预览画面。

**业务规则**：

- 移动端屏幕画面基于 WebRTC 传输，桌面端浏览器 Profile 与虚拟化真机桌面形态基于 RDP 传输；远程控制通道与任务执行通道相互分离以保证稳定性；
- 操作人员的鼠标与键盘事件映射为终端的触摸、点击、滑动、输入及返回键、Home 键、多任务键事件（移动端），或映射为桌面端的鼠标点击、键盘输入事件（桌面端）；
- 系统支持由 Agent 采集的截图与录屏，并支持保存与回看；
- 多终端宫格监控以低码率同屏预览多台终端；
- 剪贴板在操作端与终端间双向同步。

**异常场景**：WebRTC/RDP 断流时自动重连或降级；输入事件丢失时补传；弱网下自动降帧以保证可用性。

**验收标准**：单终端远控端到端延迟不大于 300 毫秒；鼠标键盘事件可正确映射为终端事件；截图录屏可采集保存；多终端宫格可同屏预览；剪贴板可双向同步。

##### 执行网关与双执行模式（FR-MC-003）

**功能目的**：以统一执行网关作为所有执行终端动作的唯一收口，提供脚本模式与智能体模式两种执行引擎，分别承载固定流程驱动与大模型实时决策驱动的作业，覆盖移动端终端与桌面端浏览器 Profile，并支持群控、养号（认知作战账号与爬虫账号）与内容投放三类执行目标。本功能融合 V2.0 的 FR-MC-003（移动端执行网关）与 FR-FB-002（桌面端执行网关），原移动端网关与桌面端网关合并为统一执行网关，按终端类型适配各自控制通道。

**使用角色**：任务调度（下发作业指令）、智能体引擎（自主决策动作）、脚本引擎（按流程执行动作）。

**前置条件**：执行网关服务可用；智能体模式下 IRS 本地大模型可用；目标执行终端与账号已绑定；控制通道（移动端 ADB/无障碍、桌面端 CDP）已就绪。

**输入**：作业指令（来自脚本模式或智能体模式）、目标执行终端组（移动端或桌面端 Profile）、内容素材、目标账号与终端。

**输出**：脚本模式执行结果、智能体模式执行结果、养号执行记录、内容投放执行记录、执行网关的动作日志与熔断记录。

**业务规则**：

- 脚本模式由预先编写的固定流程驱动终端动作，适用于流程确定、高频、批量的作业；智能体模式由终端 Agent 调用 IRS 本地大模型进行视觉推理与规划，自主决策下一步动作，适用于流程复杂、需理解界面、抗界面变化的作业；
- 两种模式按执行终端类型适配底层控制通道：移动端终端（真机/云手机/ARM 板卡/虚拟化真机）采用 ADB、无障碍服务等通道，桌面端浏览器 Profile 采用 CDP（Chrome DevTools Protocol）通道；控制通道对上层透明；
- 所有执行终端动作（移动端与桌面端）均经统一执行网关落地：执行网关对动作鉴权，校验动作来源与目标终端的合法性；对动作记录，写入动作日志并全量上报运维监控子系统；对异常动作熔断，在检测到风控信号或异常频率时停止后续动作；
- 智能体模式下的视觉推理由 Agent 调用 IRS 本地大模型完成，不经执行网关；推理产出的动作指令再经执行网关落地；
- 群控对多台终端同步控制并统一投放内容；养号按拟人化节奏模拟真人行为——认知作战账号在移动端设备上养号（经 ADB/无障碍通道），爬虫账号在浏览器 Profile 上养护（经 CDP 通道），拟人化策略均由蜂群智能体子系统提供；账号主数据由本子系统（FR-MC-010）维护，动作收口于执行网关；内容投放下发并发布内容素材到目标账号。

**异常场景**：执行网关过载时按优先级限流；智能体推理失败时降级为脚本模式或人工介入；动作触发风控信号时熔断并告警；终端掉线或浏览器 Profile 的 CDP 连接断开时挂起任务待恢复续接。

**验收标准**：脚本模式与智能体模式均可驱动移动端设备与桌面端浏览器 Profile 动作；所有动作经统一执行网关鉴权、记录、转发；执行网关可对异常动作熔断；智能体推理调用 IRS 本地大模型且不经执行网关；移动端与桌面端控制通道均可适配；三类执行目标（群控、养号、投放）均可闭环。

##### 账号养号与登录管理（FR-MC-004）

**功能目的**：负责两类账号的养号动作执行与登录管理——认知作战账号在移动端设备上的养号、爬虫账号在浏览器 Profile 上的养护，以及账号与终端的绑定、登录状态及操作记录维护。账号主数据（注册、凭据、验证、风险评估、生命周期）由本子系统的账号资源管理（FR-MC-010）统一维护。

**使用角色**：账号运营人员（绑定账号与终端）、系统（自动执行养号动作、维护登录状态、响应状态变更）、审计人员（查阅记录）。

**前置条件**：账号已在本子系统（FR-MC-010）注册并取得 account_id；目标执行终端（移动端设备或浏览器 Profile）已注册；养号策略由蜂群智能体子系统提供；执行网关可用。

**输入**：账号标识、终端标识、养号任务（发帖、关注、浏览）、账号登录事件、账号操作（发帖、关注、浏览等）、账号状态变更。

**输出**：账号与终端的绑定关系、登录状态记录、养号执行记录、账号操作记录。

**业务规则**：

- 账号-终端绑定规则：真机、云手机、虚拟化真机出于风控要求执行"一设备一账号"（一个终端仅可绑定一个账号，已绑定账号未解绑前不可再绑定其他账号）；反指纹浏览器 Profile 执行"一 Profile 一账号"（浏览器实例可多开，每个 Profile 绑定一个账号身份）；
- 系统将认知作战账号绑定到具体移动端设备、将爬虫账号绑定到浏览器 Profile，并记录绑定关系；
- 系统记录账号在终端上的登录状态及其变化；
- 养号动作（发帖、关注、浏览等拟人化行为）由本子系统的执行网关落地执行——认知作战账号经 ADB/无障碍通道在移动端执行、爬虫账号经 CDP 通道在浏览器 Profile 执行，拟人化策略由蜂群智能体子系统提供；
- 系统记录账号在终端上的各项操作，供审计与风控分析使用；
- 账号状态变更（封禁、受限等，由 FR-MC-010 判定）时停止该账号的养号任务并解绑。

**异常场景**：账号被封禁或受限时停止该账号相关任务并解绑；养号行为触发平台验证时暂停并告警；账号登录失败时记录原因并标记；账号在终端上被封时解绑并告警；操作记录写入失败时暂存重试。

**验收标准**：认知作战账号可绑定到移动端设备、爬虫账号可绑定到浏览器 Profile 并查询绑定关系；账号-终端绑定规则（一设备一账号 / 一 Profile 一账号）可正确执行；养号动作可经执行网关按拟人化策略在移动端与桌面端执行；登录状态变化可记录；账号操作可留痕供审计；账号状态变更后可联动停止被封账号任务。

##### 任务管理（FR-MC-006）

**功能目的**：把操作意图转换为设备可执行的任务并进行调度，支撑各类作业的排队、分发、重试与定时执行。

**使用角色**：运营人员（创建任务）、任务调度（自动分发）、系统（状态流转）。

**前置条件**：消息队列可用；目标设备或设备组已就绪。

**输入**：任务定义（任务类型、目标设备或设备组、参数、优先级）、计划任务的 Cron 表达式、任务状态变更事件。

**输出**：任务实例、任务调度分发结果、任务执行结果、任务最新状态。

**业务规则**：

- 系统按任务定义选择设备或设备组，生成任务实例并入消息队列，由调度器分发到设备 Agent 执行；
- 支持的任务类型包括 App 安装与启动、文件分发、内容发布、截图、数据采集、自动化脚本、设备巡检与账号状态检查；
- 任务在待执行、排队中、执行中、成功、失败、已取消、超时、部分成功等状态间流转；
- 系统支持失败重试、重试次数与超时配置；
- 计划任务支持一次性、每日、每周与自定义 Cron，并支持最大并发数与任务优先级控制。

**异常场景**：任务执行失败时按配置重试；任务超时时标记超时并告警；队列积压时按优先级调度并告警。

**验收标准**：任务可创建并生成实例入队分发；八种任务状态可正确流转；失败可重试且超时可配置；计划任务可按 Cron 定时触发并支持并发与优先级。

##### 执行引擎·脚本模式（FR-MC-007）

**功能目的**：提供脚本模式下的执行引擎，覆盖从模板任务到可视化工作流再到脚本开发的递进式自动化能力，支持 ADB 脚本、RDP、CDP 等多种自动化通道（移动端动作经 ADB/无障碍、桌面端浏览器 Profile 与虚拟化真机桌面形态经 RDP/CDP），产出的动作指令经执行网关落地。养号等风控敏感场景可优先采用脚本模式。

**使用角色**：脚本开发者（编写与调试脚本）、运营人员（选用模板或工作流）、系统（执行脚本）。

**前置条件**：执行网关可用；调试设备已接入；脚本沙箱已配置。

**输入**：模板任务选择、工作流流程定义、脚本代码与调试设备、平台界面与操作序列。

**输出**：模板任务执行结果、工作流执行编排结果、脚本调试结果、模拟点击自动化执行结果。

**业务规则**：

- 第一阶段提供模板化任务，包括打开 App、等待页面、点击、输入文本、上传文件、截图、返回、滑动、关闭 App、设备巡检与 App 状态检测；
- 第二阶段提供可视化工作流编排，节点包括开始、设备选择、启动 App、等待、点击、输入、滑动、截图、文件上传、条件判断、循环、HTTP 请求、日志、审批与结束；
- 第三阶段支持脚本开发与调试，提供脚本编辑、调试设备、执行日志、截图回放与版本管理；
- 系统针对 TikTok、Facebook 等平台实现模拟点击自动化；
- 脚本引擎产出的动作指令均经执行网关鉴权、记录与转发，不直接操作设备。

**异常场景**：脚本执行异常时捕获错误并记录；脚本越权访问敏感路径时沙箱拦截；调试设备掉线时暂停调试。

**验收标准**：三阶段能力（模板、工作流、脚本开发）均可用；脚本动作均经执行网关落地且不直接操作设备；模拟点击可在目标平台执行。

##### 可观测性与作业统计复盘（FR-MC-008）

**功能目的**：满足集群控制对可观测性的硬性要求，使终端、账号、任务的每一个动作都可知、可追溯，支撑记录、回传、告警、审计，并在此基础上完成蜂群作业的数据统计与任务复盘、将投送效果联动回传上游供效果评估闭环使用。本功能融合 V2.0 的 FR-MC-008（可观测性）与原蜂群智能体子系统的 FR-SWM-004（蜂群作业统计与复盘）——动作留痕与作业统计复盘统一收口于本功能，避免原始动作数据在两个子系统间重复采集。

**使用角色**：运维与审计人员（查阅日志与审计）、作战指挥与运营人员（查阅作业统计与复盘）、系统（自动记录、统计与回传）。

**前置条件**：日志采集与上报通道可用；告警通道已配置；效果回调接口已对接上游（OCC）。

**输入**：终端动作事件、任务执行过程、异常事件、用户与系统的操作、投放内容表现数据。

**输出**：动作日志、任务执行日志与截图、异常告警通知、可追溯的审计记录、蜂群作业统计报表、任务复盘结果、回传上游的效果回调数据。

**业务规则**：

- 每一个终端动作（点击、输入、安装、发布等）均留痕，记录时间、终端、账号与结果；
- Agent 回传任务执行日志与关键步骤截图；
- 任务失败、终端掉线、账号异常等异常事件触发告警通知；
- 系统对用户与系统操作记录审计日志，记录谁在何时对哪台终端或账号做了什么；
- 作业统计复盘基于本功能采集上报的动作日志与任务日志进行，不重复采集原始动作数据——动作留痕与作业统计同源于本功能；
- 系统对蜂群作业进行多维统计，包括任务完成率、内容触达、互动表现、账号健康度等；
- 系统支持任务复盘，对失败任务、异常账号、低效作业进行归因分析；
- 系统将投送效果数据通过回调机制联动回传至舆情作战子系统（OCC），供效果评估闭环使用。

**异常场景**：日志上报失败时本地暂存待重试；告警通道失效时降级为本地记录；审计日志写入失败时阻塞相关操作以保证不丢审计；数据源缺失时标注统计不完整；复盘归因无解时标记待人工分析；回调上游失败时暂存重试。

**验收标准**：每个终端动作可留痕并记录时间、终端、账号、结果；任务日志与截图可回传；异常可触发告警；用户与系统操作可审计追溯；蜂群作业可基于本功能数据进行多维统计；失败任务可归因复盘；效果数据可回调回传上游形成闭环。

##### 执行终端环境与风控对抗（FR-MC-009）

**功能目的**：管理执行终端（移动端与桌面端浏览器 Profile）的环境并应对平台风控，通过终端指纹管理、风控识别、代理分配与环境隔离，降低账号与终端被处置的风险。本功能融合 V2.0 的 FR-MC-009（移动端风控对抗）与 FR-FB-001 中桌面端 Profile 指纹固化与环境隔离的职责。

**使用角色**：设备运维人员（配置指纹与代理）、系统（识别风控并隔离环境）。

**前置条件**：终端指纹与代理资源可用；风控信号识别规则已配置。

**输入**：终端环境参数（含浏览器 Profile 指纹模板）、风控信号、代理分配策略、执行终端集合的隔离要求。

**输出**：终端的指纹配置、风控规避策略、代理绑定关系、终端环境隔离配置。

**业务规则**：

- 移动端指纹管理：系统管理真机、云手机、ARM 板卡、虚拟化真机等移动端设备的硬件与软件指纹，支持按需配置；
- 桌面端指纹管理：系统管理浏览器 Profile 的渲染层指纹（Canvas、WebGL、字体、时区、Audio、UA 等 20+ 维度），Profile 创建时生成并固化指纹；
- 系统识别平台风控信号并采取规避与应对策略，覆盖移动端与桌面端；
- 系统为每个执行终端（移动端设备与浏览器 Profile）分配独立代理 IP 以实现网络环境隔离；
- 系统对终端间的环境（指纹、网络、账号、Cookie/缓存）进行相互隔离，避免关联。

**异常场景**：终端指纹配置冲突时告警并提示；风控信号持续触发时降级或暂停该终端任务；代理失效时切换备用代理。

**验收标准**：移动端设备指纹与桌面端浏览器 Profile 指纹均可按需配置（含固化）；风控信号可识别并触发规避策略；各执行终端可绑定独立代理；终端间环境可相互隔离。

##### 账号资源管理（FR-MC-010）

**功能目的**：作为账号资源的平台级权威源，唯一维护社交媒体账号的主数据（注册、凭据、验证、风险评估、生命周期、账号分类），并经事件总线向数据爬取（DC）、蜂群智能体（SWM）、舆情作战（OCC）等使用方共享分发账号标识（account_id）。同时承担智能体账号的分层分组与作业生命周期管理，以及账号与智能体定义（agent_id）的绑定关系维护，使账号主数据、账号的业务组织（分层分组、作业状态）与智能体绑定统一管理。账号按用途分为两类：爬虫账号以桌面端反指纹浏览器 Profile 为执行终端，认知作战账号以移动端设备为执行终端。

**使用角色**：账号运营人员（注册与维护账号、配置分层分组、发起封号资产迁移）、各使用子系统（经账号服务接口引用账号）、系统（自动验证、状态流转、事件广播、维护绑定关系）。

**前置条件**：账号凭据加密存储机制可用；邮箱、手机接码、虚拟号等注册渠道已对接；账号状态规则与事件总线已配置；账号服务接口已就绪；分层分组规则已配置；智能体定义同步接口（II-15）可用。

**输入**：待提交的账号注册信息（平台、账号名、凭据、标签、归属、账号分类）、平台注册方式（邮箱、手机接码、虚拟号）、验证探测请求与回传结果、账号状态变更请求、分层与层级结构定义、agent_id 绑定关系（来自 SWM 同步）、封号资产迁移请求（源 agent_id、目标账号）、各使用方的账号引用请求。

**输出**：账号主数据记录、注册成功的账号标识（account_id）、账号可用性与风险评估结果、账号最新生命周期状态、智能体账号的层级分组结构、agent_id↔account_id 绑定关系记录、账号服务接口（查询/变更）、account.status.changed 事件、资产迁移执行结果。

**业务规则**：

- 账号主数据（凭据、平台、全局状态、生命周期、风险评估、账号分类，凭据须加密存储）由本子系统唯一维护，其它子系统（DC/SWM/OCC）不复制主数据，仅引用 account_id；
- 账号注册由本子系统承担入口与主数据落地，支持邮箱注册、手机号接码注册与虚拟号注册流程；注册/验证落到执行终端的动作（填写注册信息、接收输入验证码、完成登录探测）由本子系统的统一执行网关执行（爬虫账号在浏览器 Profile 经 CDP 执行、认知作战账号在移动端经 ADB/无障碍执行）并回传结果，本子系统据此判定账号状态与风险等级；
- 账号验证通过登录探测与状态识别，检测可用性并识别封禁、限制、需验证等风险点，输出风险等级；
- 账号生命周期在待登录、正常、受限、需验证、封禁、归档等状态间流转，由本子系统判定与维护；
- 账号分类：爬虫账号以桌面端反指纹浏览器 Profile 为执行终端，养护（养号）动作执行由统一执行网关经 CDP 通道承担；认知作战账号以移动端设备为执行终端，养号动作执行由统一执行网关经 ADB/无障碍通道承担、策略由 SWM 提供；两类账号的注册、验证与生命周期主数据均由本子系统维护；
- 智能体账号分层分组：系统对智能体账号按业务目标、平台、地区、风险等级等维度分层分组，形成可控的账号层级结构；
- 智能体账号作业生命周期：系统管理智能体账号的作业生命周期（待激活、活跃、休眠、受限、封禁、回收），支持状态间的自动与人工流转；
- 账号标识 account_id 为全局唯一引用，贯穿 DC（采集）、MC（养号执行、分层分组）、SWM（人设）、OCC（目标），使用方只维护各自的扩展属性并引用 account_id（如 DC 的采集关联、SWM 的人设标签、OCC 的目标标注）；
- 账号状态变更（封禁、受限等）经事件总线广播 account.status.changed 事件，使用方订阅后立即响应（停止任务、停止养号、休眠智能体、移除目标），保证被封账号全网即时失效；
- 智能体-账号绑定：账号与智能体定义（agent_id）严格 1:1 绑定，由本子系统记录并维护 agent_id ↔ account_id 绑定关系；叠加账号-终端绑定规则（FR-MC-004），移动端形成 agent_id:account_id:终端 = 1:1:1 的作战单元，Profile 端每个 Profile 内部同样 1:1:1；agent_id 由 SWM 分配并以 II-15 接口同步至本子系统持存；
- 封号资产迁移：账号被封禁后，运营人员可对该账号绑定的智能体发起资产迁移——将原 agent_id 的人设标签、提示词版本与记忆整体继承到一个新注册且未绑定 agent_id 的目标账号，旧 agent_id↔旧账号解绑并休眠、新绑定激活；目标账号须满足账号-终端绑定规则（移动端须有可用终端或后续绑定）。迁移由人工触发、内容整体继承，保证人格连贯性、避免误迁。

**异常场景**：账号被封禁或受限时自动标记状态并停止该账号相关任务；验证探测失败时记录异常并重试；注册流程接码或验证失败时回滚并记录；账号服务接口不可用时使用方降级为本地缓存只读并告警；事件广播失败时重试；分组调整失败时回滚；agent_id 绑定冲突（如目标账号已绑定其他 agent_id）时拒绝迁移并提示；资产迁移目标账号不满足绑定规则时拒绝并提示；多使用方并发变更扩展属性时按账号标识加锁。

**验收标准**：账号主数据由本子系统唯一维护且使用方不复制；account_id 全局唯一可被各子系统引用；账号注册流程可走通且凭据加密存储不落明文；账号可用性与风险等级可自动识别；账号状态可按生命周期规则流转并经事件全网即时生效；爬虫账号与认知作战账号两类分类可分别归口到桌面端与移动端执行终端；智能体账号可按多维度分层分组且作业生命周期状态可自动与人工流转；agent_id↔account_id 1:1 绑定关系可记录与查询；封号资产可经人工触发整体迁移到新账号并延续人格。

##### 智能体执行宿主与同步（FR-MC-011）

**功能目的**：作为智能体的执行宿主，接收并持存蜂群智能体子系统（SWM）同步来的智能体定义（以 agent_id 为标识，含人设标签、提示词、记忆、作业策略），在任务执行时调用这些定义驱动设备作业，并在执行前校验人设一致性。本功能确立"SWM 为智能体定义与记忆中心、MC 为智能体执行宿主"的分工：SWM 负责根据人设（画像、账号属性）编写提示词与记忆并以 agent_id 同步下发，MC 负责以 agent_id 持存、绑定账号、校验一致与执行调用。

**使用角色**：系统（接收同步、持存、校验、调用）。

**前置条件**：SWM 智能体定义同步接口（II-15）可用；执行网关可用；智能体已通过 FR-MC-010 与账号建立 agent_id↔account_id 1:1 绑定。

**输入**：来自 SWM 的智能体定义（agent_id、人设标签、提示词、记忆、作业策略）、任务执行请求（含目标 agent_id 与 account_id）。

**输出**：持存的智能体定义（按 agent_id 索引）、三元绑定关系（agent_id↔account_id↔终端）、智能体执行调用结果、人设一致性校验结果、执行网关的动作日志。

**业务规则**：

- 本子系统以 agent_id 为主键接收 SWM 同步的智能体定义并持存，作为任务执行时调用智能体的依据；
- 三元绑定记录：本子系统记录并维护 agent_id↔account_id↔终端 的三元绑定关系（与 FR-MC-010 的 agent_id↔account_id 绑定、FR-MC-004 的账号-终端绑定联动），形成 1:1:1 作战单元；
- 人设一致性校验：智能体模式下任务执行前，本子系统校验"当前 account_id 绑定的人设标签"与"agent_id 智能体定义中的人设标签"是否一致，一致方可调用 IRS 推理并经执行网关落地动作，不一致则拒绝执行并告警；一致性收口于执行宿主，作为最后一道闸；
- 任务执行时本子系统按智能体定义中的提示词、记忆与作业策略，调用 IRS 本地大模型进行视觉推理与规划，产出的动作指令再经执行网关落地；
- 智能体定义更新时（SWM 以同一 agent_id 重新同步）本子系统更新持存版本，保证执行使用最新定义；
- 本子系统可作为 OCC 作战编排的执行节点来源——编排中的智能体节点即以 agent_id 引用本子系统持存的智能体。

**异常场景**：SWM 同步失败时保留上一可用定义并告警；智能体定义缺失时降级为脚本模式或人工介入；推理调用 IRS 失败时降级处理；人设一致性校验不通过时拒绝执行并告警；三元绑定关系缺失或冲突（如 agent_id 未绑定 account_id）时挂起任务并提示。

**验收标准**：可以 agent_id 接收并持存 SWM 同步的智能体定义；三元绑定关系（agent_id↔account_id↔终端）可记录与查询；任务执行前可校验人设一致性且不一致时拒绝执行；任务执行时可按定义调用并经执行网关落地动作；智能体定义更新后可使用最新版本执行；可作为 OCC 作战编排的智能体节点来源（以 agent_id 引用）。

#### 蜂群智能体子系统（SWM）

蜂群智能体子系统是执行层的"智能体定义与记忆中心"，核心职责是根据人设（画像、账号属性）编写驱动智能体作业的提示词与记忆，并将智能体定义（人设标签、提示词、记忆、作业策略）同步下发至群控子系统（MC）持存，由 MC 在任务执行时调用。子系统实现蜂群任务智能分发、行为仿真与防伪装，以及提示词与人设管理和记忆管理。账号主数据、智能体账号的分层分组与作业生命周期由 MC 的 FR-MC-010 统一维护（人设标签由本子系统的 FR-SWM-005 维护）；作业效果统计与复盘由 MC 的可观测性能力（FR-MC-008）承担。SWM 与 MC 的分工为：SWM 为智能体定义与记忆中心（编写与同步），MC 为智能体执行宿主（持存与调用，见 FR-MC-011）。

本子系统不直接操作设备，所有动作均收口于群控子系统的统一执行网关（认知作战账号养号动作经移动端 ADB/无障碍通道、爬虫账号养护动作经桌面端 CDP 通道，均由 MC 统一执行网关收口）。子系统的产出按执行模式有所不同：在智能体模式下，本子系统将智能体定义同步至 MC，MC 据此在任务执行时调用（视觉推理调用底层 IRS 本地大模型），产出的动作指令再经执行网关落地；在脚本模式下，本子系统向 MC 的脚本引擎下发作业参数（账号、时间、内容），脚本照固定流程执行，动作同样经执行网关落地。养号的拟人化节奏与防伪装策略由本子系统提供，具体动作执行由群控子系统的统一执行网关承担。本子系统也是 OCC 作战编排中智能体节点的供给方之一——OCC 编排 MC 中的智能体节点时，其智能体定义来源于本子系统同步至 MC 的内容。

##### 蜂群任务智能分发（FR-SWM-002）

**功能目的**：将作战任务智能分发给蜂群中的智能体账号，支持分时投送与碎片化仿真作业调度，降低批量特征。

**使用角色**：作战指挥人员（下达作战任务）、系统（智能匹配与分发）。

**前置条件**：智能体账号池与人设标签已就绪；投送策略已配置。

**输入**：作战任务（含目标、内容、受众、时间窗口）、智能体账号池及其人设标签、投送策略。

**输出**：任务分发计划、分时投送排程、碎片化作业执行序列。

**业务规则**：

- 系统根据任务目标与人设标签进行智能体与任务的匹配，实现蜂群任务的智能分发；
- 系统支持分时投送，按预设时间窗口分散下发，避免瞬时集中；
- 系统将任务拆解为碎片化的离散动作，以拟人化的随机节奏分批调度执行，形成碎片化仿真作业轨迹，降低批量特征；
- 智能体级作业迁移与续接：当智能体所在执行终端离线或作业中断时，系统将未完成作业迁移到该智能体的其他可用终端继续执行，或在恢复续接；设备级负载均衡与容错重传由群控子系统（FR-MC-006、FR-MC-003）承担，本子系统只负责智能体级的作业调度决策；
- 与 OCC 作战编排的关系：本子系统供给智能体定义（同步至 MC 持存），OCC 的作战编排（FR-OCC-002）将 MC 中的智能体节点、自动化脚本节点编排为执行流程；本子系统的蜂群任务智能分发既可独立承接作战任务分发，也可作为 OCC 编排流程中智能体节点调度的执行手段。

**异常场景**：匹配不到合适智能体时告警并降低任务优先级；分时窗口错过时顺延至下一窗口；碎片化作业中断时续接未完成动作；智能体所在终端离线时迁移作业到其他可用终端，无可用终端时挂起待恢复。

**验收标准**：任务可按人设标签智能匹配分发；可按时间窗口分时投送；任务可拆解为碎片化动作并以拟人化节奏执行；终端离线时智能体未完成作业可迁移或续接。

##### 智能体行为仿真与防伪装（FR-SWM-003）

**功能目的**：实现智能体账号与社交账号的联动，模拟随机行为并对批量特征进行伪装，降低被风控识别的概率。

**使用角色**：系统（自动执行仿真与伪装）。

**前置条件**：智能体账号已绑定人设；行为模型参数已配置；设备已接入执行网关。

**输入**：智能体账号当前状态、社交平台行为上下文、行为模型参数、待伪装的操作批次。

**输出**：联动一致的智能体行为序列、随机化的作业轨迹、防伪装后的操作批次。

**业务规则**：

- 系统建立智能体与其社交账号的联动机制，使账号行为与其人设标签保持一致；
- 系统在作业动作之间注入随机浏览、停留、互动等真人行为，模拟真实用户的操作轨迹；
- 系统对账号的操作在时间间隔、操作频率、内容措辞、设备特征等维度进行防批量特征伪装，打散同质化特征，规避平台批量检测；
- 时段智能适配：系统结合平台风控规律与账号历史，主动将作业分配到风险较低的时段执行（主动择时）；设备级频次上限与冷却由 MC 任务管理承担，风控信号识别与规避由 MC 风控对抗承担，本子系统只负责策略层的择时决策。

**异常场景**：仿真行为触发平台验证时暂停并告警；伪装参数失效时更新模型；行为与人设偏离时纠正；时段适配无解时降级为人工选择。

**验收标准**：账号行为可与人设标签联动一致；作业动作间可注入随机真人行为；操作可在时间、频率、内容、设备等维度打散同质化特征；作业可主动适配到低风险时段执行。

##### 提示词与人设管理（FR-SWM-005）

**功能目的**：管理驱动智能体作业的提示词与账号人设标签，支持人设标签绑定、提示词模板库分类、版本管理、场景适配、动态调用与迭代优化。人设标签与提示词紧密相关——提示词按人设标签适配，故人设管理归属本功能。账号主数据（注册、凭据、生命周期等）由群控子系统 MC 的 FR-MC-010 统一维护，本功能只维护人设标签这一蜂群侧扩展属性并引用账号标识。

**使用角色**：提示词工程师（编写与维护模板）、账号运营人员（配置人设标签）、系统（动态调用与迭代）。

**前置条件**：提示词模板库已建立；人设标签体系已定义；MC 账号服务接口可用；作业上下文与效果反馈可采集。

**输入**：提示词模板、分类规则、适用场景标签、账号标识（引用自 MC）、人设标签定义、作业上下文、效果反馈数据。

**输出**：人设标签绑定关系、提示词模板库、版本记录、场景适配结果、动态填充的提示词、迭代优化记录。

**业务规则**：

- 系统为每个智能体账号绑定人设标签，标签涵盖身份特征、立场倾向、语言风格、兴趣领域等画像属性；本功能只维护人设标签，不复制账号主数据（主数据由 MC 的 FR-MC-010 统一管理）；
- 系统建立提示词模板库并按用途、平台、目标进行分类管理；
- 系统对提示词进行版本管理，支持版本对比、回滚与变更记录；
- 系统按作业场景适配提示词，根据人设标签、目标受众、当前态势选择合适模板；
- 系统在智能体作业时动态调用并填充提示词，生成最终作业指令；
- 系统结合作业效果反馈对提示词进行迭代优化，淘汰低效模板。

**异常场景**：人设标签冲突时提示人工裁定；模板填充失败时降级为默认模板；版本回滚失败时告警；效果反馈缺失时暂停迭代。

**验收标准**：人设标签可绑定且涵盖画像属性（不复制账号主数据）；提示词模板库可分类管理；版本可对比回滚；可按场景适配模板；可动态调用填充生成指令；可结合反馈迭代优化。

##### 蜂群记忆管理（FR-SWM-006）

**功能目的**：实现智能体作业记忆的存储、场景沉淀、历史复用与个性化状态延续，使智能体长期行为符合人设且不断演进。

**使用角色**：系统（自动存储与复用记忆）。

**前置条件**：记忆存储库可用；智能体已绑定人设。

**输入**：智能体作业过程数据、交互上下文、人设标签、历史记忆库。

**输出**：智能体作业记忆库、场景沉淀的模式、历史复用结果、个性化状态延续的智能体画像。

**业务规则**：

- 系统对智能体作业过程中的关键信息进行记忆存储，包括已完成任务、互动对象、立场表达等；
- 系统将重复场景下的经验沉淀为场景记忆，形成可复用的行为模式；
- 系统在相似作业中复用历史记忆，提升作业连贯性与效率；
- 系统基于记忆维持智能体的个性化状态延续，使其长期行为符合人设且不断演进。

**异常场景**：记忆存储失败时暂存待重试；记忆冲突时以最新记忆为准；复用记忆偏离人设时纠正。

**验收标准**：作业关键信息可记忆存储；重复场景经验可沉淀为模式；相似作业可复用历史记忆；智能体可基于记忆维持个性化延续。

#### 私有化大模型部署（IRS）

私有化大模型部署是系统的底层推理基础设施（非业务子系统），职责是部署本地大模型并提供推理调用，使全系统的 AI 推理不依赖外部公有云。它向上为舆情作战、蜂群智能体、数据爬取等子系统提供统一的本地大模型推理能力，本身不参与业务编排。

##### 本地大模型部署（FR-IRS-001）

**功能目的**：在私有化环境中部署本地大模型，构建系统的底座推理能力，使全系统的 AI 推理不依赖外部公有云，供各子系统统一调用。

**使用角色**：推理服务运维人员（部署与维护模型）、各子系统（调用本地大模型推理）。

**前置条件**：私有化 GPU 算力环境可用；大模型权重与配置已就位。

**输入**：大模型权重与配置、部署环境资源（算力、显存、网络）。

**输出**：运行中的本地大模型实例及可调用的推理接口。

**业务规则**：

- 系统在私有化环境中部署本地大模型，完成模型加载与服务实例化；
- 系统对外提供统一的推理调用接口，供数据爬取、蜂群智能体、舆情作战等子系统调用；
- 部署不依赖外部公有云模型服务。

**异常场景**：模型加载失败时回退至上一可用版本；服务实例化失败时告警并重试；算力资源不足时拒绝新请求并排队。

**验收标准**：本地大模型可在私有化环境部署并加载实例化；可对外提供推理调用接口；部署不依赖外部公有云。



#### 舆情作战业务子系统（OCC）

舆情作战业务子系统是全链路的指挥大脑，构建"目标识别 → 作战编排 → 效果评估"的作战闭环，并承担内容资源的统一管理（作为内容资源的唯一权威源，向各使用方分发内容）。本子系统基于数据爬取子系统的分析结果与私有化推理服务的本地大模型推理能力，对舆情目标进行识别与维护，以"作战编排"的方式直接编排群控子系统（MC）中的智能体节点与自动化脚本节点形成执行流程并落地，最终对作战效果进行评估与迭代。本期实现目标识别（含目标数据维护）、作战编排、效果评估、策略库与内容资源管理五项能力；情报线索侦察、全维度画像分析、抓手挖掘、舆情风险定级与对冲策略匹配、仿真舆论发声与观点博弈、全媒体投送适配与舆论对冲、线下态势联动研判等能力本期暂不实现（见附录 6.4），相关环节现阶段由人工承担，后续逐步程序化。

##### 目标识别与维护（FR-OCC-001）

**功能目的**：识别舆情事件的目标要素并对其进行全生命周期维护。目标在系统中即数据对象——支持建档、修改、关联、状态流转与删除，而非一次识别即定型的只读结果。本能力融合情报侦察、多维画像与抓手挖掘中"识别目标"的部分：从舆情事件与传播数据中识别事件主体、传播源头、核心争议点、干预目标对象，并补充传播线索、事件/群体/账号/传播画像、干预切入点与薄弱点等目标属性，形成可持续维护的目标档案，为后续作战提供靶向。

**使用角色**：情报分析人员（识别、确认识别结果、维护目标数据）、作战指挥人员（确认干预目标与切入点）、系统（辅助识别，本期以人工识别为主、系统提供数据维护支撑）。

**前置条件**：舆情事件数据与传播数据已采集；IRS 本地大模型可用；目标数据存储与维护接口可用。

**输入**：舆情事件数据、传播数据、相关账号与内容、人工或系统产出的识别结果、目标属性修改请求、目标关联与状态变更请求。

**输出**：目标档案（含事件主体、传播源头、核心争议点、干预目标对象、传播线索、多维画像属性、干预切入点与薄弱点）、目标标识（target_id）、目标变更事件。

**业务规则**：

- 目标即数据：每个识别出的目标建档为一条目标数据，赋予全局唯一的目标标识 target_id，作为后续作战、评估与统计的引用；
- 目标可修改：目标档案的各属性（事件主体、争议点、画像属性、干预切入点等）支持新增、修改与删除，识别结果不是只读终态，可随事件演进而更新；
- 目标可关联：目标之间可建立关联关系（如一个事件主体关联多个传播源头、一个干预目标关联多个薄弱点），形成目标关系网络；
- 目标有状态：目标具备状态生命周期（如待核实、已确认、已锁定、已处置、已归档），支持状态流转；
- 目标识别融合多维信息：识别过程综合事件主体、传播源头与链路、事件/群体/账号/传播画像、干预切入点与传播薄弱点，形成完整目标档案；
- 本期以人工识别为主、系统提供数据维护支撑：识别判断由情报分析人员完成并录入系统，系统负责目标数据的存储、关联、状态管理与变更通知；后续逐步接入自动识别与画像建模能力；
- 目标变更经事件总线广播 target.changed 事件，使用方（作战编排、效果评估）订阅响应。

**异常场景**：识别数据不足时目标建档为"待核实"并提示补充；目标属性修改冲突时按目标标识加锁或提示人工裁定；目标关联断裂时标注断点；事件总线广播失败时重试。

**验收标准**：目标可建档并赋予 target_id；目标各属性可新增、修改、删除；目标间可建立关联关系；目标状态可流转；目标档案可融合事件主体、传播、画像、切入点等多维信息；目标变更可经事件通知使用方；本期支持人工识别录入与系统数据维护。

##### 作战编排（FR-OCC-002）

**功能目的**：根据目标档案与干预切入点匹配干预策略、生成作业方案，并以"作战编排"的方式直接编排群控子系统（MC）中的执行节点形成执行流程（图）落地，形成"目标→编排→执行"的闭环。本功能改变了 V2.0"OCC→SWM→MC"的间接调度链路：OCC 直接编排 MC 中的节点，蜂群智能体子系统（SWM）由任务分发中枢转变为"智能体节点的供给方之一"。编排的节点类型本期为两类——智能体节点（其智能体定义来源于 SWM 同步至 MC 的内容，见 FR-MC-011）与自动化脚本节点（ADB/RDP/CDP 等通道），节点类型后续可持续扩充。本期干预切入点与策略匹配以人工为主，系统提供方案生成与编排支撑。

**使用角色**：作战指挥人员（确认切入点与策略、审核编排方案）、系统（生成方案与编排执行）。

**前置条件**：目标档案已建档；策略库可用；MC 中可用的智能体定义与执行终端状态可查询。

**输入**：目标档案（含干预切入点）、策略库、MC 执行节点资源状态（可用智能体、可用终端、可用脚本）、执行约束。

**输出**：匹配的干预策略、生成的作业方案、编排形成的执行流程（图）、调度执行落地的结果。

**业务规则**：

- 系统根据目标档案中的干预切入点匹配干预策略（本期以人工匹配为主）；
- 系统生成具体的作业方案（含内容、账号、时间、节奏）；
- 系统将作业方案编排为执行流程：以 MC 中的智能体节点、自动化脚本节点为编排实体，按内容、账号、时间、节奏组织节点间的前后序、并行与分支关系，形成可执行的流程（图）；节点类型后续可扩充（如内容生成节点、评估节点等）；
- 编排落地后由 MC 的统一执行网关收口所有节点动作——认知作战账号的养号与投放动作经移动端 ADB/无障碍通道、爬虫账号的相关动作经桌面端 CDP 通道；
- 智能体节点对应的智能体定义由 SWM 编写并同步至 MC 持存（见 FR-MC-011），OCC 编排时引用 MC 中已持存的智能体。

**异常场景**：策略匹配失败时降级为人工选择；MC 执行节点资源不足时排队或缩减规模；编排流程中某节点执行失败时按编排定义回滚、跳过或转人工；执行落地失败时回滚并告警。

**验收标准**：可根据目标档案匹配干预策略；可生成含内容、账号、时间、节奏的作业方案；可将 MC 中的智能体节点与自动化脚本节点编排为执行流程（图）；编排落地后动作经 MC 统一执行网关收口；节点类型后续可扩充。

##### 效果评估（FR-OCC-003）

**功能目的**：完成单轮干预成效统计、舆论走势修正、策略迭代反馈与作业复盘，并支持中短期与长期效果评估，形成作战闭环。本节的数据来源为两条：其一，数据爬取子系统（DC）的采集与分析结果（干预前后的舆情数据、传播数据、立场与情感变化）；其二，群控子系统（MC）可观测性能力（FR-MC-008）上报的作业执行动作日志、任务日志与截图（投放触达、互动执行、账号行为记录）。OCC 基于这两类数据进行效果分析，不自行重复采集。

**使用角色**：作战指挥与评估人员（查阅评估）、系统（自动统计与反馈）。

**前置条件**：干预已执行；DC 采集与分析结果可获取；MC 可观测性的动作日志与任务日志可获取；效果指标与历史基线可获取；长周期观察数据可积累。

**输入**：来自 DC 的干预前后舆情数据、传播数据与文本分析结果（立场/情感/观点变化）；来自 MC 可观测性的作业执行记录（投放触达、互动执行、账号行为、任务完成情况）；效果指标与历史基线、长周期观察数据。

**输出**：单轮成效统计、舆论走势修正评估、策略迭代反馈、作业复盘报告、中短期与长期效果评估结果。

**业务规则**：

- 本子系统不重复采集原始数据，效果分析所需的舆情数据来源于 DC、作业执行数据来源于 MC 可观测性；
- 系统基于 DC 舆情数据与 MC 作业数据完成单轮干预的成效统计（触达、互动、立场变化等）；
- 系统基于 DC 前后舆情对比对舆论走势进行修正评估；
- 系统将评估结果反馈至策略库以迭代优化；
- 系统结合 MC 作业执行记录进行作业复盘总结经验；
- 系统提供中短期实网绩效评估与长期舆论塑造效果评估接口，实现效果联动。

**异常场景**：DC 数据源或 MC 数据源缺失时标注评估不完整；走势修正偏差大时提示人工复核；反馈写入策略库失败时暂存重试。

**验收标准**：可基于 DC 舆情数据与 MC 作业数据进行单轮干预成效统计；可修正评估舆论走势；可将评估反馈策略库迭代；可结合 MC 作业记录作业复盘；可提供中短期与长期效果评估接口。

##### 舆论作业策略库（FR-OCC-004）

**功能目的**：搭建并迭代多语种、多场景、多风格的舆论作业策略库，为作战提供可复用、可演进的策略资产。

**使用角色**：作战策略工程师（维护策略库）、系统（自动迭代与调用）。

**前置条件**：策略定义规范已制定；历史作业效果可采集。

**输入**：策略定义（语种、场景、风格、适用条件）、历史作业效果、迭代反馈。

**输出**：多语种多场景多风格的舆论作业策略库、策略版本记录、迭代优化结果。

**业务规则**：

- 系统按多语种、多场景、多风格组织舆论作业策略库；
- 系统对策略进行分类管理与版本控制；
- 系统根据作业效果反馈对策略进行迭代优化；
- 系统支持策略的场景适配与动态调用。

**异常场景**：策略冲突时人工裁定；版本回滚失败时告警；迭代反馈不足时暂停该策略迭代。

**验收标准**：策略库可按多语种多场景多风格组织；策略可分类管理与版本控制；可按效果反馈迭代优化；可场景适配与动态调用。

##### 内容资源管理（FR-OCC-005）

**功能目的**：承担内容资源的统一管理，作为内容主数据的唯一权威源，管理内容素材的入库、分类、审核与发布排期，并向各使用方主动分发内容标识（content_id）。蜂群智能体（SWM，养号文案）、群控（MC，内容投放）与未来 AI 素材制作为使用方，通过引用内容标识获取内容并维护各自的平台适配版本与使用记录。

**使用角色**：内容运营人员（上传与排期素材）、审核人员（发布前审核）、各使用子系统（经内容服务接口引用内容）、系统（自动审核、排期与事件广播）。

**前置条件**：对象存储可用；敏感词库已配置；目标平台规格已知；内容服务接口与事件总线已就绪。

**输入**：图片、视频、文案等素材，素材的标签与平台分类信息，发布排期，待审核内容，各使用方的内容引用请求。

**输出**：内容主数据记录、入库的内容记录、发布排期、内容审核结果、内容服务接口（查询/获取素材）、content.changed 事件、内容标识（content_id）。

**业务规则**：

- 内容主数据（原始素材、分类、审核状态、来源）由本子系统唯一维护，其它子系统不复制主数据；
- 内容标识 content_id 为全局唯一引用，贯穿 SWM（养号文案）、MC（内容投放）、未来 AI 生成，使用方只维护各自的扩展属性并引用 content_id（如平台适配版本、使用记录、投放记录）；
- 系统对素材分类管理，支持标签、平台分类与账号适配；
- 系统支持按素材、账号与时间制定定时发布排期；
- 发布前对内容进行审核与敏感词检测；
- 内容新增或状态变更经事件总线广播 content.changed 事件，使用方订阅响应；本子系统作为权威源向使用方主动分发内容标识。

**异常场景**：内容服务接口不可用时使用方降级为本地缓存只读；素材上传失败时支持断点续传；敏感词命中时拦截并标记待人工复核；排期冲突时提示调整；事件广播失败时重试。

**验收标准**：内容主数据由本子系统唯一维护且使用方不复制；content_id 全局唯一可被各子系统引用；素材可分类管理与平台适配；发布排期可定时触发；内容可经审核与敏感词检测后发布；内容变更可经事件通知使用方并主动分发。

系统应提供与外部系统交互的接口。所有外部接口均应使用鉴权与传输加密。各接口如下：

**社交平台交互接口 EI-01**

**代理 IP 服务接口 EI-02**

对接对象：VPS 代理链路与代理 IP 供应商。

输入：代理分配请求（平台、地区、数量）。

输出：可用代理 IP 列表、代理可用性状态、轮换日志。

**接码与虚拟号服务接口 EI-03**

对接对象：手机号接码与虚拟号服务。

输入：注册请求（平台、手机号或虚拟号标识）、验证码获取请求。

输出：接收的验证码、注册结果、虚拟号凭据。


**对象存储接口 EI-05**

对接对象：MinIO 或阿里云 OSS 等对象存储。

输入：上传文件（素材、截图、录屏）、下载请求、签名 URL 请求。

输出：文件存储路径、下载链接（限时签名）、存储结果。

**本地大模型推理接口 EI-06**

对接对象：底层私有化大模型部署（IRS）。

输入：推理请求（文本/截图、任务类型、上下文、人设参数）。

输出：推理结果（分类标签、立场、情感、观点、规划动作）。

#### 内部接口需求

子系统间及子系统内部应通过明确的接口交互。各接口如下：

**账号服务接口 II-01**

提供方 → 调用方：群控子系统（MC） → 数据爬取（DC）、蜂群智能体（SWM）、舆情作战（OCC）。

输入：账号查询请求（account_id）、账号变更请求（状态、风险评估）。

输出：账号主数据（凭据、平台、状态、生命周期、风险等级、账号分类）。

**账号状态变更事件 II-01a**

提供方 → 事件总线 → 订阅方：群控子系统（MC） → 事件总线 → DC/SWM/OCC。

输入：account.status.changed 事件（account_id、旧状态、新状态、变更原因）。

输出：使用方订阅后执行响应（停止任务、停止养号、休眠智能体、移除目标），保证被封账号全网即时失效。

**Agent 指令与日志接口 II-02**

提供方 ↔ 调用方：群控子系统（MC）服务端 ↔ 设备端 Agent。

输入：下发指令（动作类型、参数、目标设备）、回传日志（执行结果、截图）。

输出：指令下发确认、日志与截图回传结果。

**远控画面传输接口 II-03**

提供方 → 调用方：MC 设备 → WebRTC SFU → 操作端。

输入：设备画面流、操作端输入事件（鼠标、键盘）。

输出：实时画面流（低延迟）、输入事件执行确认。

**日志与指标上报接口 II-04**

提供方 → 调用方：各子系统 → 运维监控子系统（OM）。

输入：子系统日志、运行指标（设备在线率、任务成功率、爬虫吞吐量、队列积压）。

输出：上报确认、入库结果。

**Kafka 数据总线接口 II-05**

提供方 → 调用方：数据爬取子系统（DC）内部采集 → 处理与存储环节。

输入：原始采集数据、共享资源状态变更事件。

输出：Kafka 消息流（分区分组、可回溯消费）。

**管理 REST 接口 II-06**

提供方 → 调用方：各子系统 → 前端与外部。

输入：设备/任务/内容/账号/审计的管理请求（CRUD 操作）。

输出：管理操作结果（数据列表、操作状态）。

**执行网关动作接口 II-07**

提供方 ← 调用方：群控子系统（MC）统一执行网关 ← 脚本引擎/智能体引擎。

输入：动作指令（动作类型、坐标/元素、参数、目标执行终端、账号标识、终端类型）。

输出：动作执行结果、动作日志记录、熔断记录。本接口统一收口移动端终端（真机/云手机/ARM 板卡/虚拟化真机，经 ADB/无障碍通道）与桌面端浏览器 Profile（经 CDP 通道）的所有动作；V2.0 的 II-15 桌面端执行网关动作接口已并入本接口。

**本地大模型推理调用接口 II-08**

提供方 → 调用方：设备端 Agent → 私有化大模型部署（IRS）。

输入：推理请求（截图、任务类型、人设上下文）。

输出：推理结果（视觉理解、下一步动作规划）。此接口不经执行网关，以保证低延迟。

**策略下发接口 II-09**

提供方 → 调用方：蜂群智能体子系统（SWM） → 设备端 Agent。

输入：人设标签、提示词、作业策略（任务目标、节奏、防伪装参数）。

输出：策略下发确认。

**脚本作业参数接口 II-10**

提供方 → 调用方：蜂群智能体子系统（SWM） → 脚本引擎。

输入：作业参数（account_id、content_id、时间窗口、任务类型）。

输出：作业参数下发确认。

**作战编排下发与执行回传接口 II-11**

提供方 ↔ 调用方：舆情作战子系统（OCC） ↔ 群控子系统（MC）。

输入：下发——作战编排流程（目标、策略、内容、账号、时间、节点编排关系：智能体节点引用的智能体定义、自动化脚本节点及其前后序/并行/分支）；回传——作业执行效果数据（触达、互动、完成情况、节点执行结果）。

输出：编排下发确认、效果数据回传结果，形成作战执行闭环。OCC 直接编排 MC 中的智能体节点与自动化脚本节点落地，蜂群智能体子系统（SWM）作为智能体定义的供给方经 II-15 同步至 MC，作业执行效果经 MC 可观测性（FR-MC-008）采集后回传 OCC 评估。

**执行网关日志上报接口 II-12**

提供方 → 调用方：群控子系统（MC）统一执行网关 → 运维监控子系统（OM）。

输入：全量动作日志、熔断记录（含移动端终端与桌面端浏览器 Profile 的动作）。

输出：上报确认、入库结果。

**智能体定义同步接口 II-15**

提供方 → 调用方：蜂群智能体子系统（SWM） → 群控子系统（MC）。

输入：智能体定义（人设标签、提示词、记忆、作业策略、绑定的账号标识）。

输出：同步确认、持存版本号。MC 接收后持存，作为智能体执行宿主在任务执行时调用（见 FR-MC-011），并作为 OCC 作战编排中智能体节点的定义来源。

**内容服务接口 II-13**

提供方 → 调用方：舆情作战业务子系统（OCC） → 蜂群智能体（SWM）、群控（MC）。

输入：内容查询请求（content_id）、素材获取请求。

输出：内容主数据（素材、分类、审核状态）、素材文件或下载链接。

**内容变更事件 II-13a**

提供方 → 事件总线 → 订阅方：舆情作战业务子系统（OCC） → 事件总线 → SWM/MC。

输入：content.changed 事件（content_id、变更类型、新状态）。

输出：使用方订阅后执行响应（刷新缓存、更新平台适配）。

**分析数据与情报接口 II-14**

提供方 → 调用方：数据爬取子系统（DC） → 舆情作战子系统（OCC）。

输入：分析数据请求（舆情事件、目标、时间范围）。

输出：舆情数据、传播数据、文本分析结果（立场/情感/观点）、关系图谱。

**情报回注采集接口 II-16**

提供方 → 调用方：数据爬取子系统内部 DC 分析（FR-DC-004） → DC 任务池与调度（FR-DC-002）。

输入：分析产出的高价值目标个体、关联实体与传播节点（来自 FR-DC-004），以及回注规则（自动回注或人工确认、优先级、来源情报标识）；扩散场景下另含扩散起点目标与扩散参数（关系类型、扩散层数、去重范围）。

输出：回注生成的采集任务（写入 task_pool，携带 source_type=intel_feedback 与来源情报标识）、回注与扩散的审计记录。该接口与 II-14（DC→OCC 单向情报输出）方向相反，构成 DC 内部"分析→采集"反向驱动闭环。

资源遵循统一约束：使用方只引用资源标识（account_id、content_id），不复制主数据；账号主数据由群控子系统（MC）担任权威源（FR-MC-010），内容主数据由舆情作战业务子系统（OCC）担任权威源；状态变更一律经事件总线通知。

#### 数据需求

系统应维护以下数据。账号与内容作为平台级资源按权威源模式分层存储：账号主数据（凭据、平台、状态、生命周期、风险评估、账号分类，凭据须加密存储）由群控子系统（MC）担任权威源统一维护（DR-02M）；账号扩展数据由使用方各自维护并引用账号标识，包括数据爬取侧的采集关联、群控侧的账号-终端绑定与登录状态、智能体账号分层分组与作业生命周期（亦归 MC）、蜂群侧的人设标签（DR-02E2，见 DR-09）；账号标识（account_id）作为全局唯一引用贯穿各子系统。内容主数据（原始素材、分类、审核状态、来源）由舆情作战业务子系统（OCC）担任权威源统一维护（DR-03M）；内容扩展数据由使用方维护并引用内容标识，包括平台适配版本与使用记录（DR-03E）；内容标识（content_id）作为全局唯一引用。

其它数据包括：执行终端数据，包括移动端终端（真机/云手机/ARM 板卡/虚拟化真机）、桌面端浏览器 Profile、终端分组与终端指标（DR-01）；任务数据，包括任务、任务实例与任务日志（DR-04）；脚本与工作流数据，包括脚本、脚本版本与工作流定义（DR-05）；采集与分析数据，其中 ETL 结果存于 HBase，关系数据存于图数据库（DR-06）；审计与风险数据，包括审计日志与风险事件（DR-07）；代理与指纹数据，包括代理 IP 池、移动端设备指纹配置与桌面端浏览器 Profile 指纹配置（DR-08，移动端与桌面端 Profile 指纹均归 MC）。

蜂群智能体数据，包括智能体账号的人设标签、作业记忆与提示词模板版本（DR-09）；其中智能体定义（人设标签、提示词、记忆、作业策略）由 SWM 编写并同步至 MC 持存（见 FR-MC-011）。智能体账号的分层分组关系与作业生命周期状态归 MC 维护（见 DR-02E2、FR-MC-010）。本地大模型数据，包括本地大模型配置与推理调用日志（DR-10）。舆情作战数据，包括目标识别结果、传播链路、多维画像、抓手挖掘结果、作战编排流程（节点编排关系）、策略库版本与效果评估记录（DR-11）。

平台级资源数据的统一约束：主数据只存于权威源且唯一一份；使用方只存"资源标识 + 自有扩展属性"，不复制主数据；资源标识在全系统唯一；主数据状态变更经事件总线广播。

### 非功能需求

本节给出系统的非功能需求，包括性能、安全性、保密性、可靠性、可维护性、易用性、运行环境、故障处理与约束条件。

#### 性能需求

系统应满足以下性能要求。
单设备远程控制端到端延迟应不大于 300 毫秒，多设备宫格预览可适当放宽（NFR-P-01）。
单租户应支持不少于 200 台设备的并发接入与控制（NFR-P-02）。
数据爬取子系统的爬虫集群应满足业务采集量的日处理能力，并支持水平扩展（NFR-P-03）。
任务从入队到分发应不超过 2 秒，并支持任务优先级与最大并发控制（NFR-P-04）。
WebRTC SFU 应支持单节点并发多路远控流，并在弱网下自动降帧（NFR-P-05）。
运维监控的日志检索响应应不超过 3 秒，覆盖近 7 日数据（NFR-P-06）。

#### 安全性需求

系统应满足以下安全性要求。
系统应提供用户认证与双因素，并对全部 API 进行鉴权（NFR-S-01）。
系统传输应全程使用 HTTPS 或 TLS，远程控制通道应加密（NFR-S-02）。
账号凭据、代理凭据等敏感字段应加密存储，不得明文落库（NFR-S-03）。
Agent 应进行签名校验以防止伪造设备接入，指令应签名（NFR-S-04）。
脚本应运行于沙箱并配置权限白名单，禁止越权访问与读取敏感路径（NFR-S-05）。
所有账号、设备、任务操作应留存审计日志，可追溯（NFR-S-06）。
文件访问应使用签名 URL，限时有效（NFR-S-07）。

#### 保密性需求

系统应满足以下保密性要求。
多组织或多租户的数据应严格隔离，禁止跨组织访问（NFR-C-01）。
数据访问应遵循最小权限原则，按角色与数据范围控制（NFR-C-02）。
手机号、凭据等敏感数据应脱敏展示（NFR-C-03）。数据库应定期备份，
数据导出操作应审计留痕（NFR-C-04）。

#### 可靠性需求

系统应满足以下可靠性要求。
核心服务可用性应不低于 99.5%（NFR-R-01）。
任务应支持幂等与失败重试，异常任务应自动熔断（NFR-R-02）。
Agent 掉线应自动重连，设备重启后 Agent 应自启动（NFR-R-03）。
关键服务应高可用部署，无单点故障（NFR-R-04）。
数据采集应具备补偿与断点续采能力（NFR-R-05）。

#### 可维护性需求

系统应满足以下可维护性要求。
系统应采用模块化、服务化设计，子系统可独立部署升级（NFR-M-01）。
采集、调度、频率控制、代理等关键策略应可配置，无需修改代码（NFR-M-02）。
系统应提供全链路日志与追踪，故障可定位（NFR-M-03）。
系统应提供运维仪表盘与告警，支持常态化运维（NFR-M-04）。

#### 易用性需求

系统应满足以下易用性要求。
Web 管理后台界面应清晰，设备、任务、账号、内容分区明确（NFR-U-01）。
批量操作应支持选择设备组并一键下发（NFR-U-02）。
远程控制画面与任务日志应同屏可见（NFR-U-03）。
关键操作应有确认与风险提示（NFR-U-04）。

#### 运行环境需求

服务端应运行于 Linux 操作系统，采用 Docker 与 Kubernetes 进行容器编排，后端采用 Java Spring Boot 或 Go。
数据存储应包括 PostgreSQL 或 MySQL、Redis、Kafka、HBase、图数据库与 MinIO 或 OSS。
数据爬取子系统应基于 K3s 容器化部署爬虫集群，支持横向扩缩容与节点故障自愈；原始采集数据经 Kafka 分区分组流转并支持回溯消费，任务去重与调度队列基于 Redis 实现。上述爬虫集群、Kafka 数据流转与 Redis 调度构成数据采集的资源底座（原爬取工程基础设施，现归入运行环境）。
前端应基于现代浏览器，采用 Vue3 或 React 与 TypeScript。
移动端应提供 Android Agent，兼容主流 Android 版本，设备类型包括真机、云手机、ARM 板卡与虚拟化真机，由群控子系统（MC）统一接入管理。桌面端反指纹浏览器应基于开源 BotBrowser 定制的 Chromium 内核构建，支持 CDP 接入与 Profile 级指纹配置，Profile 数据独立隔离存储，亦由群控子系统（MC）统一接入管理。移动端与虚拟化真机的远程控制可基于 RDP 通道。监控应采用 Prometheus、Grafana 与 ELK 或 Loki。

私有化推理服务应部署于配备 GPU 算力的私有化服务器或算力集群，用于本地大模型的加载与推理；部署不依赖外部公有云模型服务。

#### 故障处理需求

系统应满足以下故障处理要求。
任务异常应自动熔断，停止后续执行并告警（NFR-F-01）。
设备或 Agent 异常应自动隔离，不再派发任务，待恢复后重新接入（NFR-F-02）。
账号发生封禁或受限等异常时，应自动停止该账号相关任务并告警（NFR-F-03）。
消息中间件或数据库故障应具备重试与死信处理（NFR-F-04）。
服务异常应具备降级能力，优先保障远程控制与日志通道（NFR-F-05）。

#### 约束条件

群控子系统最小可行产品优先接入云手机与真机、实现远程控制与基础任务（CON-01）。
第一阶段不自研云手机内核，优先接入第三方云手机 API（CON-02）。
爬虫与 ETL 应复用现有大数据与基础设施组件，包括 K3s（爬虫集群容器编排）、Kafka、Redis、Spark 与 HBase（CON-03）。
蜂群智能体（SWM）、私有化大模型部署（IRS）、舆情作战（OCC）为本期 V2.0 新增能力，应优先实现核心闭环链路：本地大模型可用、蜂群可调度执行、舆情作战可形成识别到评估的闭环（CON-04）。
目标平台为海外社交平台，需考虑网络代理与合规边界（CON-05）。
大模型推理应采用私有化部署，不依赖外部公有云模型服务（CON-06）。

所有执行终端动作均应经执行网关落地，禁止任何子系统或 Agent 绕过执行网关直接操作终端，以保证动作可观测、可审计、可熔断：移动端终端（真机/云手机/ARM 板卡/虚拟化真机）动作经 ADB/无障碍通道收口，桌面端反指纹浏览器 Profile 动作经 CDP 通道收口，两类终端动作均经群控子系统（MC）的统一执行网关收口（CON-07）。
系统应同时支持脚本模式与智能体模式两种执行引擎，养号等风控敏感场景可优先采用脚本模式，内容投放与自适应场景可采用智能体模式（CON-08）。
执行终端应按指纹真实度进行风控分级，认知作战账号养号等高敏感场景应优先选用真机与 ARM 板卡，云手机与反指纹浏览器 Profile 用于爬虫账号养护与规模化采集，模拟器仅用于测试（CON-09）。
智能体模式下的视觉推理应调用 IRS 本地大模型，不经执行网关；推理产出的动作指令再经执行网关落地（CON-10）。
执行层职责应按"统一执行网关 + 内容权威源"两类归属：反指纹浏览器 Profile 的管理（创建、指纹固化、接入、监控）与桌面端 CDP 执行网关、移动端终端管理与 ADB/无障碍执行网关、账号主数据（注册、凭据、验证、风险评估、生命周期、账号分类）的唯一维护与共享分发、智能体执行宿主，均归群控子系统（MC）；内容资源（素材入库、分类、审核、排期、分发）唯一权威源归舆情作战业务子系统（OCC）。蜂群智能体子系统（SWM）作为智能体定义与记忆中心，将智能体定义同步至 MC 持存；舆情作战子系统（OCC）以作战编排方式直接编排 MC 中的智能体节点与自动化脚本节点。V3.0 已将原指纹浏览器管理子系统（FB）与共享资源管理子系统（SR）并入 MC，使执行终端管理、账号主数据与动作执行统一收口（CON-11）。
反指纹浏览器应基于开源 BotBrowser 定制，采用 Chromium 源码级指纹伪装，桌面端控制通道采用 CDP（Chrome DevTools Protocol）；浏览器 Profile 创建时生成并固化指纹，一个 Profile 对应一套固定指纹与一个账号身份（CON-12）。
账号应按用途分类管理：爬虫账号以桌面端反指纹浏览器 Profile 为执行终端、其养护（养号）动作执行经 MC 统一执行网关的 CDP 通道，认知作战账号以移动端设备为执行终端、经 MC 统一执行网关的 ADB/无障碍通道执行养号动作；两类账号的注册、验证与生命周期等主数据均由群控子系统（MC）统一维护并向各子系统分发 account_id。账号-终端绑定遵循差异化规则：真机、云手机、虚拟化真机执行"一设备一账号"，反指纹浏览器 Profile 执行"一 Profile 一账号"（实例可多开）（CON-13）。

## 合格性规定

### 验证方法

系统应采用评审、演示、测试与分析相结合的方法进行合格性验证。评审用于对需求与设计文档进行相关方确认。演示用于对设备接入、远程控制、群控、采集与可视化等能力进行现场展示。测试用于对功能、接口、性能与安全进行验证。分析用于对日志、指标与审计记录进行分析确认。

### 验证条件

合格性验证应在部署完整的各子系统及其依赖组件的测试环境中进行。环境应接入不少于规定数量的测试设备，包括云手机与真机，以及测试账号。应准备目标平台的测试数据与代理 IP 资源。私有化推理服务应部署配备 GPU 算力的环境并加载本地大模型。蜂群智能体与舆情作战子系统应接入测试智能体账号与作战场景数据。

### 验证准则

验证应以本文件的需求为准则。功能需求应逐项验证通过。非功能需求应达标，其中性能指标应经实测满足，安全项应无高危问题。各子系统接口应联通，日志与指标应正常上报至运维监控子系统。验证应无遗留的致命与严重缺陷。
