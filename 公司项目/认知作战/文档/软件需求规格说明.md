## 1 引言

### 1.1 标识

本软件命名为"认知作战平台"（以下简称"系统"或"平台"）。系统由六个子系统与一组跨子系统的公共功能组成：数据爬取子系统（DC）、多设备矩阵自动化群控子系统（MC）、运维监控子系统（OM）、蜂群智能体子系统（SWM）、私有化推理服务子系统（IRS）、舆情作战业务子系统（OCC），以及公共功能（COM）。

### 1.2 软件概述

平台面向社交媒体，构建"数据采集 → 分析研判 → 智能体编队 → 编队执行 → 效果评估 → 运维保障"的完整需求能力闭环。

系统按职责分为三层。底层为基础设施层，包括数据爬取子系统与运维监控子系统。数据爬取子系统负责爬取工程底座、账号维护、社交媒体数据的采集与分析；
运维监控子系统汇聚全系统日志与指标，完成常态化运维。

中层为执行层，包括多设备矩阵自动化群控子系统与蜂群智能体子系统。群控子系统定位为"设备执行网关与调度引擎"，统一管理安卓设备矩阵，提供设备接入、远程控制、指纹与代理隔离，并以执行网关的形式收口所有落到设备的动作——无论动作来自脚本还是智能体，均经群控子系统的执行网关落地，从而保证每一个动作可观测、可审计、可熔断；蜂群智能体子系统提供账号人格与作业策略，包括智能体账号管理、蜂群任务智能分发、行为仿真与防伪装、集群负载均衡与离线保活，以及提示词与记忆管理。执行层支持两种执行模式：脚本模式由固定流程驱动，智能体模式由大模型实时决策驱动，两者共用底层控制通道、均收口于群控执行网关。

上层为智能层，包括私有化推理服务子系统与舆情作战业务子系统。
私有化推理服务子系统提供一体化的大模型推理底座、统一网关、智能路由、并发会话管控、量化适配与容错容灾，支撑全场景 AI 推理；
舆情作战业务子系统构建"目标识别 → 情报侦察 → 多维画像 → 抓手挖掘 → 行动实施 → 效果评估"的作战闭环。公共功能（COM）为各子系统提供统一的认证、权限与组织管理。

各子系统之间存在密切的协作关系。账号是数据爬取、群控与蜂群智能体子系统的共享资产：数据爬取侧负责账号注册、验证与风险评估，群控侧通过养号维持账号存活，蜂群侧在账号上绑定人设标签并驱动智能体作业。

舆情作战子系统是全链路的指挥大脑：它基于数据爬取子系统的分析结果与私有化推理服务的推理能力，产出作战方案，再经蜂群智能体子系统调度，最终由群控子系统的设备矩阵执行落地，并将执行效果回传至舆情作战子系统进行评估闭环。

私有化推理服务子系统为数据爬取的文本分析、蜂群智能体的行为决策、舆情作战的判别与策略生成提供统一的推理能力支撑。各子系统均向运维监控子系统上报日志与指标。

## 3 需求

### 3.1 功能需求

本节给出系统的功能需求，按子系统组织。3.1.1 给出数据爬取子系统（DC）的功能需求，3.1.2 给出多设备矩阵自动化群控子系统（MC）的功能需求，3.1.3 给出运维监控子系统（OM）的功能需求，3.1.4 给出跨子系统的公共功能（COM）需求，3.1.5 给出蜂群智能体子系统（SWM）的功能需求，3.1.6 给出私有化推理服务子系统（IRS）的功能需求，3.1.7 给出舆情作战业务子系统（OCC）的功能需求，3.1.8 至 3.1.10 给出接口与数据需求。每个功能按"功能目的、使用角色、前置条件、输入、输出、业务规则、异常场景、验收标准"描述，并给出需求编号以便追踪。

#### 3.1.1 数据爬取子系统（DC）

##### 3.1.1.1 爬取工程基础设施（FR-DC-001 ~ 004）

**功能目的**：为数据爬取子系统提供分布式爬取运行的工程底座，以可弹性伸缩的爬虫集群、可靠的数据流转通道、任务调度与去重机制，以及面向海外社交平台的代理网络出口，支撑后续采集与分析能力的稳定运行。

**使用角色**：系统运维人员（配置爬虫集群与代理资源）、数据采集调度（自动调度爬虫任务）。

**前置条件**：K8s 集群可用；Kafka、Redis 中间件正常运行；VPS 代理链路与代理 IP 池已配置。

**输入**：爬虫任务定义（目标平台、采集范围、频率）、节点资源配置、代理 IP 与 VPS 代理链路配置、平台与地区分配策略。

**输出**：运行中的爬虫实例、Kafka 中的原始数据流、调度指令与去重结果、可用代理 IP 列表与轮换日志。

**业务规则**：

- 爬虫以容器化方式部署于 K8s，支持横向扩缩容与节点自愈；
- 原始数据经 Kafka 分区分组流转，支持回溯消费；
- 任务调度与去重基于 Redis 实现，包括 URL 与任务去重、调度队列与分布式锁；
- 代理 IP 池对接 VPS 代理链路，按平台与地区分配代理并定时轮换，对代理进行可用性检测与失效剔除。

**异常场景**：爬虫节点故障时自动重启或迁移；Kafka 不可用时数据暂存本地待重试；代理全部失效时告警并暂停受影响的采集任务；代理检测超时时剔除该代理并补充新代理。

**验收标准**：爬虫集群可弹性扩缩容且节点故障可自愈；Kafka 数据可分区分组流转与回溯消费；Redis 去重与调度功能生效；代理按策略分配、定时轮换并自动剔除失效节点。

##### 3.1.1.2 账号维护（FR-DC-010 ~ 014）

**功能目的**：管理社交媒体账号的提交、验证、日常维护、注册与生命周期，作为数据采集与群控执行的共享账号来源，维持账号可用性与活跃度。

**使用角色**：账号运营人员（提交与维护账号）、系统（自动执行验证、维护与注册流程）。

**前置条件**：账号凭据加密存储机制可用；邮箱、手机接码、虚拟号等注册渠道已对接；账号状态规则已配置。

**输入**：待提交的账号信息（平台、账号名、凭据、标签、归属）、平台注册方式（邮箱、手机接码、虚拟号）、维护任务（发帖、关注、浏览）、账号状态变更事件。

**输出**：入库的账号记录、账号可用性与风险评估结果、维护执行记录、注册成功的账号、账号最新状态。

**业务规则**：

- 账号凭据加密存储，记录归属与标签；
- 账号验证通过登录探测与状态识别，检测可用性并识别封禁、限制、需验证等风险点，输出风险等级；
- 账号日常维护按拟人化节奏模拟发帖、关注、浏览等真人行为，维持账号活跃度与权重；
- 账号注册支持邮箱注册、手机号接码注册与虚拟号注册流程；
- 账号生命周期在待登录、正常、受限、需验证、封禁、归档等状态间流转。

**异常场景**：账号被封禁或受限时自动标记状态并停止该账号相关任务；验证探测失败时记录异常并重试；维护行为触发平台验证时暂停并告警；注册流程接码或验证失败时回滚并记录。

**验收标准**：账号凭据加密存储且不落明文；账号可用性与风险等级可自动识别；维护任务可按拟人化节奏执行；三种注册流程均可走通；账号状态可按生命周期规则流转。

##### 3.1.1.3 社交媒体数据采集（FR-DC-020）

**功能目的**：从目标社交平台采集原始数据，覆盖 TikTok、Instagram、Facebook、YouTube、X 等海外社交平台，作为后续分析的数据来源。

**使用角色**：数据采集调度（按任务自动采集）、采集策略配置人员（配置采集方式与范围）。

**前置条件**：目标平台采集手段（逆向、模拟点击、官方 API、网页解析）已就绪；代理 IP 与维护账号可用。

**输入**：目标平台标识与采集任务（采集对象、范围、频率、使用的采集方式）。

**输出**：采集到的原始社交数据，包括用户信息、内容、互动数据、关系数据等。

**业务规则**：

- 对 Instagram 采用逆向方式采集推荐、人物、Reels 等界面数据；
- 对 TikTok、Facebook 采用模拟点击自动化采集；
- 对提供官方 API 的平台通过 API 授权采集；
- 对网页端采用页面解析采集；
- 采集过程中使用代理 IP 与维护账号，以应对平台访问限制。

**异常场景**：逆向接口失效或改版时告警并切换备用采集方式；模拟点击被风控拦截时降频或暂停；API 限流时按限额退避重试；账号被封时自动切换备用账号。

**验收标准**：各平台可通过对应采集手段获取数据；采集过程可使用代理与账号应对访问限制；采集异常可告警并切换备选手段。

##### 3.1.1.4 数据处理与存储（FR-DC-021 ~ 022）

**功能目的**：对采集到的原始数据进行清洗加工并持久化存储，提供标准的大数据 ETL 链路，完成数据的抽取、转换与加载。

**使用角色**：系统（自动执行 ETL 流程）、数据分析人员（消费加工后的数据）。

**前置条件**：Spark 或 MapReduce 计算集群可用；HBase、关系型数据库与图数据库可写入。

**输入**：采集到的原始数据。

**输出**：清洗加工后的结构化数据，持久化于 HBase 与关系库中，可供分析与检索使用。

**业务规则**：

- 基于 Spark 或 MapReduce 进行分布式批处理计算，完成数据清洗、字段提取、格式标准化、去重与关联；
- 处理结果写入 HBase 列式数据库，元数据与索引写入关系型数据库，关系数据写入图数据库。

**异常场景**：计算节点失败时任务自动重试或转移；写入 HBase 或关系库失败时数据进入重试队列；数据格式异常时隔离坏数据并记录。

**验收标准**：原始数据可经分布式计算完成清洗与标准化；结果可正确写入 HBase、关系库与图数据库；处理过程对节点失败具备重试能力。

##### 3.1.1.5 数据分析与情报（FR-DC-023 ~ 029）

**功能目的**：对加工后的数据进行分析，提供从群体到个体的筛选、关系图谱、情报检索、可视化与文本智能分析能力，支撑目标识别与内容研判。

**使用角色**：情报分析人员（检索、筛选与研判）、系统（自动执行分析与建模）。

**前置条件**：加工后的数据已就绪；AI 算法、文本模型与关键词库已配置；图数据库可用。

**输入**：加工后的数据、群体特征条件、实体标识、检索条件、待分析的文本内容与关键词库。

**输出**：目标个体集合、关系图谱、实体信息列表、关联拓扑与情报信息、实体档案视图、文本分类与筛选结果、可视化展示界面。

**业务规则**：

- 结合人工智能算法实现从群体到个体的逐层下钻筛选，从大范围群体中定位目标个体；
- 基于实体与关联数据绘制关系图谱并支持图查询；
- 提供基础信息检索，按账号、昵称、标识等检索实体信息；
- 对给定实体输出关联拓扑与情报标签，形成关联网络；
- 聚合多来源信息形成实体的全维度档案；
- 对文本内容结合文本模型与关键词库进行规则匹配与分类筛选，用于内容研判与目标识别。

**异常场景**：算法推理超时或失败时降级返回部分结果并告警；图谱查询数据量过大时分页或限流；文本模型不可用时回退到关键词规则匹配。

**验收标准**：群体到个体的筛选可逐层下钻定位目标；关系图谱可绘制并支持图查询；实体信息可多维度检索与聚合；文本可经模型与关键词库分类筛选；分析结果可可视化展示。

#### 3.1.2 多设备矩阵自动化群控子系统（MC）

本子系统定位为"设备执行网关与调度引擎"，是所有设备动作的唯一收口。子系统以开发方案 V1.1 为依据展开，核心职责为：统一管理安卓设备矩阵的接入、远程控制、指纹与代理隔离；提供脚本模式与智能体模式两种执行引擎；以执行网关的形式收口所有落到设备的动作，保证每一个动作可观测、可审计、可熔断。

子系统遵循两条基本原则。其一，动作收口原则：无论动作来自脚本引擎还是智能体引擎，所有设备动作（点击、输入、滑动、安装、发布等）均经执行网关落地，执行网关负责鉴权、记录、熔断与转发，动作日志全量上报运维监控子系统。其二，推理与执行分离原则：智能体模式下的视觉推理由智能体直连私有化推理服务（IRS）完成，不经执行网关；推理产出的动作指令再经执行网关落地，从而兼顾推理的低延迟与执行的可观测。

##### 3.1.2.1 设备管理（FR-MC-001 ~ 007）

**功能目的**：统一管理云手机、ARM 板卡、真实安卓手机与安卓模拟器等多类型设备的接入、分组、状态监控、风控分级与基础操作，为远控、群控与任务执行提供设备资源池，并按硬件指纹真实度为养号等高敏感场景提供设备选型依据。

**使用角色**：设备运维人员（注册与维护设备）、任务调度（按分级选设备）、运营人员（批量操作）。

**前置条件**：设备可安装 Agent 或可被接入；对象存储可用；风控分级规则已配置。

**输入**：设备标识与 Agent 信息、分组与标签规则、设备指标心跳、设备风控分级规则、针对设备集合的批量操作指令。

**输出**：设备台账、设备分组关系、设备实时状态视图、设备风控分级标签、批量操作执行结果。

**业务规则**：

- Agent 启动后向服务端注册并建立长连接，系统记录设备类型（区分虚拟移动端与实体移动端）、版本、型号、分组与标签；
- 系统持续采集并监控设备的在线与离线状态、电量、CPU、内存、存储与网络状态；
- 系统支持网页端接入；
- 系统按硬件指纹真实度对设备风控分级：真机与 ARM 板卡为高真实度等级，云手机为中等级，模拟器为低等级；养号等风控敏感场景优先选用高真实度等级设备；
- 系统支持对设备集合批量安装与卸载 App、批量重启、批量截图，以及通过对象存储临时链接进行文件上传与下载。

**异常场景**：Agent 掉线时标记设备离线并告警；设备指标异常（过热、存储满）时隔离并停止派发任务；批量操作部分失败时记录失败项并支持重试。

**验收标准**：多类型设备可注册接入并建立长连接；设备状态与指标可实时监控；风控分级可按规则打标且养号优先选用高真实度设备；批量操作可执行并返回结果。

##### 3.1.2.2 远程控制（FR-MC-010 ~ 014）

**功能目的**：对单台及多台设备提供低延迟的实时画面预览与输入控制，并支持多设备同屏监控，用于人工介入与设备操作。

**使用角色**：运营人员（远程操作设备）、监控人员（宫格监控）。

**前置条件**：目标设备在线且 Agent 正常；WebRTC SFU 可用；远控权限已授权。

**输入**：远控请求、目标设备标识、操作人员的鼠标与键盘输入事件。

**输出**：设备实时画面流、被翻译并执行的设备事件、截图与录屏文件、多设备宫格预览画面。

**业务规则**：

- 屏幕画面基于 WebRTC 传输，远程控制通道与任务执行通道相互分离以保证稳定性；
- 操作人员的鼠标与键盘事件映射为设备的触摸、点击、滑动、输入及返回键、Home 键、多任务键事件；
- 系统支持由 Agent 采集的截图与录屏，并支持保存与回看；
- 多设备宫格监控以低码率同屏预览多台设备；
- 剪贴板在操作端与设备间双向同步。

**异常场景**：WebRTC 断流时自动重连或降级；输入事件丢失时补传；弱网下自动降帧以保证可用性。

**验收标准**：单设备远控端到端延迟不大于 300 毫秒；鼠标键盘事件可正确映射为设备事件；截图录屏可采集保存；多设备宫格可同屏预览；剪贴板可双向同步。

##### 3.1.2.3 执行网关与双执行模式（FR-MC-020 ~ 024）

**功能目的**：以执行网关作为所有设备动作的唯一收口，提供脚本模式与智能体模式两种执行引擎，分别承载固定流程驱动与大模型实时决策驱动的作业，并支持群控、养号与内容投放三类执行目标。

**使用角色**：任务调度（下发作业指令）、智能体引擎（自主决策动作）、脚本引擎（按流程执行动作）。

**前置条件**：执行网关服务可用；智能体模式下 IRS 推理服务可用；目标设备与账号已绑定。

**输入**：作业指令（来自脚本模式或智能体模式）、目标设备组、内容素材、目标账号与设备。

**输出**：脚本模式执行结果、智能体模式执行结果、养号执行记录、内容投放执行记录、执行网关的动作日志与熔断记录。

**业务规则**：

- 脚本模式由预先编写的固定流程驱动设备动作，适用于流程确定、高频、批量的作业；智能体模式由设备端 Agent 直连私有化推理服务进行视觉推理与规划，自主决策下一步动作，适用于流程复杂、需理解界面、抗界面变化的作业；两种模式共用底层控制通道（ADB、无障碍服务等）；
- 所有设备动作均经执行网关落地：执行网关对动作鉴权，校验动作来源与目标设备的合法性；对动作记录，写入动作日志并全量上报运维监控子系统；对异常动作熔断，在检测到风控信号或异常频率时停止后续动作；
- 智能体模式下的视觉推理由 Agent 直连私有化推理服务完成，不经执行网关；推理产出的动作指令再经执行网关落地；
- 群控对多台设备同步控制并统一投放内容；养号按拟人化节奏模拟真人行为，其拟人化策略由蜂群智能体子系统提供，动作执行收口于执行网关；内容投放下发并发布内容素材到目标账号。

**异常场景**：执行网关过载时按优先级限流；智能体推理失败时降级为脚本模式或人工介入；动作触发风控信号时熔断并告警；设备掉线时挂起任务待恢复续接。

**验收标准**：脚本模式与智能体模式均可驱动设备动作；所有动作经执行网关鉴权、记录、转发；执行网关可对异常动作熔断；智能体推理直连 IRS 且不经执行网关；三类执行目标（群控、养号、投放）均可闭环。

##### 3.1.2.4 账号管理（FR-MC-030 ~ 032）

**功能目的**：在群控侧管理账号与设备的绑定、登录状态及操作记录，复用数据爬取子系统维护的账号池，支撑账号在设备上的作业与审计。

**使用角色**：账号运营人员（绑定账号）、系统（记录登录与操作）、审计人员（查阅记录）。

**前置条件**：账号池（来自 DC）可用；目标设备已注册。

**输入**：账号与设备的绑定关系、账号登录事件、账号操作（发帖、关注、浏览等）。

**输出**：账号与设备的绑定关系、登录状态记录、账号操作记录。

**业务规则**：

- 系统将账号绑定到具体设备并记录绑定关系；
- 系统记录账号在设备上的登录状态及其变化；
- 系统记录账号的各项操作，供审计与风控分析使用。

**异常场景**：账号登录失败时记录原因并标记；账号在设备上被封时解绑并告警；操作记录写入失败时暂存重试。

**验收标准**：账号可绑定到设备并查询绑定关系；登录状态变化可记录；账号操作可留痕供审计。

##### 3.1.2.5 内容管理（FR-MC-040 ~ 042）

**功能目的**：管理投放所需的内容素材、发布排期与发布审核，保障投放内容的分类有序与合规。

**使用角色**：内容运营人员（上传与排期素材）、审核人员（发布前审核）。

**前置条件**：对象存储可用；敏感词库已配置；目标平台规格已知。

**输入**：图片、视频、文案等素材，素材的标签与平台分类信息，发布排期，待发布内容。

**输出**：素材记录、发布排期、内容审核结果。

**业务规则**：

- 系统对素材分类管理，支持标签、平台分类与账号适配；
- 系统支持按素材、账号与时间制定定时发布排期；
- 发布前对内容进行审核与敏感词检测。

**异常场景**：素材上传失败时支持断点续传；敏感词命中时拦截并标记待人工复核；排期冲突时提示调整。

**验收标准**：素材可分类管理与平台适配；发布排期可定时触发；内容可经审核与敏感词检测后发布。

##### 3.1.2.6 任务管理（FR-MC-050 ~ 054）

**功能目的**：把操作意图转换为设备可执行的任务并进行调度，支撑各类作业的排队、分发、重试与定时执行。

**使用角色**：运营人员（创建任务）、任务调度（自动分发）、系统（状态流转）。

**前置条件**：消息队列可用；目标设备或设备组已就绪。

**输入**：任务定义（任务类型、目标设备或设备组、参数、优先级）、计划任务的 Cron 表达式、任务状态变更事件。

**输出**：任务实例、任务调度分发结果、任务执行结果、任务最新状态。

**业务规则**：

- 系统按任务定义选择设备或设备组，生成任务实例并入消息队列，由调度器分发到设备 Agent 执行；
- 支持的任务类型包括 App 安装与启动、文件分发、内容发布、截图、数据采集、自动化脚本、设备巡检与账号状态检查；
- 任务在待执行、排队中、执行中、成功、失败、已取消、超时、部分成功等状态间流转；
- 系统支持失败重试、重试次数与超时配置；
- 计划任务支持一次性、每日、每周与自定义 Cron，并支持最大并发数与任务优先级控制。

**异常场景**：任务执行失败时按配置重试；任务超时时标记超时并告警；队列积压时按优先级调度并告警。

**验收标准**：任务可创建并生成实例入队分发；八种任务状态可正确流转；失败可重试且超时可配置；计划任务可按 Cron 定时触发并支持并发与优先级。

##### 3.1.2.7 执行引擎·脚本模式（FR-MC-060 ~ 063）

**功能目的**：提供脚本模式下的执行引擎，覆盖从模板任务到可视化工作流再到脚本开发的递进式自动化能力，产出的动作指令经执行网关落地。

**使用角色**：脚本开发者（编写与调试脚本）、运营人员（选用模板或工作流）、系统（执行脚本）。

**前置条件**：执行网关可用；调试设备已接入；脚本沙箱已配置。

**输入**：模板任务选择、工作流流程定义、脚本代码与调试设备、平台界面与操作序列。

**输出**：模板任务执行结果、工作流执行编排结果、脚本调试结果、模拟点击自动化执行结果。

**业务规则**：

- 第一阶段提供模板化任务，包括打开 App、等待页面、点击、输入文本、上传文件、截图、返回、滑动、关闭 App、设备巡检与 App 状态检测；
- 第二阶段提供可视化工作流编排，节点包括开始、设备选择、启动 App、等待、点击、输入、滑动、截图、文件上传、条件判断、循环、HTTP 请求、日志、审批与结束；
- 第三阶段支持脚本开发与调试，提供脚本编辑、调试设备、执行日志、截图回放与版本管理；
- 系统针对 TikTok、Facebook 等平台实现模拟点击自动化；
- 脚本引擎产出的动作指令均经执行网关鉴权、记录与转发，不直接操作设备。

**异常场景**：脚本执行异常时捕获错误并记录；脚本越权访问敏感路径时沙箱拦截；调试设备掉线时暂停调试。

**验收标准**：三阶段能力（模板、工作流、脚本开发）均可用；脚本动作均经执行网关落地且不直接操作设备；模拟点击可在目标平台执行。

##### 3.1.2.8 可观测性（FR-MC-070 ~ 073）

**功能目的**：满足集群控制对可观测性的硬性要求，使设备、账号、任务的每一个动作都可知、可追溯，支撑记录、回传、告警与审计。

**使用角色**：运维与审计人员（查阅日志与审计）、系统（自动记录与告警）。

**前置条件**：日志采集与上报通道可用；告警通道已配置。

**输入**：设备动作事件、任务执行过程、异常事件、用户与系统的操作。

**输出**：动作日志、任务执行日志与截图、异常告警通知、可追溯的审计记录。

**业务规则**：

- 每一个设备动作（点击、输入、安装、发布等）均留痕，记录时间、设备、账号与结果；
- Agent 回传任务执行日志与关键步骤截图；
- 任务失败、设备掉线、账号异常等异常事件触发告警通知；
- 系统对用户与系统操作记录审计日志，记录谁在何时对哪台设备或账号做了什么。

**异常场景**：日志上报失败时本地暂存待重试；告警通道失效时降级为本地记录；审计日志写入失败时阻塞相关操作以保证不丢审计。

**验收标准**：每个设备动作可留痕并记录时间、设备、账号、结果；任务日志与截图可回传；异常可触发告警；用户与系统操作可审计追溯。

##### 3.1.2.9 设备环境与风控对抗（FR-MC-080 ~ 083）

**功能目的**：管理设备环境并应对平台风控，通过指纹管理、风控识别、代理分配与环境隔离，降低账号与设备被处置的风险。

**使用角色**：设备运维人员（配置指纹与代理）、系统（识别风控并隔离环境）。

**前置条件**：设备指纹与代理资源可用；风控信号识别规则已配置。

**输入**：设备环境参数、风控信号、代理分配策略、设备集合的隔离要求。

**输出**：设备的指纹配置、风控规避策略、代理绑定关系、设备环境隔离配置。

**业务规则**：

- 系统管理设备的硬件与软件指纹，支持按需配置；
- 系统识别平台风控信号并采取规避与应对策略；
- 系统为设备分配独立代理 IP 以实现网络环境隔离；
- 系统对设备间的环境（指纹、网络、账号）进行相互隔离，避免关联。

**异常场景**：指纹配置冲突时告警并提示；风控信号持续触发时降级或暂停该设备任务；代理失效时切换备用代理。

**验收标准**：设备指纹可按需配置；风控信号可识别并触发规避策略；设备可绑定独立代理；设备间环境可相互隔离。

#### 3.1.3 运维监控子系统（OM）

##### 3.1.3.1 日志与指标汇聚（FR-OM-001 ~ 002）

**功能目的**：汇聚数据爬取子系统、群控子系统及平台自身的日志与指标，形成统一的运维数据底座，支撑全系统可观测。

**使用角色**：运维人员（检索日志与查看指标）、系统（自动采集与汇聚）。

**前置条件**：各子系统日志采集 Agent 与指标采集器已部署；日志库与时序数据库可用。

**输入**：各子系统产生的日志与系统运行指标。

**输出**：统一日志库与时序指标数据。

**业务规则**：

- 系统通过日志采集将各子系统日志汇聚至统一日志库，支持全文检索；
- 系统通过指标采集器采集设备在线率、任务成功率、爬虫吞吐量、队列积压等指标，形成时序数据。

**异常场景**：日志采集 Agent 离线时本地暂存待恢复上报；指标采集超时时降级采样；日志库写入失败时进入重试队列。

**验收标准**：各子系统日志可汇聚至统一日志库并支持全文检索；关键指标可采集为时序数据；近 7 日日志检索响应不大于 3 秒。

##### 3.1.3.2 告警与运维（FR-OM-003 ~ 005）

**功能目的**：基于指标与规则产生告警，并通过仪表盘与运维操作支持常态化运维。

**使用角色**：运维人员（配置告警规则、查看看板、执行运维操作）。

**前置条件**：时序指标数据可用；告警规则与通知渠道已配置。

**输入**：告警规则与指标、运维操作请求。

**输出**：告警事件、可视化看板、运维操作记录。

**业务规则**：

- 系统支持阈值告警与异常检测告警，并通过多渠道通知；
- 系统提供总览、设备、任务、爬虫、异常等多维可视化看板；
- 系统支持日志查询、故障定位、巡检与容量观测等常态化运维操作。

**异常场景**：告警风暴时按规则聚合去重；通知渠道失效时降级为备用渠道；看板数据加载超时时降级展示缓存。

**验收标准**：阈值与异常检测告警可触发并多渠道通知；多维看板可可视化展示；日志查询、故障定位、巡检、容量观测等运维操作可执行。

#### 3.1.4 公共功能（COM）

##### 3.1.4.1 用户认证与权限（FR-COM-001 ~ 003）

**功能目的**：为各子系统提供统一的用户认证、基于角色的访问控制与组织管理，支持多组织的数据隔离。

**使用角色**：超级管理员（管理组织与角色）、各角色用户（登录与操作）。

**前置条件**：用户与角色数据已初始化；双因素认证通道可用。

**输入**：用户账号与密码或双因素凭证、角色与权限配置、组织与成员信息。

**业务规则**：

- 系统对多组织或多租户进行数据隔离。

**异常场景**：登录密码错误超限时锁定账号；双因素验证失败时拒绝并记录；越权访问时拦截并审计。

#### 3.1.5 蜂群智能体子系统（SWM）

蜂群智能体子系统是执行层的"智能来源"，为设备作业提供账号人格与作业策略。子系统实现智能体账号管理、蜂群任务智能分发、行为仿真与防伪装、集群负载均衡与离线保活、投送频次管控、作业效果统计，以及 MCP 管理、提示词管理与记忆管理。

本子系统不直接操作设备，所有设备动作均收口于群控子系统的执行网关。子系统的产出按执行模式有所不同：在智能体模式下，本子系统向设备端 Agent 下发人设标签、提示词与作业策略，Agent 据此自主决策（视觉推理直连私有化推理服务 IRS），产出的动作指令再经执行网关落地；在脚本模式下，本子系统向脚本引擎下发作业参数（账号、时间、内容），脚本照固定流程执行，动作同样经执行网关落地。养号的拟人化节奏与防伪装策略由本子系统提供，具体动作执行由群控子系统承担。

##### 3.1.5.1 智能体账号分层分组与人设管理（FR-SWM-010 ~ 012）

**功能目的**：对蜂群中的智能体账号进行分层分组、人设标签绑定与生命周期管理，形成可控的账号层级结构与人格化画像。

**使用角色**：账号运营人员（配置分组与人设）、系统（自动流转状态）。

**前置条件**：账号池（来自 DC）可用；人设标签体系已定义。

**输入**：账号清单、分组与层级结构定义、人设标签定义、账号状态变更事件。

**输出**：智能体账号的层级分组结构、人设标签绑定关系、账号最新生命周期状态。

**业务规则**：

- 系统对智能体账号按业务目标、平台、地区、风险等级等维度分层分组，形成可控的账号层级结构；
- 系统为每个智能体账号绑定人设标签，标签涵盖身份特征、立场倾向、语言风格、兴趣领域等画像属性；
- 系统管理智能体账号的状态生命周期，状态包括待激活、活跃、休眠、受限、封禁、回收等，支持状态间的自动与人工流转。

**异常场景**：账号被封禁时自动流转至封禁状态并停止作业；人设标签冲突时提示人工裁定；分组调整失败时回滚。

**验收标准**：账号可按多维度分层分组；人设标签可绑定且涵盖画像属性；生命周期状态可自动与人工流转。

##### 3.1.5.2 蜂群任务智能分发（FR-SWM-020 ~ 022）

**功能目的**：将作战任务智能分发给蜂群中的智能体账号，支持分时投送与碎片化仿真作业调度，降低批量特征。

**使用角色**：作战指挥人员（下达作战任务）、系统（智能匹配与分发）。

**前置条件**：智能体账号池与人设标签已就绪；投送策略已配置。

**输入**：作战任务（含目标、内容、受众、时间窗口）、智能体账号池及其人设标签、投送策略。

**输出**：任务分发计划、分时投送排程、碎片化作业执行序列。

**业务规则**：

- 系统根据任务目标与人设标签进行智能体与任务的匹配，实现蜂群任务的智能分发；
- 系统支持分时投送，按预设时间窗口分散下发，避免瞬时集中；
- 系统将任务拆解为碎片化的离散动作，以拟人化的随机节奏分批调度执行，形成碎片化仿真作业轨迹，降低批量特征。

**异常场景**：匹配不到合适智能体时告警并降低任务优先级；分时窗口错过时顺延至下一窗口；碎片化作业中断时续接未完成动作。

**验收标准**：任务可按人设标签智能匹配分发；可按时间窗口分时投送；任务可拆解为碎片化动作并以拟人化节奏执行。

##### 3.1.5.3 智能体行为仿真与防伪装（FR-SWM-030 ~ 032）

**功能目的**：实现智能体账号与社交账号的联动，模拟随机行为并对批量特征进行伪装，降低被风控识别的概率。

**使用角色**：系统（自动执行仿真与伪装）。

**前置条件**：智能体账号已绑定人设；行为模型参数已配置；设备已接入执行网关。

**输入**：智能体账号当前状态、社交平台行为上下文、行为模型参数、待伪装的操作批次。

**输出**：联动一致的智能体行为序列、随机化的作业轨迹、防伪装后的操作批次。

**业务规则**：

- 系统建立智能体与其社交账号的联动机制，使账号行为与其人设标签保持一致；
- 系统在作业动作之间注入随机浏览、停留、互动等真人行为，模拟真实用户的操作轨迹；
- 系统对账号的操作在时间间隔、操作频率、内容措辞、设备特征等维度进行防批量特征伪装，打散同质化特征，规避平台批量检测。

**异常场景**：仿真行为触发平台验证时暂停并告警；伪装参数失效时更新模型；行为与人设偏离时纠正。

**验收标准**：账号行为可与人设标签联动一致；作业动作间可注入随机真人行为；操作可在时间、频率、内容、设备等维度打散同质化特征。

##### 3.1.5.4 集群负载均衡与离线保活（FR-SWM-040 ~ 042）

**功能目的**：保障蜂群集群稳定运行，实现负载均衡、任务容错重传与离线保活。

**使用角色**：系统（自动调度与保活）。

**前置条件**：集群节点与设备状态可采集；重试与保活策略已配置。

**输入**：集群中各智能体节点与设备的负载状态、任务执行状态、设备在线状态。

**输出**：负载均衡调度结果、任务重传记录、离线保活与续接结果。

**业务规则**：

- 系统对各节点与设备的负载进行均衡调度，避免单点过载，保证作业分散执行；
- 系统对执行失败或中断的任务进行容错重传，按重试策略重新分发；
- 系统在智能体或设备离线时启动保活机制，维持账号登录态与心跳，并在恢复后自动续接未完成任务。

**异常场景**：节点持续过载时迁移任务；重传超过次数时标记失败并告警；保活心跳丢失时标记账号待重新登录。

**验收标准**：负载可均衡调度避免单点过载；失败任务可容错重传；离线时可保活并在恢复后续接任务。

##### 3.1.5.5 投送频次管控与时段智能适配（FR-SWM-050 ~ 052）

**功能目的**：对智能体的投送频次进行管控，并根据平台风控规律智能适配投送时段，规避风控。

**使用角色**：作战指挥人员（配置频次与策略）、系统（自动适配时段）。

**前置条件**：平台风控规律数据已积累；账号历史行为数据可用。

**输入**：各平台的风控规律、账号历史行为数据、投送任务计划、账号风险状态。

**输出**：投送频次管控配置、时段智能适配排程、规避风控的策略调整。

**业务规则**：

- 系统按账号、平台、内容类型对投送频次进行管控，设置单账号单日操作上限与冷却间隔；
- 系统结合平台风控规律与账号历史，智能适配最优投送时段，将作业分配到风险较低的时段执行；
- 系统在检测到风控信号时动态调整投送策略，规避高风险时段与操作。

**异常场景**：频次超限时拒绝并排队；风控信号持续时暂停该账号投送；时段适配无解时降级为人工选择。

**验收标准**：投送频次可按账号/平台/内容类型管控并设上限与冷却；时段可智能适配到低风险窗口；风控信号可触发策略调整。

##### 3.1.5.6 蜂群作业统计与复盘（FR-SWM-060 ~ 062）

**使用角色**：作战指挥与运营人员（查阅统计与复盘）、系统（自动统计与回传）。

**前置条件**：蜂群作业执行记录可采集；效果回调接口已对接上游。

**输入**：蜂群作业执行记录、投放内容表现数据、任务执行日志。

**输出**：蜂群作业统计报表、任务复盘结果、回传上游的效果回调数据。

**业务规则**：

- 系统对蜂群作业进行多维统计，包括任务完成率、内容触达、互动表现、账号健康度等；
- 系统支持任务复盘，对失败任务、异常账号、低效作业进行归因分析；
- 系统将投送效果数据通过回调机制联动回传至舆情作战子系统，供效果评估闭环使用。

**异常场景**：统计数据缺失时标注不完整；复盘归因无解时标记待人工分析；回调上游失败时暂存重试。

**验收标准**：蜂群作业可多维统计；失败任务可归因复盘；效果数据可回调回传上游形成闭环。

**验收标准**：蜂群资源可集中纳管与调度；操作可按角色与任务范围权限控制；任务池可接收排队分发回收；资源可按负载动态分配。

- 系统按多语种、多场景、多风格组织舆论作业策略库；
- 系统对策略进行分类管理与版本控制；
- 系统根据作业效果反馈对策略进行迭代优化；
- 系统支持策略的场景适配与动态调用。

输出为多语种多场景多风格的舆论作业策略库、策略版本记录，以及迭代优化结果。

#### 3.1.8 外部接口需求

系统应提供与外部系统交互的接口。其一，系统应通过逆向、模拟点击与官方 API 等方式与 TikTok、Instagram、Facebook、YouTube、X 等社交平台交互（EI-01）。其二，系统应对接 VPS 代理链路与代理 IP 供应商，获取代理网络出口（EI-02）。其三，系统应对接手机号接码与虚拟号服务，用于账号注册（EI-03）。其四，系统应对接第三方云手机供应商 API，获取云手机实例（EI-04）。其五，系统应对接 MinIO 或阿里云 OSS 等对象存储，存储素材、截图与录屏（EI-05）。其六，系统应在大模型层面实现私有化部署，不依赖外部公有云模型服务，相关推理能力由私有化推理服务子系统（IRS）内部提供（EI-06）。所有外部接口均应使用鉴权与传输加密。

#### 3.1.9 内部接口需求

子系统间及子系统内部应通过明确的接口交互。数据爬取子系统与群控子系统之间应提供账号池接口，群控子系统据此复用账号并绑定设备（II-01）。群控子系统的 Agent 与服务端之间应通过 WebSocket 或 MQTT 长连接下发指令并回传日志（II-02）。群控子系统与设备之间应通过 WebRTC SFU 传输远控画面与输入（II-03）。各子系统应通过日志采集 Agent 与指标采集器向运维监控子系统上报日志与指标（II-04）。数据爬取子系统内部应以 Kafka 作为数据总线，将采集数据流转至处理与存储环节（II-05）。系统应提供设备、任务、内容、账号、审计等管理的 REST 接口，供前端与外部调用（II-06）。

群控子系统的执行网关是所有设备动作的唯一收口，应提供动作执行接口，供脚本引擎与智能体引擎调用，执行网关负责对动作鉴权、记录、熔断与转发（II-07）。智能体模式下，设备端 Agent 与私有化推理服务子系统之间应提供推理直连接口，用于视觉感知与规划推理，不经执行网关，以保证低延迟（II-08）；推理产出的动作指令再经执行网关落地。蜂群智能体子系统应向设备端 Agent 提供策略下发接口，下发人设标签、提示词与作业策略（II-09）；向脚本引擎下发作业参数（账号、时间、内容）（II-10）。舆情作战子系统与蜂群智能体子系统之间应提供作战方案下发与效果回传接口，形成作战执行闭环（II-11）。群控子系统的执行网关应向运维监控子系统上报全量动作日志与熔断记录（II-12）。蜂群智能体子系统与数据爬取子系统之间应共享账号池，蜂群账号的人设标签与生命周期管理复用数据爬取侧的账号资产（II-13）。舆情作战子系统与数据爬取子系统之间应提供分析数据与情报接口，作战研判基于爬取侧的分析结果展开（II-14）。

#### 3.1.10 数据需求

系统应维护以下数据：设备数据，包括设备、设备分组与设备指标（DR-01）；账号数据，包括社交账号、登录记录与操作记录，凭据须加密存储（DR-02）；内容数据，包括素材、发布排期与发布记录（DR-03）；任务数据，包括任务、任务实例与任务日志（DR-04）；脚本与工作流数据，包括脚本、脚本版本与工作流定义（DR-05）；采集与分析数据，其中 ETL 结果存于 HBase，关系数据存于图数据库（DR-06）；审计与风险数据，包括审计日志与风险事件（DR-07）；代理与指纹数据，包括代理 IP 池与设备指纹配置（DR-08）。

蜂群智能体数据，包括智能体账号的人设标签、分层分组关系、生命周期状态、作业记忆与提示词模板版本（DR-09）。推理服务数据，包括推理请求日志、并发会话状态、KV 缓存调度记录与量化模型配置（DR-10）。舆情作战数据，包括目标识别结果、传播链路、多维画像、抓手挖掘结果、作战方案、策略库版本与效果评估记录（DR-11）。

### 3.2 非功能需求

本节给出系统的非功能需求，包括性能、安全性、保密性、可靠性、可维护性、易用性、运行环境、故障处理与约束条件。

#### 3.2.1 性能需求

系统应满足以下性能要求。单设备远程控制端到端延迟应不大于 300 毫秒，多设备宫格预览可适当放宽（NFR-P-01）。单租户应支持不少于 200 台设备的并发接入与控制（NFR-P-02）。数据爬取子系统的爬虫集群应满足业务采集量的日处理能力，并支持水平扩展（NFR-P-03）。任务从入队到分发应不超过 2 秒，并支持任务优先级与最大并发控制（NFR-P-04）。WebRTC SFU 应支持单节点并发多路远控流，并在弱网下自动降帧（NFR-P-05）。运维监控的日志检索响应应不超过 3 秒，覆盖近 7 日数据（NFR-P-06）。

私有化推理服务应支持常态 130 路、峰值 155 路的稳定并发推理会话（NFR-P-07）。推理统一网关应对推理请求进行集中接入与限流，单请求经校验、过滤到转发的处理应满足实时推理时延要求（NFR-P-08）。推理队列在突发流量下应通过削峰填谷保障稳定，异常请求重试与超时熔断不应影响其他会话（NFR-P-09）。AWQ INT4 量化模型相对原模型的精度损失应控制在可接受范围，由精度补偿算法予以弥补（NFR-P-10）。

#### 3.2.2 安全性需求

系统应满足以下安全性要求。系统应提供用户认证与双因素，并对全部 API 进行鉴权（NFR-S-01）。系统传输应全程使用 HTTPS 或 TLS，远程控制通道应加密（NFR-S-02）。账号凭据、代理凭据等敏感字段应加密存储，不得明文落库（NFR-S-03）。Agent 应进行签名校验以防止伪造设备接入，指令应签名（NFR-S-04）。脚本应运行于沙箱并配置权限白名单，禁止越权访问与读取敏感路径（NFR-S-05）。所有账号、设备、任务操作应留存审计日志，可追溯（NFR-S-06）。文件访问应使用签名 URL，限时有效（NFR-S-07）。

#### 3.2.3 保密性需求

系统应满足以下保密性要求。多组织或多租户的数据应严格隔离，禁止跨组织访问（NFR-C-01）。数据访问应遵循最小权限原则，按角色与数据范围控制（NFR-C-02）。手机号、凭据等敏感数据应脱敏展示（NFR-C-03）。数据库应定期备份，数据导出操作应审计留痕（NFR-C-04）。

#### 3.2.4 可靠性需求

系统应满足以下可靠性要求。核心服务可用性应不低于 99.5%（NFR-R-01）。任务应支持幂等与失败重试，异常任务应自动熔断（NFR-R-02）。Agent 掉线应自动重连，设备重启后 Agent 应自启动（NFR-R-03）。关键服务应高可用部署，无单点故障（NFR-R-04）。数据采集应具备补偿与断点续采能力（NFR-R-05）。

#### 3.2.5 可维护性需求

系统应满足以下可维护性要求。系统应采用模块化、服务化设计，子系统可独立部署升级（NFR-M-01）。采集、调度、频率控制、代理等关键策略应可配置，无需修改代码（NFR-M-02）。系统应提供全链路日志与追踪，故障可定位（NFR-M-03）。系统应提供运维仪表盘与告警，支持常态化运维（NFR-M-04）。

#### 3.2.6 易用性需求

系统应满足以下易用性要求。Web 管理后台界面应清晰，设备、任务、账号、内容分区明确（NFR-U-01）。批量操作应支持选择设备组并一键下发（NFR-U-02）。远程控制画面与任务日志应同屏可见（NFR-U-03）。关键操作应有确认与风险提示（NFR-U-04）。

#### 3.2.7 运行环境需求

服务端应运行于 Linux 操作系统，采用 Docker 与 Kubernetes 进行容器编排，后端采用 Java Spring Boot 或 Go。数据存储应包括 PostgreSQL 或 MySQL、Redis、Kafka、HBase、图数据库与 MinIO 或 OSS。前端应基于现代浏览器，采用 Vue3 或 React 与 TypeScript。移动端应提供 Android Agent，兼容主流 Android 版本，设备类型包括云手机、ARM 板卡、真机与模拟器。监控应采用 Prometheus、Grafana 与 ELK 或 Loki。

私有化推理服务应部署于配备 GPU 算力的私有化服务器或算力集群，满足常态 130 路至峰值 155 路并发推理的显存与算力需求；推理框架应支持 AWQ INT4 量化权重的高效加载与 MoE 专家路由；推理网关与会话管控服务应以高可用方式部署。

#### 3.2.8 故障处理需求

系统应满足以下故障处理要求。任务异常应自动熔断，停止后续执行并告警（NFR-F-01）。设备或 Agent 异常应自动隔离，不再派发任务，待恢复后重新接入（NFR-F-02）。账号发生封禁或受限等异常时，应自动停止该账号相关任务并告警（NFR-F-03）。消息中间件或数据库故障应具备重试与死信处理（NFR-F-04）。服务异常应具备降级能力，优先保障远程控制与日志通道（NFR-F-05）。

#### 3.2.9 约束条件

群控子系统应按开发方案 V1.1 分阶段落地，最小可行产品优先接入云手机与真机、实现远程控制与基础任务（CON-01）。第一阶段不自研云手机内核，优先接入第三方云手机 API（CON-02）。爬虫与 ETL 应复用现有大数据组件，包括 Kafka、Spark 与 HBase（CON-03）。蜂群智能体（SWM）、私有化推理（IRS）、舆情作战（OCC）三个子系统为本期 V2.0 新增能力，应优先实现核心闭环链路：推理底座可用、蜂群可调度执行、舆情作战可形成识别到评估的闭环（CON-04）。目标平台为海外社交平台，需考虑网络代理与合规边界（CON-05）。大模型推理应采用私有化部署，不依赖外部公有云模型服务，并采用 AWQ INT4 量化以适配自有算力（CON-06）。

所有设备动作（无论来自脚本引擎还是智能体引擎）均应经群控子系统的执行网关落地，禁止任何子系统或 Agent 绕过执行网关直接操作设备，以保证动作可观测、可审计、可熔断（CON-07）。系统应同时支持脚本模式与智能体模式两种执行引擎，养号等风控敏感场景可优先采用脚本模式，内容投放与自适应场景可采用智能体模式（CON-08）。设备应按硬件指纹真实度进行风控分级，养号等高敏感场景应优先选用真机与 ARM 板卡，云手机用于规模化采集与投放，模拟器仅用于测试（CON-09）。智能体模式下的视觉推理应直连私有化推理服务，不经执行网关；推理产出的动作指令再经执行网关落地（CON-10）。

## 4 合格性规定

### 4.1 验证方法

系统应采用评审、演示、测试与分析相结合的方法进行合格性验证。评审用于对需求与设计文档进行相关方确认。演示用于对设备接入、远程控制、群控、采集与可视化等能力进行现场展示。测试用于对功能、接口、性能与安全进行验证。分析用于对日志、指标与审计记录进行分析确认。

### 4.2 验证条件

合格性验证应在部署完整的各子系统及其依赖组件的测试环境中进行。环境应接入不少于规定数量的测试设备，包括云手机与真机，以及测试账号。应准备目标平台的测试数据与代理 IP 资源。私有化推理服务应部署满足并发会话规模（常态 130 路、峰值 155 路）的 GPU 算力环境，并加载 AWQ INT4 量化模型。蜂群智能体与舆情作战子系统应接入测试智能体账号与作战场景数据。

### 4.3 验证准则

验证应以本文件的需求为准则。功能需求应逐项验证通过。非功能需求应达标，其中性能指标应经实测满足，安全项应无高危问题。各子系统接口应联通，日志与指标应正常上报至运维监控子系统。验证应无遗留的致命与严重缺陷。

## 6 附录

### 6.1 需求编号说明

FR-DC-NNN 表示数据爬取子系统功能需求，FR-MC-NNN 表示多设备矩阵自动化群控子系统功能需求，FR-OM-NNN 表示运维监控子系统功能需求，FR-COM-NNN 表示公共功能需求，FR-SWM-NNN 表示蜂群智能体子系统功能需求，FR-IRS-NNN 表示私有化推理服务子系统功能需求，FR-OCC-NNN 表示舆情作战业务子系统功能需求。NFR-P、NFR-S、NFR-C、NFR-R、NFR-M、NFR-U、NFR-F 分别表示性能、安全、保密、可靠性、可维护性、易用性与故障处理的非功能需求。EI、II、DR、CON 分别表示外部接口、内部接口、数据与约束。

子系统代号对照：DC（Data Crawler，数据爬取）、MC（Multi-device Control，多设备群控）、OM（Ops Monitor，运维监控）、COM（Common，公共功能）、SWM（Swarm，蜂群智能体）、IRS（Inference Service，私有化推理服务）、OCC（Opinion Combat Command，舆情作战业务）。
