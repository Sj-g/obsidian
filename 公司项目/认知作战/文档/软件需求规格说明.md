## 1 引言

### 1.1 标识

本软件命名为"认知作战平台 v1.0"（以下简称"系统"或"平台"）。系统由三个相互协作的子系统组成：数据爬取子系统、多设备矩阵自动化群控子系统、运维监控子系统。本文件给出系统的软件需求规格说明（SRS），作为概要设计、详细设计、开发实现与验收确认的依据。

> 说明：本文档为**对内**技术需求文档，如实描述系统各能力的真实用途与边界，供研发团队开发与验收使用。

### 1.2 软件概述

平台面向社交媒体，构建"数据采集 → 分析研判 → 编队执行 → 运维保障"的完整能力链。v1.0 由三大子系统构成：

| 子系统 | 代号 | 定位 |
| --- | --- | --- |
| 数据爬取子系统 | DC（Data Crawler） | 情报输入端。负责爬取工程底座、账号维护、社交媒体数据 ETL 与分析 |
| 多设备矩阵自动化群控子系统 | MC（Multi-device Control） | 执行端。基于安卓设备矩阵，实现远程控制、群控、养号、数据兜底与内容投放，全程可观测 |
| 运维监控子系统 | OM（Ops Monitor） | 保障端。汇聚多系统日志与指标，完成常态化运维 |

子系统间关系：

```text
[数据爬取 DC] 账号维护 ──共享账号池──→ [群控 MC] 养号 / 内容投放
[数据爬取 DC] 数据采集 ←──数据兜底─── [群控 MC] 移动端 / 网页端
[三个子系统] 日志 / 指标 ──────────────→ [运维监控 OM]
```

账号是 DC 与 MC 的共享资产：DC 侧负责账号注册、验证与风险评估，MC 侧负责通过养号维持账号存活，并通过设备矩阵执行投放。

### 1.3 文档概述

本文档按 GB/T 8567 结构编写。第 1 章给出标识、概述与术语；第 2 章列出引用文件；第 3 章给出功能与非功能需求（核心）；第 4 章规定合格性验证方法；第 5 章给出需求追踪关系；第 6 章为附录。功能需求采用 `FR-XX-NNN` 编号（XX 为子系统代号），非功能需求采用 `NFR-N` 编号，便于需求追踪与测试覆盖。

### 1.4 术语和缩略语

| 术语/缩略语 | 含义 |
| --- | --- |
| 群控 | 对多台移动设备进行集中、同步、批量控制 |
| 智能体控制 | 设备端部署 Agent，按服务端下发策略自主执行任务 |
| 养号 | 通过模拟真人行为（发帖、关注、浏览等）维持社交账号活跃度与可信度 |
| 数据兜底 | 在常规爬取不可达时，由移动端/网页端作为补充采集手段 |
| 逆向 | 对目标 App 的网络协议或界面结构进行分析，以获取数据或实现自动化 |
| 风控 | 社交平台对异常/自动化行为的检测与处置机制 |
| 设备指纹 | 标识设备身份的硬件/软件特征集合 |
| 云手机 | 云端虚拟化或容器化的安卓实例 |
| ARM 板卡 | 集成 ARM 芯片的安卓主板设备（板卡云机） |
| Agent | 部署在终端设备上、与服务端通信并执行指令的代理程序 |
| ADB | Android Debug Bridge，安卓调试桥 |
| WebRTC | 支持浏览器/移动端实时音视频通信的协议，用于远程控制画面传输 |
| ETL | Extract-Transform-Load，数据抽取-转换-加载 |
| RBAC | Role-Based Access Control，基于角色的访问控制 |
| K8s | Kubernetes，容器编排平台 |
| Kafka / Redis / HBase / Spark | 分别为消息中间件 / 缓存与键值存储 / 列式数据库 / 分布式计算引擎 |
| SRS | 软件需求规格说明（Software Requirements Specification） |

| EI-03 | 与接码/虚拟号服务接口 | 对接手机号接码、虚拟号服务用于账号注册 |
| EI-04 | 与云手机供应商接口 | 对接第三方云手机 API（第一阶段） |
| EI-05 | 与对象存储接口 | 对接 MinIO / 阿里云 OSS 存储素材、截图、录屏 |
| EI-06 | 与 AI 模型服务接口 | 对接文本模型用于文本智能分析 |

### 3.3 内部接口需求

| 编号 | 接口 | 说明 |
| --- | --- | --- |
| II-01 | DC ↔ MC 账号池接口 | MC 复用 DC 维护的账号，按账号绑定设备 |
| II-02 | MC Agent ↔ 服务端指令接口 | 基于 WebSocket / MQTT 长连接下发指令、回传日志 |
| II-03 | MC ↔ 设备 WebRTC 接口 | 基于 WebRTC SFU 传输远控画面与输入 |
| II-04 | 各子系统 → OM 日志/指标接口 | 通过日志采集 Agent 与 Prometheus exporter 上报 |
| II-05 | DC 内部 Kafka 数据总线 | 爬取数据经 Kafka 流转至处理与存储 |
| II-06 | REST API | 设备、任务、内容、账号、审计等管理接口（详见概要设计） |

### 3.5 性能需求

| 编号 | 指标 | 要求 |
| --- | --- | --- |
| NFR-P-01 | 远控延迟 | 单设备远控端到端延迟 ≤ 300ms；宫格预览可放宽 |
| NFR-P-02 | 群控并发 | 单租户支持 ≥ 200 台设备并发接入与控制 |
| NFR-P-03 | 爬虫吞吐 | DC 爬虫集群日处理能力满足业务采集量，水平可扩展 |
| NFR-P-04 | 任务调度 | 任务从入队到分发 ≤ 2s；支持任务优先级与最大并发控制 |
| NFR-P-05 | WebRTC 并发 | SFU 支持单节点并发多路远控流，弱网自动降帧 |
| NFR-P-06 | 日志检索 | OM 日志检索响应 ≤ 3s（近 7 日数据） |

### 3.6 安全性需求

| 编号 | 要求 |
| --- | --- |
| NFR-S-01 | 用户认证与双因素；API 全量鉴权 |
| NFR-S-02 | 传输全程 HTTPS/TLS；远控通道加密 |
| NFR-S-03 | 账号凭据、代理凭据等敏感字段加密存储，不明文落库 |
| NFR-S-04 | Agent 签名校验，防止伪造设备接入；指令签名 |
| NFR-S-05 | 脚本沙箱与权限白名单，禁止越权访问与读取敏感路径 |
| NFR-S-06 | 所有账号/设备/任务操作留审计日志，可追溯 |
| NFR-S-07 | 文件访问使用签名 URL，限时有效 |

### 3.7 保密性需求

| 编号 | 要求 |
| --- | --- |
| NFR-C-01 | 多租户/多组织数据严格隔离，禁止跨租户访问 |
| NFR-S-02 | 数据访问最小权限，按角色与数据范围控制 |
| NFR-C-03 | 敏感数据脱敏展示（如手机号、凭据） |
| NFR-C-04 | 数据库定期备份；导出操作审计留痕 |

### 3.8 可靠性需求

| 编号 | 要求 |
| --- | --- |
| NFR-R-01 | 系统可用性 ≥ 99.5%（核心服务） |
| NFR-R-02 | 任务幂等与失败重试，异常任务自动熔断 |
| NFR-R-03 | Agent 掉线自动重连；设备重启后 Agent 自启动 |
| NFR-R-04 | 关键服务高可用部署，无单点故障 |
| NFR-R-05 | 数据采集具备补偿与断点续采能力 |

| NFR-M-02 | 关键策略（采集、调度、频控、代理）可配置，无需改代码 |

### 3.11 运行环境需求

## 4 合格性规定

### 4.1 验证方法

| 方法 | 适用范围 |
| --- | --- |
| 评审 | 需求、设计文档由相关方评审确认 |
| 演示 | 设备接入、远控、群控、采集、可视化等能力现场演示 |
| 测试 | 功能测试、接口测试、性能测试、安全测试 |
| 分析 | 对日志、指标、审计记录进行分析确认 |

### 4.2 验证条件

- 测试环境部署完整三大子系统及依赖组件
- 接入不少于规定数量的测试设备（云手机/真机）与测试账号
- 准备目标平台测试数据与代理 IP 资源

### 4.3 验证准则

- 功能需求 `FR-*` 逐项验证通过
- 非功能需求 `NFR-*` 达标（性能指标实测满足、安全项无高危问题）
- 各子系统接口联通、日志与指标正常上报至 OM
- 无遗留致命与严重缺陷
