## 1. 背景

ADR-002（2026-07-16）按"终端形态"对 MC 菜单做了首次重组，新建「指纹浏览器」一级菜单组放 MC-11/12/13，新建「设置」组放 MC-03。但 ADR-002 §6 自己标注了"指纹浏览器组语义张力"风险——MC-11 养号监控、MC-12 节奏策略本质是通用养号策略（手机端也养号），归"指纹浏览器"名不副实。

后续用户给出新的设计判断：**养号、拟人化都是模板和编排的结果**，不需要独立的养号监控页和节奏策略页。这推翻了 ADR-002 的核心产物（指纹浏览器组），并引出后续一系列 MC 菜单调整。

## 2. 决策（取代 ADR-002 的对应部分）

### 决策 1：放弃"按终端形态分组"，终端形态下沉为单页操作控件

- 删除「指纹浏览器」一级菜单组（ADR-002 决策 1 的核心产物）。
- 删除「远程控制」一级菜单组；MC-17 单设备远控、MC-18 多设备宫格并入「终端资源」组。
- 删除「账号资产」一级菜单组；新建「资源」组（MC-06 账号数据 + MC-05 代理IP池）。
- 终端形态（移动端/浏览器）的差异不再用菜单分组承载，改为在 **MC-15 编排器、MC-16 脚本IDE 的 DetailHeader 加「载体切换（移动端|浏览器）」控件**，对应 ADB/无障碍 vs CDP 两种控制通道。
- 菜单组总数 **8 → 6**。

### 决策 2：删除 MC-11、MC-12、MC-19（养号/拟人是编排结果）

- **MC-11 养号监控、MC-12 节奏策略**：删除页面。理由：养号、拟人化都是模板和编排的结果，不需要独立的养号监控页和节奏策略页；养号能力以模板形态保留在 M-MC-08 编排体系（MC-14 模板库的养号模板 + MC-15 编排器执行）。
- **MC-19 执行网关熔断监控**：删除页面。网关本身是后端运行时（M-MC-05，CON-07 动作收口核心），删页面不废网关。
- 三页均**只删线框页面，需求/模块留阶段二**：R-MC-009（养号 M-MC-09）、M-MC-05（网关）的需求/模块评估留阶段二。

### 决策 3：MC-13 任务管理移回「任务与编排」组

- ADR-002 把 MC-13 移到「指纹浏览器」组并差点改名"浏览器任务"。本决策反转：**MC-13 移回「任务与编排」组，保持「任务管理」通用名**（R-MC-007 跨终端通用，强行改名会割裂手机端）。任务列表内用 terminal_type 筛选浏览器/手机。

### 决策 4：MC 最终菜单结构（6 组 13 页）

| 菜单组 | 二级页 |
| --- | --- |
| 设备总览 | MC-01 设备总览首页 |
| 终端资源 | MC-02 终端台账、MC-17 单设备远控、MC-18 多设备宫格 |
| 资源 | MC-06 账号数据、MC-05 代理IP池 |
| 任务与编排 | MC-13 任务管理、MC-14 模板库、MC-15 编排器、MC-16 脚本IDE |

另：MC-08（MC-06 详情，不进侧边栏）、MC-09/MC-10（MC-21 按钮，不进侧边栏）。

## 3. ADR-002 仍成立、未被取代的决策（保留有效）

MC-04 指纹风控删页面、MC-07 账号注册删页面、MC-08→MC-06 详情、MC-09/10→MC-21 按钮、MC-06 改名「账号数据」、MC-14 模板分浏览器/手机脚本、MC-15/16「从模板库选用」按钮、MC-21 承接 MC-09/10、新建「设置」组放 MC-03、MC-04/07 只删页面需求留阶段二——以上均保留有效。

## 4. 对其他 ADR 的影响

- **ADR-002**：状态加注「部分被 ADR-005 取代」。被取代范围：指纹浏览器组、远程控制组、账号资产组、MC-11/12/19 去留、菜单 8→6、终端形态分组思路。
- **ADR-004 §4.4 业务数据下沉**：原计划把可观测数据落到 MC-19 熔断；MC-19 已删，该落点假设失效，下沉专项须重选落点（如 MC-20 动作审计）。
