## 1. 背景

OCC 控制台原为 6 个一级菜单组 / 20 个二级页面，承载完整「目标识别 → 数据分析与情报 → 作战编排 → 效果评估 → 策略与内容」闭环。用户提出大幅精简：情报分析与策略与内容两大块为后台行为/可后置，不需要前端页面；目标档案自带关联网络信息；作战编排/效果评估各只留必要页；且全平台术语「作战」改为「行动」。

## 2. 决策

### 决策 1：OCC 控制台大幅精简（6 组/20 页 → 4 组/5 页）

| 改动 | 处理 | 背后模块（需求留阶段二） |
| --- | --- | --- |
| 情报分析组（OCC-02~05）整组删 | 4 页全删 | M-OCC-02 数据分析与情报（OCC 核心"大脑"：sklearn评分/NebulaGraph图谱/ES检索/IRS文本） |
| OCC-07 关联网络 | 并入 OCC-06 目标档案（作为属性分组卡），删独立菜单项 | M-OCC-03 关系图谱 |
| OCC-08 方案规划 | 删，作战编排组只留 OCC-09/10 | M-OCC-04 |
| OCC-11 成效看板、OCC-12 复盘报告 | 删，效果评估组只留 OCC-13 | M-OCC-06（评估） |
| OCC-13 | 保留并改名「评估」（原"中短期与长期评估"） | M-OCC-06 |
| 策略与内容组（OCC-14~20）整组删 | 7 页全删 | M-OCC-07策略库 / **M-OCC-08内容主数据(CON-11同构权威源)** / M-OCC-09审核风控 |

最终 OCC 侧边栏 4 组：行动总览(OCC-01) / 目标与网络(OCC-06，含关联网络) / 行动编排(OCC-09,10) / 评估(OCC-13)。

### 决策 2：OCC 删除类页面全部只删线框，需求/模块留阶段二

- 与 ADR-001/002 策略一致。⚠️ 重点风险：
  - **M-OCC-02（数据分析与情报）** 是 OCC 的核心分析能力，全删其页面意味着 OCC 前端失去情报分析入口，阶段二须评估这些能力是转为纯后台 API、还是保留需求但不提供 UI。
  - **M-OCC-08（内容主数据）** 是平台级权威源（与 MC 账号主数据 CON-11 同构），删其页面后内容主数据的管理入口消失，阶段二须评估内容主数据是否仍需要、由谁维护。
- 需求 R-OCC-001~009 编号本次不变，留阶段二评估去留。

### 决策 3：「作战」→「行动」（全平台术语替换）

- **阶段一范围**：只改 `.pen` 内用户可见文案——控制台品牌名（作战中心→行动中心）、菜单组名（作战总览→行动总览、作战编排→行动编排）、面包屑、页面标题/描述、总览图标题/卡片、Legend。
- **阶段二范围（重大，须专门处理）**：
  - markdown 文档全局替换「作战」→「行动」（全库 240+ 处，22 个文件），含项目名「认知作战平台」→「认知行动平台」、子系统名「舆情作战业务子系统」→「舆情行动业务子系统」、核心术语「作战单元/作战闭环/作战编排」等。
  - ⚠️ **git 仓库路径**：工作目录含「认知作战」（`公司项目/认知作战/文档`），git 根 `/home/sjg/obs/shijianguo`。改路径会破坏 Obsidian vault 配置与所有相对引用，是**文件系统级迁移**，阶段二须单独、谨慎决策（可能保留目录名只改文档内文字，避免破坏 vault）。
  - ⚠️ **语义审定**：「作战」在 SRS 与多个核心概念绑定（作战单元 = `agent_id:account_id:终端:代理IP` 四元绑定），机械替换为"行动单元"等新词须逐个审定，不是简单查找替换。

## 5. 备选方案（已否决）

- **保留情报分析/策略与内容页面**：用户明确表示情报分析是后台行为、策略与内容暂不需要前端。否决，按要求删除。
- **作战→行动 只改控制台层（保留项目名/子系统名）**：用户明确要求连项目名/子系统名一起改。否决窄范围方案，采用全平台替换（但 markdown 与 git 路径留阶段二）。
- **阶段一连 markdown/git 路径一起改**：git 路径迁移会破坏 Obsidian vault，markdown 全局替换 240+ 处须语义审定，混在阶段一风险过高。否决，阶段一仅改 .pen 可见文案。

## 6. 后果与风险

- **OCC 能力大幅收窄**：前端从 20 页砍到 5 页，情报分析（M-OCC-02）、策略与内容（M-OCC-07/08/09）的前端入口全失。阶段二必须明确这些能力是「转后台 API 无 UI」「保留需求待后续补 UI」还是「废需求」，否则 OCC 退化为只剩目标档案+编排+评估的薄壳。
- **M-OCC-08 内容主数据（CON-11 同构权威源）风险**：删其页面后内容主数据无管理入口，而 MC 任务（养号/投放）依赖内容素材。阶段二须评估内容主数据是否仍需要、由谁维护，否则可能断 MC 内容链路。
- **「作战→行动」语义风险**：作战单元（四元绑定）、作战闭环等是 SRS 核心术语，机械替换可能产生不合语境的新词，阶段二须逐个审定。
- **git 路径风险**：目录名「认知作战」与项目名绑定，改路径破坏性大，阶段二建议保留目录名只改文档内文字。
- **阶段一/二不一致窗口进一步扩大**：现在线框（SWM+MC+OCC 三批）都是新结构新术语，markdown 文档全旧。三批累计：删页 SWM1+MC2+OCC15=18 页、术语全局替换、多处模块/需求待评估。**强烈建议尽快启动阶段二**，否则追溯断裂累积成系统性问题。
- **编号稳定**：R-OCC-001~009、OCC-01~20 编号本次均不变（删的编号空置，不重排）。
