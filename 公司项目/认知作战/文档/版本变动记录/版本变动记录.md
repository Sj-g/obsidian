本次为 SWM 子系统的**结构性转向**：放弃原「以 coze-studio 为智能体定义/运行时底座」的路线，改为「**以 coze-loop（Go）为提示词工程与评测引擎旁挂集成 + 其余智能体域组件用 Java**」。

转向理由：经源码级调研，coze-studio（Go）虽有 SingleAgent 主实体与运行时，但其 Plugin 执行/会话执行/自带用户体系与 CON-07（动作收口）、CON-11（执行宿主唯一）、R-COM-001（鉴权统一）三大硬约束冲突，隔离成本高；且其 Prompt 版本/Playground/评测能力近乎空白（恰是 coze-loop 的原生领地）。而 coze-loop 原生覆盖 M-SWM-02（提示词工程）与 M-SWM-06（评测），与 Java 网关经 HTTP/OpenAPI 解耦，异构成本最低。

转向后的 SWM 定位由「智能体定义与记忆中心」改为「**提示词生成与记忆中心**」：SWM 只生成提示词包与承载记忆，**运行时（场景适配/动态调用/调 IRS）移至 MC 的 agent-runtime 子模块**，与执行网关逻辑隔离以保留 CON-10 语义。coze-loop 作为唯一外部 Go 服务（CON-14 智能体域特例，仿 DC 采集域特例思路）。
