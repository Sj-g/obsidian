## V3.4 变更明细（2026-07-13）

### 一、技术选型替换（DC 子系统存储与编排）
本次基于 DC 详细设计落地，将 DC 子系统的存储引擎与容器编排替换为最终选型，并同步回写上游需求与概要设计文档。

| 维度 | 调整前（V3.3） | 调整后（V3.4） |
| --- | --- | --- |
| 后端语言（管控面/调度面/采集） | "Java Spring Boot 或 Go"（开放） | **Python（FastAPI）** |
| ETL 计算引擎 | Spark 或 MapReduce | **PySpark**（基于 Python 的 Spark） |
| 列式存储（明细数据） | HBase | **ClickHouse** |
| 图数据库（关系数据） | "图数据库"（未具体） | **NebulaGraph** |
| 爬虫集群容器编排 | K3s | **Kubernetes（KubeSphere 纳管）** |

### 二、设计决策依据
- **Python 全栈（C/C 决策）**：爬虫逆向采集生态最强，管控面/调度面/ETL(PySpark) 同语言，避免跨语言拼装。
- **ClickHouse 替 HBase（Q6=A）**：列式 OLAP，高压缩、列式扫描，适合大规模采集明细查询；仅替明细存储，关系库(PG)与图库(NebulaGraph)职责不变。
- **NebulaGraph（Q7=A）**：分布式图库，原生支撑 R-DC-008 BFS 目标扩散与 OCC 关联网络分析。
- **K8s + KubeSphere（Q8=A）**：全平台统一容器编排与管理面，废弃 K3s 独立编排说法。

### 三、关键设计决策（DC SDD 落地）
| 决策点 | 选择 | 说明 |
| --- | --- | --- |
| SDD 范围 | 全四模块一次写完 | M-DC-01~04 / R-DC-001~008 |
| 交付形式 | 独立 .md 文件 | 《软件详细设计说明-DC子系统.md》 |
| 去重键粒度 | 目标 × 数据类型 | 手段切换走重试/降级，不开新去重维度 |
| 配额维度 | 全局并发 + 单平台 QPS + 单账号/单IP 频率 | Redis 滑动窗口 + 令牌桶 |

## V3.3 变更明细（2026-07-13）

### 一、结构调整：数据分析与情报由 DC 移至 OCC
原 V3.2 中「数据分析与情报」（群体下钻、关系图谱、实体检索、文本智能分析）位于 DC（数据爬取）子系统。该能力本质属"分析研判"而非"采集/ETL"，且其产出直接服务于 OCC「目标识别与维护」。为使子系统职责与能力归属一致，将其由 DC 移至 OCC「目标识别与维护」（R-OCC-001）与「作战编排」之间。
