## 5. 核心设计原则（源自 CON-01~CON-13）

修订任何设计文档时，下列原则不可违背：

1. **动作收口（CON-07）**：所有执行终端动作（脚本/智能体、移动端 ADB/无障碍、桌面端 CDP）均经 MC 统一执行网关落地，禁止绕过，保证可观测、可审计、可熔断。
2. **推理与执行分离（CON-10）**：智能体视觉推理由 Agent 调 IRS 本地大模型完成，不经执行网关；动作指令再经网关落地。
3. **双执行模式（CON-08）**：脚本模式与智能体模式并存，共用底层控制通道，均收口于执行网关。
4. **权威源唯一（CON-11）**：账号主数据由 **MC** 唯一维护（R-MC-011）、内容主数据由 **OCC** 唯一维护；使用方只引用标识，变更经事件总线通知。
5. **私有化推理（CON-06）**：大模型私有化部署，不依赖外部公有云。
6. **可观测优先**：各子系统向 OM 上报日志与指标，关键动作全量留痕。
7. **行动单元**：移动端 `agent_id:account_id:终端:代理IP = 1:1:1:1`；移动端"一设备一账号一 IP"，桌面端"一 Profile 一账号一 IP"。
8. **统一技术栈分工**：**管控/业务微服务统一用 Java（Spring Boot）；数据采集与分析（爬虫采集 worker、PySpark ETL）用 Python；两者经 Kafka/REST 解耦。** DC 整体归 Python 为「采集域特例」（其 dc-service 管控面与 crawler/ETL 同属数据采集体系），不算违背原则；OM、COM 等其余管控/业务微服务用 Java。鉴权采用 JWT 无状态令牌 + com-auth-lib 共享验签库（各子系统本地验签，无网络开销）。

## 9. 线框稿设计规范（Pencil `.pen`，必读）

本节是 [`认知行动平台-线框图`](./认知行动平台-线框图) 的设计规范。**画/改任何线框页面前必须遵守本节**。规范源自已验证样板页（MC-02 终端台账），是全平台 67 页的统一标准。

### 9.1 总体原则

- **低保真灰阶，禁止彩色**。用 shadcn 中性色变量（`$--foreground`/`$--muted`/`$--card`/`$--muted-foreground`/`$--background`/`$--border`），主操作用 `$--foreground` 实底 + `$--primary-foreground` 文字。**不引入蓝/绿/红等彩色**——这是线框稿不是高保真。
- **★ 图标/图片用占位符，不渲染真图标**。所有图标位置用**灰色占位方框**（`type:"rectangle"`，15×15 或按容器，`fill:"$--muted-foreground"`，`cornerRadius:2`）表示，**不用 lucide 真图标**。图片同理用灰底占位框 + 文字标注「图片」。这是线稿图，图标只表意不渲染。占位符 fill 跟随所在容器（核心按钮内用 `$--primary-foreground`）。
- **所有页面共用 3 个框架元素**：两级常驻侧边栏 + 通用顶栏 + 内容区。不要为单个页面另造侧边栏/顶栏。
- **页面数据来自真实文档**：字段名/表格列/状态值/枚举取自 SRS 与详细设计（表结构、状态机），不臆造。页面号 + 名 + 对应模块 `M-XX-NN` 写进每页。
- **Pencil 是实时协作画布**：文档会变，节点 id 可能失效。**任何引用节点 id 前，先用 `batch_get` 实查确认**，不要凭记忆。

### 9.2 三个框架组件（组件区，位于画布上方）

组件是 `reusable:true` 的 frame，页面用 `ref` 实例化 + `descendants` 覆盖。**节点 id 会随重建变化，以下 id 仅供参考，用前务必 `batch_get` 实查**。

| 组件 | 作用 | 关键可覆盖点 |
| --- | --- | --- |

### 9.3 侧边栏覆盖模板（复制即用）

实例化侧边栏时，只需做一件事：**高亮当前页**（侧边栏常驻全部展开，不折叠，无需控制 enabled）。OCC/SWM/OM 页面还要覆盖品牌名 + 菜单文字（MC 菜单文字是组件默认值，MC 页面免覆盖）。

**先 `batch_get` 实查侧边栏组件，拿到 6 个 `Group-XX`/`Item-XX` 的真实 id**，再按下方模板填 descendants：

```js
Insert(page,{type:"ref",ref:"<侧边栏组件id>",name:"Sidebar",height:"fill_container",descendants:{
  "<Item-当前页id>":{fill:"$--muted"},           // 高亮当前页：实底
  "<Item-当前页id>/Dot 或 ILabel":{fill:"$--foreground",fontWeight:"600"},
  // OCC/SWM/OM 页面额外覆盖（MC 免）：
  "<BrandNameid>":{content:"行动中心"},
  "<6个一级菜单Labelid>":{content:"各自菜单名"},
  "<6个一级菜单的二级Item ILabel>":{content:"各自二级页名"}
}})
```

### 9.4 六种页面范式（决定内容区结构）

按《系统页面清单》每页职责归类，内容区按范式搭。**范式归属以 `系统页面清单.md` 为准**。

| 范式 | 内容区结构 | 典型页 |
| --- | --- | --- |
| **list-table**（记录管理，~28 页） | 标题区 → **整合工具栏**（左：类型 chips + 筛选下拉；右：搜索框 + 操作按钮）→ 可选统计条 → 表格 → 分页 | MC-02 终端台账、MC-06 账号、MC-13 任务、MC-20 审计 |
| **form-detail**（~22 页） | 标题区（含状态徽章/流转按钮）→ 左表单（分组）+ 右面板（状态时间线/关联） | OCC-06 目标档案、MC-08 账号生命周期、MC-04 指纹 |
| **dashboard**（~6 页） | 标题区（时间筛选 Tab）→ 指标卡网格 → 图表区 → 列表/快捷入口 | MC-01、OCC-01、SWM-01、OM-01 总览首页 |
| **canvas**（~3 页） | 三栏：左节点/脚本树 + 中画布/代码编辑器 + 右属性/调试面板 | MC-15 编排器、MC-16 脚本 IDE、OCC-09 编排定义 |
| **live-monitor**（~6 页） | 左主画面/指标 + 右信息/日志面板 | MC-17 单控、MC-18 宫格、MC-19 熔断、OM-04 指标 |
| **graph**（~2 页） | 顶查询栏 + 中图谱区（节点+连线）+ 右节点详情面板 | OCC-03 关系图谱、OCC-07 关联网络 |

**★ 工具栏元素布局规则（强制，单行）**：工具栏**必须单行**（`layout:"horizontal"`，禁止换行），内部左右分区：

| 区域 | 放什么 | 样式 |
| --- | --- | --- |
| **左侧（检索区）** | **搜索框 + 筛选/过滤**（下拉、chips、日期范围等）。检索类功能聚集在左。 | 搜索框：白底灰边 + 放大镜 icon + 占位文字；筛选：灰边下拉框。 |
| **右侧（操作区，最右）** | **相关操作**，分两类：①**核心操作 = 实底带文字按钮**（如「新建」「分配」「保存」「检索」「手动同步」）放在**最右侧**；②**次要操作 = 图标按钮**（仅图标，如导出/刷新/更多）排在核心按钮左边。 | 核心：`fill:"$--foreground"` + `$--primary-foreground` 文字 + lucide 图标；图标：`type:"icon"`（lucide 库），30×30 描边框。 |

左右之间用 `width:"fill_container"` 的 Spacer 撑开。**核心操作按钮放工具栏最右侧**（不放标题行）。

> 图标按钮 = 30×30 frame + `cornerRadius:6` + 灰边描边，内部放**灰色占位方框**（`rectangle` 15×15 `$--muted-foreground`，见 §9.1 占位规则），**不渲染真图标**。

**★ 整合头部规则（所有范式强制）**：内容区头部 = **标题区（上下结构）+ 工具栏（单行）**，两部分：

| 部分 | 结构 |
| --- | --- |
| **标题区（vertical 上下结构）** | 上：页面标题（18-20px 加粗）；下：简短描述（11px 灰）。**标题与描述上下排，不要左右排**。标题区**不放操作按钮**。 |
| **工具栏（horizontal 单行）** | 左检索（搜索+筛选）+ Spacer + 右操作（图标 + **核心按钮在最右**）。按范式微调：list-table 如上；form-detail 标题区可加状态徽章；dashboard 标题区加时间筛选 Tab；canvas 工具栏放保存/校验/试运行/发布；live-monitor 标题区加返回按钮；graph 工具栏放查询输入+筛选+查询按钮。 |

**反例（禁止）**：①标题→描述→统计条→操作栏→筛选栏→表格，6 段纵向堆叠；②操作全是文字按钮挤一排；③核心按钮放标题行；④标题和描述左右排在一行；⑤工具栏换行成两行。
**正例**：标题区（标题上、描述下）+ 工具栏（单行：左搜索+筛选，右图标+核心按钮最右）+ 表格/内容。

### 9.5 画布组织（子系统分区 + 菜单层级布局）

画布按子系统分区，每个分区有黑底白字大标题；分区内**按一级菜单层级**布局：

- **纵向 = 同级（一级菜单之间）**：6 个一级菜单上下排列，行距 **1200**（容纳最高页面 1100 + 间隙）。
- **横向 = 从属（同一菜单下的二级页）**：二级页左右排列，页间距 60，每页宽 1440。
- 每行左上方放黑底白字**菜单标题条**（菜单名 + 页数）。
- 4 个分区：**MC 区**（y≈1500 起，21 页 6 行）→ **OCC 区**（y≈8500 起）→ **SWM 区** → **OM 区**（各区下方，各自大标题 + 菜单行）。

### 9.6 Pencil 操作要点（避坑）

- **`batch_design` 的 JS 每批独立作用域**，跨批变量不共享；要跨批引用节点，用上一批返回的真实 id（不能用 JS 变量占位给 `FindEmptySpace` 的 `nodeId`）。
- **`Update` 不能改 `id`/`type`/`ref`**。要换组件实例：`Delete` 旧 `ref` → `Insert` 新 `ref` → `Move` 到 index 0。
- **ref 实例的内部 slot 不能直接 `Insert`**：内容区必须是页面自建的普通 frame，不是侧边栏组件的子节点。
- **禁用属性**：无 `strokeDasharray`（虚线用浅色实线代替）、无百分比尺寸（用 `fill_container`/`fit_content` 或 px）、`monospace` 不是有效字体（代码用 `JetBrains Mono`）。
- **迁移组件实例后必查**：用 `batch_get` 确认页面 frame 仍是 `[侧边栏ref, 右侧frame]` 两子节点结构（防内容区脱离父级变成画布游离节点）。
- 画完每页用 `snapshot_layout(problemsOnly:true)` 验证无溢出/折叠/重叠。

### 9.7 常见线框任务

- **画一个新页**：① `batch_get` 查侧边栏/顶栏组件当前 id；② `FindEmptySpace` 在该子系统分区的目标菜单行找位（或算坐标：行 y = 分区起点 + 菜单序号×1200，列 x = 4800 + 页序号×1500）；③ 建页面 frame（1440 宽）→ 插侧边栏 ref（展开+高亮）→ 插右侧 frame → 插顶栏 ref（改面包屑）→ 按 §9.4 范式填内容区 → 去除 `placeholder:true`。
- **迁移页面到新组件**：删旧侧边栏/顶栏 ref → 插新组件 ref（带 descendants）→ `Move` 到首位 → `batch_get` 复查结构。
- **改风格**：改组件本身（`reusable` 源），所有实例自动跟随；不要逐页改。

### 9.8 列表→详情跳转范式（master-detail，必读）

平台大量页面是「**主列表页 → 点击行 → 跳转详情页**」的 master-detail 交互。详情页有独立的布局规范，与列表页（§9.4 的 list-table）不同。

**典型的列表→详情跳转关系对**（基于已画页面与《系统页面清单》）：

| 列表页（list-table） | 跳转目标（详情/操作页） | 触发 |
| --- | --- | --- |
| MC-02 终端台账 | 终端详情 / MC-17 单设备远控 | 行操作「详情」/「远程控制」 |
| MC-06 账号主数据 | MC-08 账号生命周期与凭据 | 行操作「详情」 |
| MC-13 任务管理 | 任务实例详情 / MC-15 编排器 / MC-16 脚本IDE | 行操作「查看实例」/「编排」/「脚本」 |
| MC-14 模板任务库 | MC-15 编排器（实例化） | 模板「选用实例化」 |
| OCC-04 实体检索 | 实体全维度档案 | 检索结果点击 |
| OCC 目标列表 | OCC-06 目标档案与状态管理 | 目标点击 |
| SWM-09 评测数据集 | 评测实验详情 | 数据集点击 |

> **凡是「列表点击进来」的页面都是详情页**（含 MC-08/15/16/17、OCC-06 等），必须遵守下方详情页布局规范——核心标志：**顶栏面包屑下方有带返回图标的标题区**。

**详情页布局规范**（与列表页区别）：

1. **★ 标题区在顶栏下方 + 返回图标（详情页核心标志）**：详情页的结构 = 顶栏（面包屑）→ **标题区（顶栏正下方，非顶栏内）** → 内容。标题区左侧第一个元素是**返回图标**（lucide `arrow-left`，32×32 描边图标按钮，点击回来源列表），紧跟对象标题（如「目标档案 · TGT-0042」）。**任何从列表点进来的页面**（MC-08/15/16/17、OCC-06 等）都必须有这个带返回图标的标题区。标题区上下结构：上行 = 返回图标 + 对象标题 + 状态徽章 + 主操作按钮；下行 = 简短描述。
2. **标题区 = 对象标题 + 状态徽章 + 主操作**：标题行横向排列——左：对象标题（如「目标档案 · TGT-0042」）；中：当前状态徽章（实底圆角条，灰阶，如「已锁定」）；右：主操作按钮（状态流转/保存/编辑）。**状态徽章紧贴标题**，是详情页区别于列表页的视觉标志。
3. **主体左右分栏**（详情页核心特征，区别于列表页的单栏表格）：
   - **左栏（主，占 ~2/3，`width:"fill_container"`）**：对象的属性表单，按**字段分组**纵向堆叠（每组一个白卡：组标题 → 字段）。字段用「标签（灰小）+ 值框（白底灰边）」键值对，可两列横排。
   - **右栏（侧，固定 ~280-320px 宽）**：与该对象相关的辅助信息——**状态变更时间线**（点+连线+「谁·何时·从X→Y」）、**关联对象列表**、**操作入口**（跳其它相关页）。
4. **信息密度高于列表页**：详情页字段全量展示（列表页只显关键列），右栏的时间线/关联是列表页没有的。
5. **底部操作行**：保存/取消/删除等收尾按钮横向排列，主操作实底、次操作描边。

**与 list-table 的关键差异速查**：

| 维度 | 列表页（list-table） | 详情页（master-detail） |
| --- | --- | --- |
| 布局 | 单栏：工具栏 + 表格 | 左右分栏：左表单 + 右侧辅助 |
| 主体 | 表格（多行多对象） | 单对象全字段表单 |
| 筛选 | 顶部 chips + 下拉 | 无（已定位到单对象） |
| 状态 | 表格列里的状态标签 | 标题旁的状态徽章 + 右栏状态机/时间线 |
| 顶栏 | 无返回按钮 | 有「‹ 返回列表」 |
| 数据量 | 一屏多行 | 一屏一对象的完整画像 |
