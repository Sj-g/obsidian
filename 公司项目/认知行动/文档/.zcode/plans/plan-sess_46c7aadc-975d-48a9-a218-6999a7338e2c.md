# 修订方案:执行网关通道 SDK 化(MC SDD V1.1 → V1.2)

## 背景与决策

用户澄清网关下挂的通道适配应是「**多个 SDK 包,每个适配一种设备类型,向网关提供统一服务接口**」,而非原设计的「ChannelAdapter 类族(策略模式)」。

**设计决策**(已与用户确认):
- **SDK 划分维度:按设备类型**——5 个 SDK 包对应 `terminal_type` 的 5 个取值(真机 / 云手机 / ARM 板卡 / 虚拟化真机 / Profile)
- **版本号:升 V1.2**(V1.1 摘要已在版本变动记录第 7 行固化,本次网关 SDK 化是对 M-MC-05 内部架构的实质澄清,独立成版)

**关键简化**:ChannelAdapter 类族(AdbAdapter/AccessibilityAdapter/CdpAdapter)只存在于 SDD-MC 一个文件;HLD(概要设计说明.md / 架构图.md)用「控制通道适配」抽象层,不触及 SDK 级。本次修订是「为 HLD 抽象层补实现细化」,**HLD/架构图/RTM/SRS 全部不动**,改动收敛到 3 个文件。

### ⑤ §5.2.1 关键类说明 + 设计要点(行 768-810)
重写「DeviceChannelRouter + DeviceSdk」段落,新增「设备 SDK 包族」设计说明,要点:
- **每个设备类型一个独立 SDK 包**(jar 依赖,同进程,非独立服务),网关面向 `DeviceSdk` 统一接口编程,按 `terminal_type` 路由到对应 SDK
- **SDK 向网关提供服务**:暴露 `click/input/screenshot/install/swipe` 等高级 API,把协议细节(ADB 命令拼装、无障碍事件协议、CDP 报文)全屏蔽
- **移动端 4 个 SDK**(真机/云手机/ARM/虚拟化真机)内部组合 ADB + 无障碍协议库,**共享底层协议库**(避免重复封装);指令经 II-02 长连接下发到设备端 Agent 执行
- **Profile SDK 封装 CDP**,直连指纹浏览器(EI-06)调试端口,**无需设备端 Agent**(解释桌面端无 Agent 的不对称)
- SDK 是同进程 jar 依赖(零网络开销、可独立演进、来源混合:自研/开源/厂商提供),不违背「一子系统一微服务、内部不拆分」原则

### ⑥ §5.2.1 动作执行算法伪代码(行 777-804)
变量名/类型名同步:`adapter = router.route(...)` → `sdk = router.route(...)`;`result = adapter.execute(action)` → `result = sdk.execute(action)`。注释「# adb/accessibility/cdp」→「# 5 类设备 SDK」。算法逻辑不变。
